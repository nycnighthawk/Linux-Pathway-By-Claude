## The model

Every file has an **owner**, a **group** and a **mode** of twelve bits: three sets of read, write and execute (`r`, `w`,
`x`) for the owner, the group and everyone else, plus three special bits. The check goes in a fixed order and the first
matching class decides: if you are the owner the owner bits apply, otherwise if your group matches the group bits apply,
otherwise the other bits apply. The superuser bypasses most checks.

Octal digits add up read as 4, write as 2 and execute as 1:

| Letters | Octal | Typical use |
|---|---|---|
| `rw-------` | `600` | private key |
| `rw-r--r--` | `644` | ordinary file |
| `rwxr-xr-x` | `755` | program or directory |
| `rwxrwx---` | `770` | team directory |

Symbolic edits work on classes: `chmod u+x file`, `chmod g-w file`, `chmod o= file`. Use a capital `X` with `-R`
to add execute only to directories (and to files that already have it): `chmod -R g+rX tree`.

## Directories are different

| Bit | On a file | On a directory |
|---|---|---|
| `r` | read the content | list the names |
| `w` | change the content | create, delete and rename entries |
| `x` | run it | enter it and reach things inside by name |

A file's own bits do not matter if a parent directory cannot be searched. This is the most common reason for a
puzzling "permission denied": check every directory on the path with `namei -l /path/to/file`.

## Ownership

`chown user:group file` changes both; `chgrp group file` changes the group. Only the superuser can give a file away; an
owner may hand a file to any group they belong to. Users and groups are **numbers on disk**; names are looked up when
you list. A disk moved to another machine may show different names for the same numbers.

## umask: the default

A program asks the kernel for a mode, usually `666` for files and `777` for directories. The **umask** removes bits
from the request. With `umask 022` a file starts at `644` and a directory at `755`; with `umask 027` a file is `640`
and a directory `750`. The umask can only remove bits, so ordinary file creation never makes a file executable.

## The special bits

| Bit | Octal | Effect |
|---|---|---|
| setuid | `4000` | an executable runs as its owner, not as the caller (for example `passwd`) |
| setgid | `2000` | an executable runs with its group; on a **directory**, new entries inherit the directory's group |
| sticky | `1000` | on a directory: entries can be removed or renamed only by their owner, the directory's owner or root |

The listing shows them as `s` in an execute position and `t` at the end: `-rwsr-xr-x`, `drwxrws---`, `drwxrwxrwt`.
Setuid programs owned by root are among the most attacked code on a system, because a bug in one is a path to root.
Inventory them regularly: `find / -xdev -type f -perm -4000 2>/dev/null`. Mount options such as `nosuid` switch the bits
off for a whole file system.

## Worked example: a team directory and a drop box

```bash
sudo groupadd labteam
sudo mkdir /srv/proj /srv/drop
sudo chgrp labteam /srv/proj
sudo chmod 2770 /srv/proj          # setgid: new files get group labteam; others have no access
sudo chmod 1777 /srv/drop          # sticky: anyone may add, only owners may remove
stat -c '%a %U:%G %n' /srv/proj /srv/drop
```

Now create a file in `/srv/proj` as a team member. It inherits the group, but whether other members can **write** to it
depends on that member's umask. Compare `umask 022` and `umask 002`, and decide whether the project needs a cooperative
umask or an access-list default.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| "Permission denied" on a readable file | A parent directory lacks `x` | `namei -l` |
| SSH refuses a private key | The key file is readable by others | `chmod 600 ~/.ssh/id_*` |
| A script will not run | No execute bit, or mounted `noexec` | `ls -l`, `mount` options |
| A service cannot read its config after a fix | `chmod -R 777` made things worse | Restore sane modes; fix the real cause |
| Team members cannot edit each other's files | Group bit missing from the new file | The umask, the setgid bit on the directory |
| Orphaned files after deleting an account | Numeric ids were not reassigned | `find / -nouser -o -nogroup` |
