- Tell the difference between using software and distributing it, and say which one creates a source obligation.
- Identify a running system and read the licence information of what is installed on it.

## What a distribution is

The Linux kernel manages memory, processes and devices, but a kernel alone cannot serve a web page. A **distribution**
bundles the kernel with a C library, a shell, the command-line tools, an init system, a package manager, an installer
and a promise: someone will build these parts together, test the combination and ship security fixes for a stated
period. When you choose a distribution you mostly choose that policy.

| Family | Package format and tools | Typical choice for |
|---|---|---|
| Debian family (Debian, Ubuntu) | `.deb`, `apt` and `dpkg` | community-governed stable releases, wide hardware support |
| Red Hat family (RHEL, Fedora, Rocky, Alma) | `.rpm`, `dnf` and `rpm` | long support windows, certification, enterprise tooling |
| SUSE family (SLES, openSUSE) | `.rpm`, `zypper` | enterprise and community lines with their own tools |
| Rolling release (Arch and similar) | its own format | current software, continuous updates |

Each release has a **support window**, the length of time fixes arrive. It is the main product difference between
otherwise similar distributions. Package repositories are organised into channels, for example a slow stable channel
and a fast development channel, and a package normally moves from the second to the first as bugs are cleared.

## Licences in one page

A licence is a grant of permissions under copyright, with conditions. Free software and open source are two names for
licences that let anyone run, study, change and redistribute the code. They differ in what happens when you pass a
modified copy on.

| Family | Examples | What it asks of you when you redistribute |
|---|---|---|
| Permissive | MIT, BSD, Apache-2.0 | keep the notice; you may keep your changes private |
| Weak copyleft | LGPL, MPL, CDDL | changes to the licensed files stay open; other code may link to them |
| Strong copyleft | GPL | the whole combined work goes out under the GPL, with source |
| Network copyleft | AGPL | the same, and also when users reach your modified copy over a network |

Three ideas carry most of the weight:

1. **Using is not distributing.** Running GPL software, even modified, inside your own company triggers nothing. The
   source obligation begins when a copy leaves your organisation, in an image, a download or an appliance.
2. **A distribution is hundreds of separate works.** There is no single licence for it. The distributor carries the
   notices and source offers for each component.
3. **Compatibility is real.** Some licences cannot be combined in one work. The CDDL used by the ZFS file system is
   the well-known example: it cannot be shipped inside the mainline kernel, so ZFS on Linux lives outside it.

> The rule of thumb in this course is a teaching aid. Real obligations depend on the exact licence text and on how
> components are combined. For a product, ask a lawyer.

## Worked example: identify a system and read its licences

Start with the file that names the running distribution.

```bash
cat /etc/os-release              # NAME, ID, VERSION_ID: the family and release
```

On a Red Hat family host, the package database stores a licence field for every package.

```bash
rpm -qa --qf '%{NAME} %{LICENSE}\n' | sort | head
```

On a Debian family host, each package ships a copyright file that is the authoritative statement of its terms.

```bash
ls /usr/share/doc/bash/
less /usr/share/doc/bash/copyright
```

A loadable kernel module declares its own licence, and the kernel records when a module with a non-free licence is loaded.

```bash
modinfo -F license ext4          # for example: GPL
cat /proc/sys/kernel/tainted     # 0 means no taint flag is set
```

If the last command prints a non-zero number after you load a vendor driver, you now know both what happened and why a
kernel developer may decline to debug a crash that follows.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| A product ships a modified GPL daemon with no way to get its source | The source obligation was missed when the appliance image was built | The component list and the source offer for each copyleft item |
| Someone assumes private use needs a source offer | Using and distributing were confused | Did a copy leave the organisation? |
| A kernel crash report is declined | A non-free module taints the kernel | `/proc/sys/kernel/tainted` and the loaded modules |
| A component cannot be combined with another | Incompatible licences | The SPDX identifiers of both |
