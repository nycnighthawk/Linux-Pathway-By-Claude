# Text tools that compose

This lesson follows the topic synthesis `synth/LNX-101/LNX-101-T04.md`, which carries the sources and the history.

## What you will be able to do

- Choose between grep, sed, awk, cut, sort, uniq, tr and xargs for a given text question.
- Build a pipeline one stage at a time and check the output after each stage.
- Avoid the common traps: unsorted input to `uniq`, locale-dependent sorting, and file names with spaces.
- Know when a pipeline is the wrong tool and a real parser or script is better.

## The idea: small filters joined by pipes

Most system information is text: logs, account files, command output. Each tool below does one job on a stream of
lines, and a pipe connects the output of one to the input of the next. The tools stream, so they handle files larger
than memory, and every stage runs at once.

| Tool | Does | Typical use |
|---|---|---|
| `grep` | selects lines that match or do not match | find errors; its exit status says whether anything matched |
| `sed` | edits a stream | substitute text, delete lines, print ranges |
| `awk` | splits lines into fields and runs rules | per-field conditions, simple sums and counts |
| `cut` | extracts columns | one field by delimiter or character range |
| `sort` | orders lines | by key, as text or numbers, with `-u` to drop duplicates |
| `uniq` | collapses *adjacent* duplicate lines | with `-c` to count them |
| `tr` | translates or deletes single characters | change case, strip carriage returns |
| `xargs` | builds command lines from a list | run a command for many names |

## Building a pipeline

Add one stage at a time and look at the output before adding the next. To find the busiest clients in a web log:

```bash
awk '{ print $1 }' access.log                 # 1. the address field
awk '{ print $1 }' access.log | sort          # 2. sort so equal addresses are adjacent
... | uniq -c                                  # 3. collapse and count (uniq only sees neighbours)
... | sort -rn                                 # 4. biggest count first
... | head -3                                  # 5. the top three
```

The `sort` before `uniq -c` is essential. The same shape, **extract, sort, group, sort, take**, answers hundreds of questions.

Two more patterns worth knowing:

```bash
awk -F: '$3 >= 1000 { print $1 }' /etc/passwd          # accounts with a user id of 1000 or more
sed -E 's/[A-Za-z0-9._-]+@/***@/g' mail.txt            # hide the part of each address before the @
```

## Traps

- **Sorting depends on the locale.** In scripts whose output must be stable, run `LC_ALL=C sort`.
- **File names with spaces.** `xargs` splits its input on blanks and treats quotes specially. Use null separators on
  both ends: `find . -type f -print0 | xargs -0 wc -l`.
- **The default pipeline status** is that of the last stage, so an early failure is hidden. Use `set -o pipefail`.
- **GNU and BSD differ.** `sed -i` needs a suffix argument on macOS; a command copied from a Mac may fail on Linux.
- **Text is lossy.** Splitting on commas breaks on quoted fields; embedded newlines break every line-oriented tool.
  For CSV, JSON or YAML use a tool that understands the format, such as `jq` or a CSV-aware program.
- **Nested repetition** in a regular expression can stall some engines (next topics).

## Worked example: how many bytes came from each status class?

```bash
awk '{ class = substr($9, 1, 1) "xx"; bytes[class] += $10 }
     END { for (c in bytes) print c, bytes[c] }' access.log | sort
```

Read it aloud: take the first digit of the status, call it the class, add the byte count to that class, and at the end
print each class. Replace the awk program by `cut` and `sort` stages and notice how much clearer the single awk rule is
once a number has to be added.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Duplicates survive `uniq` | The input was not sorted | Add `sort` before it |
| Output order differs between machines | Locale collation | `LC_ALL=C` |
| A name with a space becomes two arguments | `xargs` without `-0` | Null-separated list |
| `sed -i` changed a link into a regular file | In-place edit replaces the file | Edit the real file, or use a backup suffix and compare |
| `grep` says "Binary file matches" | It guessed the file is not text | `grep -a` or look at the data |
