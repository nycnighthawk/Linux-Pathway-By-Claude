# Editing text with vi, vim and nano

This lesson follows the topic synthesis `synth/LNX-101/LNX-101-T07.md`, which carries the sources and the history.

## What you will be able to do

- Open, change, save and quit a file in vim, and recognise which mode you are in.
- Combine an operator, a motion and a count to make an edit in a few keystrokes.
- Repeat an edit across a file with a substitution or an ex script.
- Use nano for a quick change, and set the default editor that other programs launch.

## Two kinds of editor

Vi and its descendant **vim** are *modal*: the same keys do different things in different modes. They are installed on
nearly every system, work well over slow connections, and reward practice. **nano** is *modeless*: you type where the
cursor is, and a bar at the bottom lists the commands. It is the right tool for an occasional change.

## Vim in one page

| Mode | How you get there | What keys do |
|---|---|---|
| Normal | start here; press `Esc` from anywhere | every key is a command |
| Insert | `i` (before the cursor), `a` (after), `o` (new line below) | keys produce text |
| Command line | `:` | ex commands: save, quit, substitute |
| Visual | `v` (characters), `V` (lines) | select text, then apply an operator |

The survival set: `i` to type, `Esc` to stop typing, `:w` to save, `:q` to quit, `:wq` or `ZZ` to do both, `:q!` to quit
without saving, `u` to undo, `Ctrl-r` to redo. If you cannot find the way out, press `Esc` twice and type `:q!`.

### The grammar of normal mode

A command is **operator + motion**, with an optional count.

| Operators | Motions |
|---|---|
| `d` delete, `c` change, `y` yank (copy) | `w` word, `$` end of line, `0` start of line, `}` paragraph, `/text` search |

So `dw` deletes a word, `d$` deletes to the end of the line, `c2w` changes two words, `y}` copies a paragraph, and `3dd`
deletes three lines. `.` repeats the last change, `p` pastes, and `qa ... q` records a macro in register `a`, replayed by `@a`.

### Ex commands

```
:%s/old/new/g          replace in the whole file
:%s/old/new/gc         ask before each replacement
:g/pattern/d           delete every line that matches
:3,5s/foo/bar/         only on lines 3 to 5
:$put ='[extra]'       append a line at the end
```

The same commands can run **without a screen**, which is how a repeatable edit is made:

```bash
vim -Es -u NONE -N file.txt < keys.vim     # keys.vim holds one ex command per line, ending with wq
```

## nano in one page

Open with `nano file`. Type to insert. The footer shows commands with `^` meaning the control key:

| Key | Action |
|---|---|
| `^O` | write out (save) |
| `^X` | exit (it asks whether to save changes) |
| `^W` | search |
| `^K`, `^U` | cut a line, paste it |

## Which editor do other programs launch?

Tools that need you to edit a file (`visudo`, `crontab -e`, `git commit`, `systemctl edit`) look at environment
variables: `VISUAL` first, then `EDITOR`, then a distribution default. Git also has `core.editor`, and the systemd tools
check `SYSTEMD_EDITOR` first. Set it once in your shell start-up file:

```bash
export EDITOR=vim
```

For privileged edits prefer `sudoedit file`: it copies the file to a temporary place, runs the editor **as you**, and
writes the result back. Starting `sudo vim file` runs the whole editor, with its plugins and shell escapes, as root.

## Worked example: one edit, three ways

Goal: change the port from `8080` to `9090` in `app.conf`.

```bash
sed -i.bak 's/8080/9090/' app.conf                # a stream edit, with a backup
vim -Es -u NONE -N app.conf <<'EOF'
%s/8080/9090/
wq
EOF
vim app.conf                                       # interactive: /8080<Enter>  cw9090<Esc>  :wq<Enter>
```

Count the keystrokes in the interactive version and decide when each of the three is the right choice.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Typed text became commands (or the reverse) | Wrong mode | Look for `-- INSERT --` at the bottom; press `Esc` |
| Cannot save a file | It is protected, or you are not the owner | `ls -l`, then `sudoedit` |
| "Swap file already exists" | Another session, or a crashed one | Is the other editor still open? Recover or delete the swap file |
| A commit opened an unexpected editor | `EDITOR` is unset or different | `echo "$EDITOR"` and `git config core.editor` |
| An edit under sudo changed ownership | A copy was written, not the original | `ls -l` before and after |
