## A file is an inode; a name is an entry in a directory

A directory is a table that maps names to inode numbers. The **inode** holds everything about the file except its name:
type, owner, mode, size, timestamps and the location of the data. Because the name lives in the directory, one inode can
have several names, and removing a name is a different act from removing the file. The data is freed when the last name
is gone and the last program holding the file open has closed it.

The listing `ls -li /usr/bin/passwd` shows the pieces:

| Column | Meaning |
|---|---|
| inode number | which record this is, valid only inside one file system |
| first character of the mode | file type: `-` regular, `d` directory, `l` symbolic link, `c`/`b` device, `p` pipe, `s` socket |
| nine permission characters | owner, group and others (next topic) |
| link count | for a file, how many names point at the inode |
| owner, group, size, time, name | the rest |

## Hard links and symbolic links

| | Hard link | Symbolic link |
|---|---|---|
| What it is | another name for the same inode | a small file whose content is a path |
| Same inode as the target | yes | no |
| Crosses file systems | no | yes |
| Can point at a directory | no | yes |
| If the target is deleted | the data survives under the other name | the link dangles |
| Create with | `ln target name` | `ln -s target name` |

A symbolic link stores text, and a relative target is resolved from the link's own directory, not from where you
stand. `readlink name` prints the stored text and `readlink -f name` resolves it fully. Many commands can either follow
a link or act on the link itself, so check before a recursive copy, archive or permission change.

## The standard layout

| Directory | Purpose |
|---|---|
| `/etc` | configuration local to this machine |
| `/usr` | the operating system's programs, libraries and shared data (`/usr/bin`, `/usr/lib`) |
| `/usr/local` | software you built or installed yourself, kept apart from packages |
| `/opt` | self-contained third-party applications |
| `/var` | data that changes: `/var/log`, `/var/lib`, `/var/spool`, `/var/cache`, `/var/tmp` |
| `/tmp` | temporary files, may be cleared at any time or at reboot |
| `/home`, `/root` | personal files and the administrator's own directory |
| `/boot` | kernel and boot loader files |
| `/srv` | data served by this machine |
| `/run` | runtime state, kept in memory, gone after a reboot |
| `/dev`, `/proc`, `/sys` | not storage: devices, kernel process view and device model, shown as files |

Modern distributions have merged the old split: `/bin`, `/sbin` and `/lib` are symbolic links into `/usr`. Image-based
systems go further: `/usr` is read-only and part of a signed image, local configuration in `/etc` is merged on update,
and `/var` persists. The useful mental model is three kinds of data: the vendor's content, the machine's configuration
and the system's changing state.

## Worked example: two names, one file, and a dangling link

```bash
cd "$(mktemp -d)"
echo hello > data.txt
ln data.txt data.hard            # hard link: same inode, link count 2
ln -s data.txt data.soft         # symbolic link: its own inode
ls -li                           # compare inode numbers and link counts
rm data.txt
cat data.hard                    # still works: the inode lives on
cat data.soft                    # fails: the link now dangles
```

Then explain the output of `ls -li` after each step. A second experiment: try `ln /etc/hostname /tmp/h` and, if
`/tmp` is on another file system, read the error message about crossing devices.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Disk is full after deleting a big file | A running program still has it open | `lsof +L1` for open files with link count 0 |
| "No space left" with space free | Inodes are exhausted by many small files | `df -i` |
| An editor or tool breaks a link | It replaced the file instead of writing through the link | `ls -l` before and after |
| A restored backup is three times too large | Links were copied as files | The archiver's link options |
| A script fails after an upgrade | It assumed `/bin` and `/usr/bin` differ | `readlink -f /bin` |
