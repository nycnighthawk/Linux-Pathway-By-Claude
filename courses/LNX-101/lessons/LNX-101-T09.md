# Archiving and compression

This lesson follows the topic synthesis `synth/LNX-101/LNX-101-T09.md`, which carries the sources and the history.

## What you will be able to do

- Explain why packaging a tree and shrinking it are two separate jobs, and how they combine in a pipe.
- Create, list, verify and extract tar archives with gzip, xz or zstd, and choose a compressor for the situation.
- Preserve links, modes and awkward file names, and build a compressed cpio archive of the kind a kernel boots from.
- Extract an untrusted archive safely.

## Two jobs, two tools

Moving a directory tree raises two problems. **Packaging** turns thousands of files, each with a name, owner, mode,
timestamp and maybe links, into one stream. **Compression** removes redundancy from any stream to save space or time.
Unix keeps them apart: `tar` packs, a compressor shrinks, and a pipe joins them. Any compressor works on any stream,
so a better compressor needs no change to `tar`.

| Tool | Job | Notes |
|---|---|---|
| `tar` | pack a tree into a stream, or unpack it | stores name, type, owner, group, mode and time; no index |
| `gzip` | fast, universal compression | suffix `.gz` |
| `bzip2` | smaller and slower than gzip | suffix `.bz2`; has lost ground |
| `xz` | smallest output, slowest to compress, fast to unpack | suffix `.xz`; good for release files |
| `zstd` | wide range of levels, from near-gzip speed to near-xz size | suffix `.zst` |
| `cpio` | older packer that reads names from standard input | used for boot-time root file systems |

## tar in four verbs

```bash
tar -cf site.tar site/                 # create
tar -tf site.tar                       # list, without extracting
tar -xf site.tar -C /scratch           # extract into another directory
tar -caf site.tar.zst site/            # -a picks the compressor from the suffix
```

Recent GNU `tar` detects the compression when reading, so `tar -xf` works on all of them. The suffix convention is the
archive suffix plus the compressor's suffix; extensions can lie, and `file archive` tells you what is really inside.

Details that matter:

- **Leading slashes** are stripped from member names by default, so an archive made from `/etc` restores under the
  current directory, not over the live files. Keep names relative on purpose.
- **Owners** are stored with names and numbers. Only the superuser can restore ownership; an ordinary user gets files
  owned by themselves. Add `--numeric-owner` when the archive is restored on a system with different accounts.
- **Links** are stored as links, but only as hard links if all the names are archived in the same run.
- **Extended attributes and access lists** need `--xattrs` and `--acls` on both create and extract.

## Choosing a compressor

The ordering is a rule of thumb: gzip is fast and everywhere, xz is smallest and slowest to compress, zstd offers the
best range between them. Compression is a trade of processor time and memory for size, so:

- A nightly backup that runs once and is read rarely: a strong level, such as `zstd -19`.
- A live system that compresses on the fly: a low level, such as `zstd -3` or `gzip`.
- A release file compressed once and downloaded often: `xz`.

Data that is already compressed (JPEG images, video, an existing `.gz`) does not shrink again. Compressing it again
wastes time. A very strong setting can also need a lot of memory to **decompress**, so a file made on a large machine may
fail on a small one.

## Verify, do not hope

A backup is worth something only if it restores. Right after creating an archive:

```bash
zstd -t site.tar.zst                    # check the compressor's checksum
tar -tf site.tar.zst >/dev/null         # read every header
mkdir restore && tar -xf site.tar.zst -C restore
diff -r site restore/site               # compare the trees
```

Damage in the middle of a compressed stream can make everything after it unreadable, and `tar` has no index, so
extracting one member reads the stream up to it. Keep a checksum of the archive (`sha256sum`) separately.

## Worked example: names with spaces, and a boot-style archive

```bash
find site -name '* *' -print0 | tar --null -T - -cf spaces.tar        # null-separated list survives spaces
cd rootfs && find . -print0 | cpio --null -o -H newc | gzip > ../initramfs.cpio.gz
```

The first line uses the same null-separator rule as `find -print0 | xargs -0` in the text-tools lesson. In the second,
`cpio` reads the names from standard input, and the `newc` format is the one the kernel accepts for an initial root file
system. Running it **inside** `rootfs` makes `init` appear at the top level of the archive. Check with
`zcat ../initramfs.cpio.gz | cpio -it`.

Try this too: build the same archive with `gzip -9`, `xz -9` and `zstd -19`, compare size and time with `time`, and then
extract as an ordinary user to see which attributes could not be restored.

## Safety: never extract the untrusted as root

A member name can contain `../` or be absolute, and a link member can point outside the target. An unfiltered
extraction as root can then write over system files. Rules:

- Extract an untrusted archive in an empty scratch directory, as an unprivileged user, after listing it with `tar -t`.
- Do not use `-P` (keep absolute names) unless you mean it.
- In Python, use `tarfile.extractall(..., filter="data")`, which rejects such members.

Container image layers are tar archives too, so the same rules apply when you pull or unpack an image.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Archive restores with the wrong owner | Restored as an ordinary user, or accounts differ | Run as root, `--numeric-owner` |
| Links became copies, or the other way round | Options or sources differ | `tar -tvf` and look for `->` and `link to` |
| "Cannot open: not in gzip format" | Extension does not match the content | `file archive` |
| Cannot decompress on a small machine | Level needs lots of memory | Compress with a lower level |
| Spaces in file names break the list | List not null-separated | `-print0` with `--null -T -` |
| Files restored outside the target | Absolute or `../` member names | List first; use a scratch directory |
