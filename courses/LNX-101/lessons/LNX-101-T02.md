# Navigating the shell: globbing, quoting and history

This lesson follows the topic synthesis `synth/LNX-101/LNX-101-T02.md`, which carries the sources and the history.

## What you will be able to do

- Move around the directory tree quickly and know which path a command is really acting on.
- Name sets of files with glob patterns and predict what a pattern will expand to, including when it matches nothing.
- Choose between backslash, single quotes and double quotes, and quote every variable that holds a name.
- Reuse earlier commands with the history list, and configure what the history keeps.

## The shell rewrites your line before anything runs

The program you start never sees what you typed. The shell first splits the line into words, then rewrites the words in
a fixed order, and only then starts the command with the final list of arguments:

1. brace expansion, such as `{a,b}`
2. tilde expansion, such as `~` for a home directory
3. parameter, arithmetic and command substitution, such as `$name`, `$((1+2))` and `$(date)`
4. word splitting of the results of step 3, on blanks
5. pathname expansion, the globbing step
6. quote removal

Almost every shell surprise is a consequence of this order. In particular, **programs do not glob; the shell does**.
`ls *.txt` is really `ls a.txt b.txt` by the time `ls` starts.

## Navigating

Every process has a working directory. Absolute paths start at `/`, relative paths start from the working directory,
and `.` and `..` mean the current and parent directory.

| You type | What happens |
|---|---|
| `cd` or `cd ~` | go home |
| `cd -` | return to the previous directory (stored in `OLDPWD`) |
| `pushd DIR`, `popd` | dive into a directory and come back, using a stack |
| `pwd -P` | print the physical path, with symbolic links resolved |
| `CDPATH=~/work:/srv` | let `cd project` search the listed parents |

## Globbing

A glob is a pattern language of its own, separate from regular expressions.

| Pattern | Matches |
|---|---|
| `*` | any run of characters, but not a leading dot |
| `?` | exactly one character |
| `[abc]`, `[a-c]`, `[!a-c]` | one character from, or not from, a set |
| `{x,y}` | not a glob but brace expansion: expands to two words |

Three behaviours deserve attention:

- **Hidden files** (leading dot) are skipped by `*` unless you set `shopt -s dotglob`.
- **No match** means the pattern is passed through unchanged. `ls *.zip` with no zip files runs `ls '*.zip'`. Use
  `shopt -s nullglob` to expand to nothing, or `failglob` to raise an error.
- **Sorting** follows the locale, so order can differ between machines.

## Quoting

Quoting stops the shell from interpreting characters you mean literally.

| Tool | Effect |
|---|---|
| backslash `\x` | protects the one character after it |
| single quotes `'...'` | protect everything, with no exceptions |
| double quotes `"..."` | protect most things, but still expand `$var`, `$(cmd)` and `$((..))` |
| `$'...'` | single quotes that also translate escapes such as `\n` and `\t` |

The rule that prevents most bugs: **quote every expansion that holds a name**. Inside double quotes a variable
becomes exactly one word, and it is not split or matched against files.

```bash
name='my notes.txt'
cat $name          # two words: cat 'my' 'notes.txt'  (fails)
cat "$name"        # one word: works
```

## History

The history list records previous commands. A reverse search (`Ctrl-R`) finds an older line by a fragment, and the
arrow keys walk the list. Separately, history expansion rewrites a line before it is parsed:

| Expansion | Meaning |
|---|---|
| `!!` | the previous command |
| `!$` | the last word of the previous command |
| `^old^new` | repeat the previous command with `old` replaced by `new` |

Three variables and one option control what is kept: `HISTCONTROL` (for example `ignoreboth` drops lines that start
with a space and duplicates), `HISTSIZE` (entries in memory), `HISTFILE`, and `shopt -s histappend` (append to the
file at exit instead of overwriting it). A command prefixed with a space is a quick way to keep a password out of the
file, but only if `ignorespace` or `ignoreboth` is set.

## Worked example: a file name that fights back

```bash
mkdir demo && cd demo
touch a.txt 'my notes.txt' ./-rf.txt
rm *.txt            # the shell expands this, in sorted order, to: -rf.txt a.txt 'my notes.txt'
```

Here `rm` receives `-rf.txt` first, which looks like an option. The files were saved from harm only because the
combination is not a valid option set. Make the intent explicit instead:

```bash
printf '%s\n' *.txt      # names, one per line, safe for every name
rm -- -rf.txt            # `--` ends option processing
rm ./-rf.txt             # or give the name a directory prefix
```

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| A loop treats one file as two | An unquoted variable was split on the blank | Quote `"$f"` |
| A command complains about a file named `*.log` | The glob matched nothing and passed through | `shopt nullglob` or `failglob` |
| A deletion behaves like it was given options | A name starting with `-` | Use `--` or a `./` prefix |
| `Argument list too long` | The glob expanded past the kernel limit | Use `find ... -exec` or `xargs` |
| `!` does odd things when pasted | History expansion fired | Use single quotes, or `set +H` |
