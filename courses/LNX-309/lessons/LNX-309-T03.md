# keepalived and HAProxy

This lesson follows the topic synthesis `synth/LNX-309/LNX-309-T03.md`, which carries the sources, the history and the failure cases.

## What you will be able to do

- Explain how VRRP moves a floating address and what its failure modes are.
- Write a keepalived pair with a health script and a HAProxy configuration with health-checked back ends.
- Decide between this design, a Pacemaker cluster and a cloud load balancer.
- Test failover and avoid VRRP split brain.

## Two small daemons

| keepalived | HAProxy |
|---|---|
| VRRP: elects a master by priority, master holds the address | proxy at layer 4 (TCP) or 7 (HTTP) |
| sends gratuitous ARP when the address moves | spreads requests, removes failed servers |
| `vrrp_script` and `track_script` lower priority when a check fails | `check inter 2s fall 3 rise 2` per server |

## keepalived essentials

```text
global_defs { enable_script_security  script_user root }
vrrp_script chk_haproxy { script "/usr/bin/pidof haproxy"  interval 2  fall 2  rise 2 }
vrrp_instance VI_WEB {
    state BACKUP   interface eth0   virtual_router_id 51   priority 150   advert_int 1
    unicast_src_ip 192.168.10.11   unicast_peer { 192.168.10.12 }
    virtual_ipaddress { 192.168.10.100/24 dev eth0 }
    track_script { chk_haproxy }
}
```

The `virtual_router_id` matches on both nodes and is unique on the VLAN; priorities differ. Use unicast on filtered networks. `nopreempt` avoids a second interruption when the old master returns. Test with `keepalived -t -f file`.

## HAProxy essentials

```text
frontend web   bind 192.168.10.100:80   default_backend app
backend app    balance leastconn   option httpchk GET /healthz
               server app1 192.168.10.21:8080 check inter 2s fall 3 rise 2
```

- Set `net.ipv4.ip_nonlocal_bind=1` so the standby can bind the address it does not yet hold.
- Validate with `haproxy -c -f`; drain with the runtime socket (`set server app/app1 state drain`).
- Pass the client address with `option forwardfor` or the PROXY protocol.
- Keep SELinux `haproxy_connect_any` off and label back-end ports instead.

## Choosing

| Situation | Use |
|---|---|
| stateless web tier on a network you control | keepalived + HAProxy |
| stateful service, shared storage, strict ordering | Pacemaker with fencing |
| public cloud | managed load balancer or cloud address agents (VRRP and ARP tricks often do not work) |

## Failure modes

- VRRP split brain from filtered multicast: both nodes hold the address. Use unicast and alert on duplicates.
- A health script flaps and moves the address needlessly.
- Reload with an unvalidated configuration.
- Health check tests the web server but not the application.

## Worked example: two masters

A switch update filtered multicast, so each node took the address. The mistake was hidden because both proxied to the same back ends. Unicast peers and a failover test after every network change fixed it.
