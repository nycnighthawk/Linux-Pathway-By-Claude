# createrepo_c, aptly, Pulp 3

This lesson follows the topic synthesis `synth/LNX-304/LNX-304-T04.md`, which carries the sources, the history and the failure cases.

## What you will be able to do

- Build and update an RPM repository with `createrepo_c` and a Debian repository with `apt-ftparchive` or `aptly`.
- Mirror upstream content with `reposync` and `aptly mirror`, and say what to filter.
- Describe Pulp 3's remote, repository, publication and distribution chain.
- Publish atomically and set a retention rule.

## RPM repositories

```bash
createrepo_c /srv/repo/el9/noarch/            # writes repodata/
createrepo_c --update /srv/repo/el9/noarch/   # incremental, after adding packages
gpg --detach-sign --armor repo/repodata/repomd.xml
reposync --repoid=baseos --newest-only --download-metadata -p /srv/mirror
```

`repodata/repomd.xml` lists `primary`, `filelists` and `other` (and `updateinfo` for advisories) with checksums. Clients read it first, so it is the file to sign and the file to monitor for age. Check with `dnf --repofrompath=t,URL --repo=t list available`.

## Debian repositories

```bash
apt-ftparchive packages . > Packages && gzip -k Packages     # flat repository
apt-ftparchive release . > Release && gpg --clearsign -o InRelease Release
aptly repo create -distribution=bookworm -component=main site
aptly repo add site pkg.deb
aptly snapshot create site-2026-11-15 from repo site
aptly publish snapshot -gpg-key=KEYID site-2026-11-15 internal
```

A flat repository ends its source entry with `./`. A proper archive has `pool/` and `dists/` and is built by `reprepro` or `aptly`.

## Pulp 3 in one picture

remote (where from) → repository (versioned, every change is a new immutable version) → publication (metadata for one version) → distribution (a stable URL that points to a publication). Rolling back is pointing the distribution at an older publication. Sync policies: `immediate`, `on_demand`, `streamed`.

## Publish safely

Build aside, validate, then switch a symlink or use `aptly publish switch`. Write index files last. Keep every version that a snapshot or lifecycle stage still needs, and delete the rest by a written retention rule. Alert when `repomd.xml` or `InRelease` is older than the sync interval.

## Worked example: the half-published mirror

A nightly in-place sync replaces the index before 40 packages arrive; a patch job at 02:12 gets 404s. Sync into a staging directory, check it, then swap.
