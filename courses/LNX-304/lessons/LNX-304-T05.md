# Dated snapshots

This lesson follows the topic synthesis `synth/LNX-304/LNX-304-T05.md`, which carries the sources, the history and the failure cases.

## What you will be able to do

- Explain what a repository snapshot freezes and what it does not.
- Create cheap, immutable, dated snapshots and point environments at them.
- Promote and roll back by changing a pointer, and say what a rollback does not undo.
- Set a retention rule that cannot delete a live pointer's target.

## Two layers

Snapshots are immutable and named by date. Environments (`dev`, `test`, `prod`) are mutable pointers to snapshots. Only the pointer layer changes during a rollout.

```bash
cp -al mirror/el9 snapshots/2026-11-01     # hard links: unchanged files cost nothing
chmod -R a-w snapshots/2026-11-01          # immutable by permission
ln -sfn ../snapshots/2026-11-01 channels/prod
aptly snapshot create bookworm-2026-11-08 from mirror bookworm
aptly publish switch bookworm prod/bookworm bookworm-2026-11-08
aptly snapshot diff bookworm-2026-11-01 bookworm-2026-11-08
```

Pulp makes a new repository version at every change; a distribution is the pointer. `snapshot.debian.org` is a public, timestamped archive useful for rebuilding old states.

## Make them correctly

1. Snapshot the whole set of repositories that feed a machine, under one name.
2. Sync completely, verify, then snapshot, in one job that fails closed.
3. Re-sign internally or relax `Valid-Until` knowingly: an old signed index expires.
4. Clients take the environment name from configuration, never a date typed by hand.

## Roll back honestly

Pointing `prod` at the previous snapshot restores what can be installed. It does not downgrade installed packages (use `dnf downgrade`, `dnf history undo` or a pinned `apt install pkg=version`) and it does not touch data. Pair it with a machine-level snapshot for critical systems.

## Retention

Keep every snapshot a pointer refers to, the previous one for each environment, and a compliance tail. Refuse to delete anything referenced. Watch the age of production's pointer: a long freeze is an unpatched fleet.

## Worked example: the deleted rollback target

A clean-up job deleted snapshots older than 30 days, but production was held on a 45-day-old snapshot for a change freeze. The next promotion failed and rollback was impossible. The fix is a check against the pointer list before any deletion.
