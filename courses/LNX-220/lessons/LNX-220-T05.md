# Sanitizers and static analysis

This lesson follows the topic synthesis `synth/LNX-220/LNX-220-T05.md`, which carries the sources and the history.

## What you will be able to do

- Build with AddressSanitizer and UndefinedBehaviorSanitizer and read their reports.
- Set sanitizer options through environment variables and know which sanitizers cannot be combined.
- Use compiler warnings, GCC's analyzer and clang-tidy as the static layer.
- Place each tool in a continuous-integration pipeline.

## Sanitizers

Compile and link with the same flag: `-fsanitize=address`, `-fsanitize=undefined`, `-fsanitize=thread`, `-fsanitize=memory` (Clang only), `-fsanitize=leak`. Add `-g`, `-O1` and
`-fno-omit-frame-pointer`. ASan and UBSan combine; TSan and MSan stand alone.

```bash
cc -g -O1 -fsanitize=address,undefined -fno-sanitize-recover=all -o app app.c
ASAN_OPTIONS=detect_leaks=1:abort_on_error=0 UBSAN_OPTIONS=print_stacktrace=1 ./app
```

LeakSanitizer needs `ptrace`; in a container without it set `detect_leaks=0`. By default UBSan continues after a finding; `-fno-sanitize-recover=all` makes it stop, which suits tests.

## Reading an ASan report

First line: the error kind (`heap-buffer-overflow`, `heap-use-after-free`, `stack-buffer-overflow`, `double-free`) and the access size. Then the stack of the bad access, then where the block was
allocated and, for use after free, where it was freed. Start with the first frame in your own code. UBSan prints one line: file, line and kind (`signed integer overflow`, `shift exponent too large`, `load of misaligned address`).

## Static layer

- Warnings: `-Wall -Wextra -Wformat=2 -Wshadow`, with `-Werror` in CI.
- GCC: `-fanalyzer` explores paths for double free, leaks, null dereference and buffer problems.
- Clang: `scan-build make`, and `clang-tidy -p build file.c` using `compile_commands.json`.
- `cppcheck` is compiler independent. Kernel code uses Sparse, Smatch and Coccinelle.

Sanitizers see only paths that run; static tools see paths that do not run but can be wrong, so keep a baseline and a reviewed suppression list.

## Worked example: the off-by-one

A loop `for (i = 0; i <= n; i++) buf[i] = ...` writes one int past a heap block. The program prints the right sum. Under ASan the first line is a heap-buffer-overflow WRITE of size 4,
the allocation stack points at `malloc((size_t)n * sizeof *buf)` and the fix is `i < n`. In the same program `a * b` with large operands is flagged by UBSan as signed overflow; the fix is
to widen to 64 bits and clamp or to reject the input.
