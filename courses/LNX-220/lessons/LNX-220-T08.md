## A new-style daemon

It does not fork into the background, does not write a pid file, logs to stderr, and lets the manager handle restarts and logs. The unit says how to treat it through `Type=`: `simple`, `exec`, `notify`
(wait for `READY=1`), `oneshot`, `forking` (legacy).

## sd_notify

systemd sets `NOTIFY_SOCKET` to a datagram socket path (a leading `@` means the abstract namespace). Send text datagrams of `KEY=VALUE` lines: `READY=1`, `STATUS=waiting for jobs`, `RELOADING=1`, `STOPPING=1`,
`MAINPID=`, `WATCHDOG=1`. `NotifyAccess=main` allows only the main process to send. Without the variable the call is a no-op, so the same binary runs anywhere. From shell: `systemd-notify --ready --status="up"`.

```python
import os, socket
def notify(msg):
    path = os.environ.get("NOTIFY_SOCKET")
    if not path: return
    s = socket.socket(socket.AF_UNIX, socket.SOCK_DGRAM)
    s.sendto(msg.encode(), "\0" + path[1:] if path[0] == "@" else path)
```

## Socket activation

A `.socket` unit has `ListenStream=`, `ListenDatagram=` and so on. The manager binds the socket and starts the service on demand, passing descriptors starting at number 3. Environment: `LISTEN_FDS` (count),
`LISTEN_PID` (must equal your own pid, otherwise ignore everything), `LISTEN_FDNAMES`. `Accept=no` passes the listening socket; `Accept=yes` starts one instance per connection. Restarting the service loses no connections because
the kernel keeps them queued on the manager's socket. Test without installing units: `systemd-socket-activate -l 8080 ./server`.

```ini
# lab.socket
[Socket]
ListenStream=/run/lab.sock
[Install]
WantedBy=sockets.target

# lab.service
[Service]
Type=notify
NotifyAccess=main
ExecStart=/usr/local/bin/labd
```

## Logging

Anything on stdout or stderr goes to the journal. A line starting `<3>` is an error and `<6>` informational (`<0>` to `<7>` are the syslog levels). For structured fields use `sd_journal_send()`. Query:
`journalctl -u lab.service -b -p err`, `journalctl -o json-pretty -n 5`, `journalctl _PID=1234`. Use `systemd-cat -t tag cmd` to pipe a command's output into the journal.

## Worked example: the service that "hangs" at start

With `Type=notify` the manager waits until `TimeoutStartSec` (90 s by default) for `READY=1`. If the program never sends it, `systemctl start` hangs and then kills it although the process ran fine. Either send the message after
initialisation or use `Type=simple`. A second classic mistake is launching the program from a wrapper shell script without `exec`: the pid no longer matches `LISTEN_PID`, so the program ignores its sockets.
