# Unit tests, coverage and fuzzing

This lesson follows the topic synthesis `synth/LNX-220/LNX-220-T06.md`, which carries the sources and the history.

## What you will be able to do

- Structure C code so parsing logic can be tested apart from I/O.
- Measure line coverage with gcov and read the gaps.
- Write a libFuzzer-style harness and run it with sanitizers or a standalone driver.
- Turn every fuzzer crash into a permanent regression test.

## Unit tests

Keep logic in a library, `main()` thin. A test program uses `assert()` or a framework and exits non-zero on failure. Register it with the build system: `test('name', exe)` in Meson,
`add_test()` and `ctest` in CMake, a `check` target in make. Run it once under ASan and UBSan ([LNX-220-T05](lesson:LNX-220-T05)). Tests must be fast, deterministic and independent of each other.

## Coverage with gcov

```bash
cc -O0 --coverage -o t parse.c tests.c
./t
gcov -n t-parse.gcda          # or gcovr / lcov for reports
```

`--coverage` writes `.gcno` (flow graph) at compile time and `.gcda` (counters) at run time. Use `-O0` so lines map cleanly. Read the unexecuted lines: they are the error returns and boundary cases nobody tested. High coverage proves execution, not correctness.

## Fuzzing

A harness is one function:

```c
int LLVMFuzzerTestOneInput(const uint8_t *data, size_t size) {
    struct kv out[4];
    parse_kv((const char *)data, size, out, 4);
    return 0;
}
```

With Clang: `clang -g -O1 -fsanitize=fuzzer,address,undefined harness.c parse.c -o fuzz` then `./fuzz corpus/` (options `-max_len`, `-dict`, `-runs=0` to replay, `-merge=1` to minimise, `-fork=N`). AFL++:
`afl-clang-fast` to build and `afl-fuzz -i seeds -o out -- ./target`. A standalone driver that replays files and generates inputs lets you use the same harness with plain gcc, as in the lab. Seeds of valid inputs and a token dictionary help; checksums and signatures
block blind mutation, so build a fuzzing mode that skips them (never in production).

## Worked example: from crash to regression test

The fuzzer stops with an ASan stack overflow report and leaves a `crash-...` file. Replay it: `./fuzz crash-file`. Minimise with `-minimize_crash=1`. The stack shows `memcpy` into a 16-byte field with a longer value;
add a length check, replay the file (no crash now), and commit it under `tests/regress/`. A unit test then replays every file in that directory so the bug cannot return.
