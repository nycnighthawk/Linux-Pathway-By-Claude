## Make in one page

A rule has the form `target: prerequisites` and a tab-indented recipe. make compares modification times and runs the recipes of stale targets. Variables
carry flags (`CC`, `CFLAGS`, `CPPFLAGS`, `LDFLAGS`, `LDLIBS`). Automatic variables: `$@` target, `$<` first prerequisite, `$^` all prerequisites. Targets that
are not files (`clean`, `test`, `install`) are declared `.PHONY`. Useful options: `-j N`, `-n` (print only), `-k`, `-C dir`, `-B`, `-d`.

```make
CC ?= cc
CFLAGS ?= -O2 -g
CPPFLAGS += -MMD -MP
SRC := $(wildcard src/*.c)
OBJ := $(SRC:src/%.c=obj/%.o)

calc: $(OBJ)
	$(CC) $(LDFLAGS) -o $@ $^

obj/%.o: src/%.c | obj
	$(CC) $(CPPFLAGS) $(CFLAGS) -c $< -o $@

obj:
	mkdir -p $@

clean:
	rm -rf obj calc

-include $(OBJ:.o=.d)
.PHONY: clean
```

`-MMD -MP` makes the compiler write `foo.d` listing every header it read, so a changed header rebuilds exactly the objects that include it. The `| obj` is an
order-only prerequisite: the directory must exist but its timestamp never forces a rebuild.

## CMake

```cmake
cmake_minimum_required(VERSION 3.16)
project(calc C)
add_executable(calc src/main.c src/calc.c)
target_include_directories(calc PRIVATE src)
install(TARGETS calc RUNTIME DESTINATION bin)
enable_testing()
add_test(NAME runs COMMAND calc)
```

Configure `cmake -S . -B build -DCMAKE_BUILD_TYPE=Release`, build `cmake --build build -j`, test `ctest --test-dir build`, install
`DESTDIR=$PWD/stage cmake --install build --prefix /usr`. Properties attach to targets with `PRIVATE`, `PUBLIC` or `INTERFACE` and propagate through
`target_link_libraries`. `-DCMAKE_EXPORT_COMPILE_COMMANDS=ON` writes `compile_commands.json` for analysers.

## Meson

```meson
project('calc', 'c')
executable('calc', ['src/main.c', 'src/calc.c'], install : true)
test('runs', executable('t', 'tests/t.c'))
```

`meson setup build --prefix=/usr`, `meson compile -C build`, `meson test -C build`, `DESTDIR=$PWD/stage meson install -C build`. Sanitizers and coverage
are options: `-Db_sanitize=address,undefined`, `-Db_coverage=true`.

## Worked example: why does it always relink?

Run `make -d | head -40` or `make --trace`. If a prerequisite named in the program's rule is phony or never created, make treats it as newer every time. If an object never
rebuilds after a header edit, the Makefile has no `-MMD` and no `-include`. With Ninja, `ninja -d explain` tells you why each step is considered dirty, and for CMake
`cmake --build build --verbose` prints the actual compile line so you can see whether your flag arrived.
