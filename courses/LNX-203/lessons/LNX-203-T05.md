## What you will be able to do

## A tool skeleton

```python
#!/usr/bin/env python3
import argparse, json, logging, sys

def main(argv=None):
    p = argparse.ArgumentParser(description="Report full mounts.")
    p.add_argument("--threshold", type=float, default=80.0)
    p.add_argument("file")
    args = p.parse_args(argv)
    logging.basicConfig(stream=sys.stderr, level=logging.INFO, format="%(levelname)s: %(message)s")
    ...
    return 0

if __name__ == "__main__":
    sys.exit(main())
```

`main()` returns the status and takes `argv`, so tests can call it. Results go to standard output, diagnostics through `logging` to standard error; argparse itself exits 2 for a usage error and 0 for `--help`. Pick exit codes on purpose and document them (0 healthy, 1 problem found, 2 could not run is a common monitoring convention).

## Files, JSON and processes

`pathlib.Path` replaces string handling of paths: `Path(p).read_text()`, `.glob("*.log")`, `.stat().st_size`, `/` to join. The `json` module loads and dumps JSON; `csv`, `tomllib` and `configparser` cover other formats.

```python
import subprocess
r = subprocess.run(["systemctl", "is-active", unit], capture_output=True, text=True, check=False)
if r.returncode != 0: ...
```

Pass a list, not a string, and leave `shell=False` so a value cannot be reinterpreted by a shell. Use `check=True` to raise `CalledProcessError`, `timeout=` to bound the run and `capture_output=True` to collect output. Catch the specific exceptions you can handle (`OSError`, `json.JSONDecodeError`) and let the rest surface.

## Environments and packaging

`python3 -m venv .venv` creates an isolated environment; `.venv/bin/pip install -r requirements.txt` fills it, and pinned requirements make runs repeatable. Distribution packages that provide Python modules (for example `python3-requests`) suit scripts that run on one managed host; a venv suits an application with its own dependencies. A `pyproject.toml` with a `[project.scripts]` entry turns a function into an installed command, and `pytest` runs tests that call `main([...])` directly and check the return value and captured output.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| `ModuleNotFoundError` under cron or systemd | different interpreter or environment than your shell | `sys.executable`, the unit's `ExecStart` |
| Output vanishes in a pipe | buffering | `print(..., flush=True)` or `python3 -u` |
| Shell metacharacters in a name do damage | `shell=True` with interpolated text | pass an argument list |
| Division by zero on empty data | missing guard | handle zero sizes explicitly |
