# KubeVirt and OpenShift Virtualization

This lesson follows the topic synthesis `synth/LNX-315/LNX-315-T09.md`. Field names follow the current API and are marked (to verify) there for your release.

## What you will be able to do

- Describe the components that turn a VM into a Kubernetes object.
- Write a VirtualMachine with an instance type, a preference, an imported disk and a cloud-init seed.
- Say what live migration needs and what blocks it.

## Architecture

- **virt-api** validates and serves the new resource types.
- **virt-controller** watches VMs and creates the pods that realise them.
- **virt-handler** is a per-node agent (DaemonSet).
- **virt-launcher** is the pod that holds libvirt and QEMU for one VM, its disks and its network plumbing.

Kubernetes schedules the launcher pod, so node selectors, taints, affinity and resource requests place VMs. Nodes need hardware virtualization.

## Two objects

A **VirtualMachine** is the durable definition with a run strategy (Always, Halted, Manual, RerunOnFailure, Once). A **VirtualMachineInstance** is one running instance and comes and goes. You normally work with the VM.

## Specification

Instance types set size (CPU, memory); preferences set the guest profile (devices, firmware). A VM can reference both by name. Pinning, hugepages, NUMA, IOThreads, TPM and Secure Boot appear as fields that map to the libvirt features you met earlier.

## Storage

Volumes can be PVCs, DataVolumes, container disks, cloud-init and sysprep sources, config maps or secrets. The Containerized Data Importer fills a DataVolume from an HTTP URL, a registry image, an upload or a clone. Import a golden image once and clone it per VM. Filesystem and block volume modes differ; block avoids a layer.

## Networking

The pod network with **masquerade** binding is simple and works with Services. For real layer 2 access, attach a secondary network (bridge, VLAN, SR-IOV VF) through a network attachment definition.

## Live migration

Create a VirtualMachineInstanceMigration or run `virtctl migrate`. It needs shared storage with a shared access mode, bandwidth, compatible CPUs and no blocking feature such as PCI passthrough. Node drains use migration when the eviction strategy says so.

## OpenShift Virtualization

The supported product built on KubeVirt: operator, console, templates, upgrade path and integrations. The engine is the same QEMU and libvirt.

## What goes wrong

A VM stuck scheduling (no virtualization node, no memory for guest plus overhead, unbound volume); a non-migratable VM stalling a node drain; broad access to VM subresources granting console access; a stateful VM's volumes deleted with its namespace; treating the pod memory limit as the whole VM cost.
