# SR-IOV virtual functions for NICs and GPUs

This lesson follows the topic synthesis `synth/LNX-315/LNX-315-T02.md`, which carries the sources, the history and the failure cases.

## What you will be able to do

- Explain the physical function and virtual function split and what the hardware divides.
- Enable VFs, set per-VF policy through the PF, and attach a VF to a guest.
- Weigh SR-IOV against paravirtual networking, especially for migration and visibility.

## The idea

One physical device presents a few **physical functions (PF)** that the host controls and many lightweight **virtual functions (VF)**. A VF has its own PCI identity, registers and queues, so each can go to a different VM through VFIO with its own IOMMU group. The guest uses an ordinary VF driver; the data path bypasses the host.

## Enable and configure

```bash
echo 0  > /sys/class/net/ens1f0/device/sriov_numvfs     # change a non-zero count only via 0
echo 12 > /sys/class/net/ens1f0/device/sriov_numvfs
ip link set ens1f0 vf 0 mac 52:54:00:aa:00:00 vlan 120 \
   max_tx_rate 10000 spoofchk on trust off state auto
```

Per-VF policy lives on the PF: MAC, VLAN and QoS tag, rate limits, spoof checking, trust, link state. They are your main controls over a guest with direct hardware access; set them explicitly. Make the count persistent with a unit or `systemd.link` and `systemd.network` `[SR-IOV]` sections.

## Attach

libvirt: a `hostdev` of the VF's PCI address, or an `<interface type='hostdev'>` (libvirt sets MAC and VLAN first), or a network with `<forward mode='hostdev' managed='yes'><pf dev='ens1f0'/></forward>` as a pool. KubeVirt: an `sriov` binding plus a Multus network attachment and the SR-IOV device plug-in. GPUs: vendor tooling creates VFs with a profile (memory, compute share); the guest needs the vendor driver.

## Limits to plan for

Fixed VF count; queues and interrupt vectors shared across VFs (too many VFs starve each one); no host visibility of VF traffic without switchdev, representors and offload; no ordinary live migration (failover bonding with a virtio standby, or vendor VFIO migration); the PF mailbox is attack surface; shared PCIe bandwidth gives noisy neighbours.

## Worked example: 64 VFs, 40 VMs

Enabling all 64 VFs left too few interrupt vectors per VF; some came up with one queue and starved. Enable only what you need and set queues per VF explicitly.
