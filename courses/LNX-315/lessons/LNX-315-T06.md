# VirtualBox administration from the command line

This lesson follows the topic synthesis `synth/LNX-315/LNX-315-T06.md`, which carries the sources, the history and the failure cases.

## What you will be able to do

- Build, start and snapshot a VirtualBox machine with `VBoxManage` alone.
- Pick a network mode for a stated reachability requirement.
- Keep Guest Additions healthy and use the guest-property service instead of polling.

## The object model

VirtualBox keeps a registry of machines, disk images and networks. Each machine has a name, a UUID and a state. A disk is its own object and can outlive a machine. `VBoxManage` is a client of a background service, so everything the window does can be commanded. Never edit a settings file while the service is running.

## A scripted build

1. `createvm --name N --ostype T --register` creates and registers the machine.
2. `modifyvm` sets memory, CPUs, firmware, chipset, I/O APIC and network adapters.
3. `createmedium disk` makes the disk; `storagectl` adds a controller; `storageattach` attaches the disk and the installer image.
4. `startvm N --type headless` runs it with no window.

Finish a script with `showvminfo --machinereadable` so you can compare the machine with your intent. Use machine-readable output when a script parses results.

## Headless operation

Without a display, see early boot through a serial port redirected to a file or socket (no extension needed), and reach the guest through the network afterwards. The `controlvm` command pauses, saves, resets and sends an ACPI power button for a polite shutdown. A hard power-off may leave the guest file system dirty.

## Guest Additions

The additions are drivers and services inside the guest: shared folders, time sync, clipboard, and the guest-property and guest-control services. On Linux they build kernel modules per kernel, so use the distribution package with DKMS where there is one. When a feature breaks after a kernel update, check the additions version and whether a module exists for the running kernel.

The host can wait for a guest-published property such as the IP address and then SSH in, which is more robust than polling a port.

## Network modes

| Mode | Guest reaches out | Host or LAN reaches guest | Guests reach each other |
|---|---|---|---|
| NAT | yes | only through port forwards | no |
| NAT network | yes | only through forwards | yes |
| Bridged | yes | yes, as a LAN peer | yes |
| Host-only | no (unless a second adapter) | host only | yes |
| Internal | no | no | yes |

A common development layout is adapter 1 NAT for outbound traffic plus adapter 2 host-only for SSH from the host.

## Snapshots and clones

A snapshot creates a differencing disk. Long chains slow I/O and use space, so a snapshot is not a backup. A clone needs a fresh machine-id and SSH host keys inside the guest, or machines collide.

## What goes wrong

A missing kernel module after a host kernel update with Secure Boot on; Guest Additions that drifted from the host; scripts parsing human-readable output; a bridged adapter on wireless; cloned guests with duplicate identities; snapshot chains that fill the disk.
