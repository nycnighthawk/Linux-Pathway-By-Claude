# Disk images: qcow2 internals, backing chains and block jobs

This lesson follows the topic synthesis `synth/LNX-315/LNX-315-T04.md`, which carries the sources, the history and the failure cases.

## What you will be able to do

- Explain how qcow2 maps guest addresses to file clusters and why a new image is tiny.
- Build, inspect, rebase, commit, flatten and check backing chains without losing data.
- Choose the right live block job (commit, pull, copy) and the right backup approach.

## Structure in brief

A qcow2 file is a header, header extensions, then clusters (64 KiB by default). A guest address goes through the **L1 table** to an **L2 table** to a data cluster; **refcounts** record how many users each file cluster has (more than one means copy-on-write). Unallocated clusters read as zeros, or from the **backing file** if there is one. Version 3 adds zero clusters, lazy refcounts and header extensions (bitmaps, encryption, data file); newer QEMU adds zstd compression and subcluster-sized extended L2 entries.

Creation options that matter: `cluster_size`, `preallocation` (off, metadata, falloc, full), `lazy_refcounts`, `compression_type`, `extended_l2`.

## The commands

```bash
qemu-img create -f qcow2 -b base.qcow2 -F qcow2 vm1.qcow2     # always state the backing format
qemu-img info --backing-chain vm1.qcow2
qemu-img map vm1.qcow2                                         # which layer owns each range
qemu-img check vm1.qcow2                                       # -r all repairs, best effort
qemu-img commit vm1.qcow2                                      # merge the overlay down into its backing file
qemu-img rebase -F qcow2 -b new-base.qcow2 vm1.qcow2           # copy data so content stays the same
qemu-img rebase -u -b moved-base.qcow2 vm1.qcow2               # only rewrite the pointer; content must be identical
qemu-img convert -O qcow2 vm1.qcow2 flat.qcow2                 # standalone copy of the whole chain
```

## Live

External snapshot: `virsh snapshot-create-as --disk-only --atomic` (add the guest agent's freeze for consistency). Merge it back with a block **commit** (top into base; `--active --pivot` for the running layer), or **pull** (stream base data into the overlay, to drop a slow or remote base). Move a disk with `blockcopy`. A job has a state to poll and often an explicit finish; do not delete old files until it has concluded.

Backup: persistent **dirty bitmaps** record changes since a point in time; push or pull backup copies only those clusters; a restore needs the full plus each increment in order.

## Space

Thin provisioning promises more than the storage has. Watch free space, enable discard end to end (guest fstrim, bus unmap, image) to reclaim.

## Worked example: the "unused" base

A base file was deleted after one overlay was committed. Forty other overlays used it and none could start. Before touching a base, run `qemu-img info --backing-chain` over every image to list dependants.
