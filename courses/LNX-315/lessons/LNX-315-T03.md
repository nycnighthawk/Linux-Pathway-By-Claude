# Performance: NUMA, CPU pinning, hugepages, IOThreads, virtio-blk and virtio-scsi

This lesson follows the topic synthesis `synth/LNX-315/LNX-315-T03.md`, which carries the sources, the history and the failure cases.

## What you will be able to do

- Read the host topology and turn it into a placement plan for a guest.
- Write the libvirt settings for NUMA memory, vCPU and I/O thread pinning, hugepages and CPU model.
- Choose between virtio-blk and virtio-scsi, configure multiqueue and IOThreads, and prove a change with a benchmark.

## Look first

```bash
lscpu -e                      # cpu, node, socket, core: find SMT siblings
numactl --hardware            # nodes, free memory, distances
cat /sys/class/block/nvme0n1/device/numa_node
numastat -c qemu-kvm          # where a running guest's memory is
```

CPU numbering differs between machines. Never copy pinning from another host without checking this output.

## The layout decisions

| Resource | Decision | libvirt |
|---|---|---|
| memory | which node, how strict | `numatune/memory mode='strict' nodeset='1'` |
| vCPUs | whole cores, siblings together, same node as memory and device | `cputune/vcpupin` |
| helper threads | keep off the pinned cores | `emulatorpin`, `iothreadpin` |
| page size | 1 GiB or 2 MiB hugepages reserved on that node | `memoryBacking/hugepages` |
| CPU | host-passthrough for speed; named model for migration | `cpu mode=` |
| topology | tell the guest the truth | `cpu/topology` and NUMA cells |

Pinning removes migrations and cache thrash but also the scheduler's ability to balance. Reserve hugepages at boot (1 GiB pages need it); remember reserved memory disables overcommit and ballooning for those guests. Isolate cores on the host (`isolcpus`, `nohz_full`, `rcu_nocbs`, IRQ affinity, a tuned profile) and measure jitter.

## Disks

- **virtio-blk**: shortest path, best IOPS per CPU cycle; each disk takes a PCI slot.
- **virtio-scsi**: one controller for many disks, SCSI features (reservations, UNMAP, WRITE SAME), a few per cent slower.
- Both: `queues` equal to the vCPU count, an IOThread (`iothreads`, `driver iothread=`), `cache='none' io='native'`; enable discard end to end for thin storage.

## Measure

fio with the real block size and queue depth, in the guest; the application's own latency percentiles (p99, p999). Change one thing at a time and keep the XML with the result.

## Worked example: wrong siblings

XML copied from a host where siblings were adjacent was applied to a host where siblings are cpu+16. The guest's SMT pairs were on different cores and ran 30 per cent slower than untuned. A pre-flight script that checks pinning against `lscpu` output would have caught it.
