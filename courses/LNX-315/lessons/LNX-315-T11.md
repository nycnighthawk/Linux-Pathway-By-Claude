# Live migration tuning

This lesson follows the topic synthesis `synth/LNX-315/LNX-315-T11.md`. Option names and minimum versions change; they are marked (to verify) there.

## What you will be able to do

- Read migration counters and say whether a migration will converge.
- Choose between multifd, auto-converge, dirty limit and post-copy for a given guest and policy.
- Write a `virsh migrate` command with deliberate settings, and a drain policy for a cluster.

## The model

Pre-copy sends all memory, then repeatedly resends what the guest dirtied, then pauses the guest for a short final copy. It converges when the remaining dirty memory can be sent within the allowed downtime. Compare three numbers: the dirty rate, the transfer rate, and the downtime target. Before the switchover, the source holds the full current state, so a failure leaves the guest running.

## The controls

| Control | Effect | Cost |
|---|---|---|
| Bandwidth cap | protects other traffic | too low means no convergence |
| Max downtime | accepted final pause | longer pause |
| **Multifd** | several connections fill a fast link | CPU and threads |
| **XBZRLE** and accelerator compression | fewer bytes for re-dirtied pages | CPU, cache memory |
| **Auto-converge** | throttles all vCPUs in steps | slows the whole guest |
| **Dirty limit** | throttles only vCPUs above a dirty-rate limit (needs KVM dirty ring) | still slows busy vCPUs |
| **Post-copy** | run on the target early, fetch missing pages on demand | state split between hosts; failure can lose the guest |
| Timeout | abort or switch strategy | |

Older multi-thread compression was removed from recent QEMU. With post-copy, multifd speeds only the pre-copy phase.

## Interactions

PCI passthrough blocks generic migration. Hugepages change tracking granularity. Pinning and NUMA must be satisfiable on the target. Unshared disks add block migration time.

## KubeVirt

Cluster-wide settings cover concurrent migrations, per-migration bandwidth, completion timeouts, auto-converge, post-copy and a migration network. The eviction strategy decides whether a drain migrates guests.

## A tuning method

1. Measure the guest's dirty rate under load.
2. Check usable bandwidth and MTU.
3. Enable multifd on fast links; set the cap deliberately.
4. Set downtime from the application's tolerance.
5. Add selective throttling if allowed.
6. Use post-copy last, on a reliable network.
7. If all fails, change the plan.

## What goes wrong

Twenty simultaneous migrations over one link; a pause far longer than assumed; a mixed-CPU fleet where one host pair fails; tuning tested only on an idle guest.
