# Milestone 3: provision, harden, patch, upgrade, decommission

This milestone follows the topic synthesis `synth/LNX-401/LNX-401-T03.md`. Product versions and defaults change; confirm them in current vendor documents (to verify).

## Goal

Script the full life of a host and prove each step.

## Lessons this milestone relies on

- LNX-306-T01 to T04 (unattended install, network boot, cloud-init, Packer)
- LNX-306-T08 and T09 (release upgrades, drift detection and secure wipe)
- LNX-204-T09 and T11 (OpenSCAP, errata triage)
- LNX-304-T05 to T07 (snapshots, content views, patch rings)
- LNX-303-T08 (compliance as code)
- LNX-305-T07 (idempotence and check mode)

## Steps

1. Define the four actions as separate entry points with a precondition and a check each.
2. Order the decommission steps so nothing can authenticate or alert against a ghost host.
3. Patch in rings: canary first, then the rest, health check between them.
4. Treat IdM servers specially: check replicas before an upgrade or a removal.
5. Record one run of each action with timestamps.

## Acceptance

- The grader passes.
- After a decommission, the directory, CA, DNS, monitoring and inventory return nothing for the host name.
- A failed canary stops the ring.
