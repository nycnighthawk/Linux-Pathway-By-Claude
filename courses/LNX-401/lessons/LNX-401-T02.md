# Milestone 2: test against a genuine Windows AD with a trust

This milestone follows the topic synthesis `synth/LNX-401/LNX-401-T02.md`. Product versions and defaults change; confirm them in current vendor documents (to verify).

## Goal

Repeat the identity tests on a real Windows domain and record the evidence.

## Lessons this milestone relies on

- LNX-301-T04 and T05 (joining Samba AD and a genuine Windows AD)
- LNX-301-T07 and T08 (IdM to AD trust, ID mapping, sssctl)
- LNX-302-T02, T04, T05 and T10 (winbind versus SSSD, SMB with Kerberos, AD DNS and time, Linux in a real estate)
- LNX-204-T10 (TLS and openssl)

## Steps

1. Provide a Windows Server forest yourself (an evaluation licence on your own hardware is acceptable).
2. Prove name resolution and time first. Then join, then password login, then ticket login, then group access. Keep the Kerberos trace of one failure and one success.
3. Create the trust from IdM; test an AD user on an IdM host; check the ID ranges do not overlap.
4. Write each difference from Samba and what you changed in the code because of it.
5. Fill in the evidence file and run the structure check.

## Acceptance

- The evidence file passes the check.
- Your notes show the four steps as separate tests.
- At least one real difference is recorded with its fix.
