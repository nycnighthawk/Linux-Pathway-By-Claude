# Helm chart authoring and testing

This lesson follows the topic synthesis `synth/LNX-313/LNX-313-T06.md`, which carries the sources, the history and the failure cases.

## What you will be able to do

- Lay out a chart and write templates with helpers, `include`, `toYaml | nindent` and `required`.
- Keep the values surface small and enforce it with a JSON schema.
- Test a chart at four levels and release it as a signed, immutable artifact.

## Layout

```
mychart/
  Chart.yaml          apiVersion v2, name, version (chart, SemVer), appVersion (the app)
  values.yaml         documented defaults that work
  values.schema.json  validation at install, upgrade, lint, template
  templates/          _helpers.tpl, deployment.yaml, service.yaml, NOTES.txt, tests/
  crds/               installed once, never templated, never upgraded by Helm
```

## Idioms

- Named templates in `_helpers.tpl` for the full name, labels and selector labels; every object uses them.
- `{{- toYaml .Values.resources | nindent 12 }}` for subtrees, never hand-indented copies.
- `{{ required "image.repository is required" .Values.image.repository }}`.
- Omit `replicas` when the autoscaler is enabled, or each upgrade resets it.
- Selector labels never change after the first release; selectors are immutable.
- No random secrets generated on every render; no `latest` tags.

## Test pyramid

1. `helm lint` (structure, schema).
2. `helm template` plus a Kubernetes schema validator and policy checks.
3. Unit tests on rendered documents (does the Ingress exist only when enabled?).
4. `ct install` into a kind cluster: install, upgrade from the previous release, run `helm test`, uninstall.

## Release

`helm package`, bump the chart version on every change, push to an OCI registry, sign the artifact. Operations: `helm upgrade --install --atomic --wait`, `helm rollback`, a diff plugin before upgrades.

## Worked example: upgrade fails on a selector

A helper change altered a selector label. The Deployment selector is immutable, so the upgrade fails. Restore the selector labels and put the new label only in the Pod template labels.

## Self-check

1. What is the difference between `version` and `appVersion`?
2. Why are CRDs not templated?
3. What does the schema file add over comments in `values.yaml`?
4. Why omit `replicas` with autoscaling on?
5. Which test level finds an upgrade-path bug?
