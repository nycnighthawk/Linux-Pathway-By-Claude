# GitOps with Argo CD or Flux

This lesson follows the topic synthesis `synth/LNX-313/LNX-313-T07.md`, which carries the sources, the history and the failure cases.

## What you will be able to do

- State the four OpenGitOps principles and what each one removes from push pipelines.
- Write an Argo CD Application with safe automation and a Flux GitRepository plus Kustomization.
- Design a repository layout for promotion and a break-glass procedure.

## The four principles

1. Declarative description. 2. Versioned and immutable. 3. Pulled automatically. 4. Continuously reconciled.

## Two tools, two shapes

| | Argo CD | Flux |
|---|---|---|
| Model | server and UI around an `Application` | toolkit of controllers |
| Source | repo, path, revision in the Application | `GitRepository`, `OCIRepository`, `HelmRepository` |
| Apply | sync policy: automated, `prune`, `selfHeal` | `Kustomization` or `HelmRelease` with `interval`, `prune` |
| Order | sync waves, hooks | `dependsOn`, health checks |
| Fleet | `ApplicationSet` generators | per-tenant namespaces and service accounts |

## Decisions that matter

- Prune deletes live objects removed from Git; protect stateful objects.
- Self-heal reverts hand edits; define break-glass (suspend reconciliation for one app).
- Ignore fields owned by other controllers (replicas under an autoscaler).
- Secrets: encrypt in Git (SOPS), reference an external store, or keep outside Git.
- Separate the application repository from the configuration repository; promote by commits that change a tag in the next environment's directory.

## Worked example: nothing deploys

Git has the change, the cluster does not. The repository token expired and the source reports an authentication error. Alert on failed reconciliation older than a few minutes, not only on drift.
