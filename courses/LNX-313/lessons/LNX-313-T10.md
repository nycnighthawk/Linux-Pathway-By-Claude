# Inner loop: Tilt/Skaffold, devcontainers

This lesson follows the topic synthesis `synth/LNX-313/LNX-313-T10.md`, which carries the sources, the history and the failure cases.

## What you will be able to do

- Name the stages of the inner loop and where each tool shortens it.
- Write a Skaffold file and a Tiltfile with file sync, port forwarding and a test resource.
- Define a dev container that matches the CI toolchain.

## The loop

edit, build, deploy, look, repeat. Shorten it by caching layers (dependencies first, source last), syncing files into running containers (live update) for interpreted languages, forwarding ports and streaming logs, and keeping the cluster close (a local cluster that can load images without a registry push).

| Tool | Shape | Strength |
|---|---|---|
| Skaffold | declarative `skaffold.yaml`: build, test, deploy, portForward, profiles | same file in CI; many builders (Docker, Jib, buildpacks, ko) |
| Tilt | `Tiltfile` in Starlark plus a web UI | live update, many services, local resources |
| Telepresence, mirrord | intercept traffic to a local process | systems too big for a laptop |
| Dev containers | `devcontainer.json`: image, features, ports, extensions, lifecycle commands | one toolchain for developers and CI |

## Rules that keep it honest

Use the same manifests or chart as delivery (profiles or overlays for the differences). Leave probes, limits and security contexts on. Build the real image in CI so live update cannot hide missing files. Mount only the credentials a dev container needs; lifecycle commands run repository code.

## Worked example: works in sync, fails in the pipeline

Live update copied a new file into the container, but the Dockerfile never copies it. Add a CI step that builds the image and runs the same tests, and prefer layer order that makes real rebuilds fast.
