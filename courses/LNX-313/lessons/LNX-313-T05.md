# Jobs and CronJobs

This lesson follows the topic synthesis `synth/LNX-313/LNX-313-T05.md`, which carries the sources, the history and the failure cases.

## What you will be able to do

- Set completions, parallelism, back-off, deadline and clean-up for a Job.
- Write a CronJob schedule with an explicit time zone and the right concurrency policy.
- Make batch work safe under at-least-once semantics and alert on missing runs.

## Job fields

| Field | Meaning | Default |
|---|---|---|
| `completions`, `parallelism` | successes needed, Pods at once | 1, 1 |
| `backoffLimit` | failures tolerated | 6 |
| `activeDeadlineSeconds` | upper bound on run time | none |
| `ttlSecondsAfterFinished` | delete the Job and Pods later | none |
| `completionMode: Indexed` | stable index per Pod for partitioned work | NonIndexed |
| `podFailurePolicy` | act on exit codes or Pod conditions (ignore disruption, fail on a known permanent error) | none |

Template `restartPolicy` must be `Never` or `OnFailure`.

## CronJob fields

`schedule` (five fields: minute, hour, day of month, month, weekday; when both day fields are restricted either may match), `timeZone`, `concurrencyPolicy` (Allow, Forbid, Replace), `startingDeadlineSeconds`, `successfulJobsHistoryLimit` (3) and `failedJobsHistoryLimit` (1), `suspend`.

## Guarantees

At least once in practice: a run may rarely be duplicated or missed. Tasks need idempotent output (names from the scheduled date, locks or leases). Alert on the age of the last success, not only on failure.

## Worked example: nothing has run for days

Events say too many start times were missed after a control-plane outage. Set `startingDeadlineSeconds` to bound the catch-up window and alert on the last success.
