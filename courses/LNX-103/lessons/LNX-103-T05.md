# Software RAID with mdadm

This lesson follows the topic synthesis `synth/LNX-103/LNX-103-T05.md`, which carries the sources and the history.

## What you will be able to do

- Pick a RAID level for a workload and state how many failures it survives.
- Create, describe, monitor and repair an md array with `mdadm`.
- Read `/proc/mdstat` and `mdadm --detail` in an incident.

## Levels

| Level | Min. devices | Usable | Survives |
|---|---|---|---|
| RAID 0 | 2 | all | nothing |
| RAID 1 | 2 | one device | all but one |
| RAID 5 | 3 | N-1 | one |
| RAID 6 | 4 | N-2 | two |
| RAID 10 | 4 | about half | one per mirror pair, at least |

RAID is availability, not backup: a deletion or corruption is copied faithfully to every member.

## Create and inspect

```bash
mdadm --create /dev/md0 --level=5 --raid-devices=3 --bitmap=internal /dev/sd[abc]1
cat /proc/mdstat           # [3/3] [UUU]; an underscore marks a missing member: [UU_]
mdadm --detail /dev/md0    # State, Raid Level, UUID, member states (active sync, faulty, removed)
```

The array is usable at once; redundancy appears when the first sync ends. Members carry a superblock (version 1.2 by
default, 4 KiB from the start), so arrays assemble from the members alone. A write-intent bitmap limits a resync after a
crash to dirty regions.

## Make it persistent and watched

```
# /etc/mdadm.conf  (Debian: /etc/mdadm/mdadm.conf)
DEVICE partitions
MAILADDR root
ARRAY /dev/md0 metadata=1.2 name=host:0 UUID=3c1f9d06:0b6a7e2d:8a24f6b5:11c9d7aa
```

Generate ARRAY lines with `mdadm --detail --scan`, review them, rebuild the initramfs (`dracut -f` or
`update-initramfs -u`). Run `mdmonitor.service`, and test the mail path with
`mdadm --monitor --scan --oneshot --test`. Scrub with `echo check > /sys/block/md0/md/sync_action` and read
`mismatch_cnt`.

## Replacing a failed member

```bash
mdadm /dev/md0 --fail /dev/sdc1
mdadm /dev/md0 --remove /dev/sdc1
sfdisk -d /dev/sda | sfdisk /dev/sdd          # same layout as a healthy disk
mdadm /dev/md0 --add /dev/sdd1                # rebuild starts automatically
watch cat /proc/mdstat
```

Check serial numbers before pulling a disk (`lsblk -o NAME,SERIAL`). `--replace ... --with ...` rebuilds onto a new disk
while the old one stays in service. Grow with `mdadm --grow` (`--raid-devices=N`, `--size=max`), then grow the layers above.
Remove an array: unmount, `mdadm --stop`, `mdadm --zero-superblock` on every member, delete the ARRAY line.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Array runs degraded for months | alerts never arrive | `mdadm --monitor --oneshot --test` |
| Array appears as `/dev/md127` | name does not match the host | `name=` in ARRAY, `mdadm.conf` |
| Second disk fails during rebuild | long rebuild, same-batch disks | use RAID 6, replace early |
| Wrong disks erased by `--create` | device letters changed | `lsblk -o NAME,SERIAL` first |
