# NFS and SMB clients, autofs

This lesson follows the topic synthesis `synth/LNX-103/LNX-103-T07.md`, which carries the sources and the history.

## What you will be able to do

- Mount NFS and SMB shares with sensible options and make them persistent without blocking boot.
- Write an NFS `exports` file and read the effective options.
- Configure autofs with a wildcard map, or use `x-systemd.automount` instead.

## NFS

Server: `/etc/exports`, one line per export, `exportfs -ra` to apply, `exportfs -v` to show.

```
/srv/export/projects  192.168.10.0/24(rw,sync,no_subtree_check,root_squash)
/srv/export/docs      *.example.com(ro,sync,no_subtree_check)
```

`root_squash` (default) maps client root to the anonymous user; `no_root_squash` does not. NFSv4 uses one TCP port,
2049, and a pseudo-root.

Client:

```bash
mount -t nfs4 files.example.com:/export/home /mnt/home -o rw,sec=sys,nosuid,nodev
nfsstat -m                          # effective options
```

| Option | Meaning |
|---|---|
| `vers=4.2` | protocol version |
| `hard` (default) / `soft` | retry forever / give up after `retrans` tries (risks silent write loss) |
| `timeo=`, `retrans=` | request timeout (tenths of a second) and retry count |
| `sec=sys\|krb5\|krb5i\|krb5p` | security flavour; `krb5p` also encrypts |
| `nconnect=N` | several TCP connections to one server |
| `actimeo=`, `noac`, `cto` | attribute cache and close-to-open consistency |
| `_netdev`, `nofail`, `x-systemd.automount` | network order, boot safety, mount on first access |

## SMB

```bash
mount -t cifs //files.example.com/team /mnt/team \
  -o credentials=/root/.smbcred,uid=1000,gid=1000,vers=3.1.1,seal,_netdev,nofail
```

`/root/.smbcred` (mode 0600) holds `username=`, `password=`, `domain=`. Never put the password on the command line.
Use `vers=3.1.1` or `3.0`; avoid SMB1. `uid=`, `gid=`, `file_mode=`, `dir_mode=` decide how Windows files appear.

## autofs

```
# /etc/auto.master.d/home.autofs  (or /etc/auto.master)
/home  /etc/auto.home  --timeout=600
# /etc/auto.home
*  -fstype=nfs4,rw,sec=sys,nosuid  files.example.com:/export/home/&
```

The key `*` matches any name and `&` repeats it, so one line serves every user. Map line format: **key
[-options] location**; direct maps use the `/-` mount point; `-fstype=cifs` needs the location written `://server/share`.
Enable with `systemctl enable --now autofs`, reload after edits, debug with `automount -f -v`. `x-systemd.automount` in
fstab gives on-demand mounts for a few fixed shares without another daemon.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Files owned by `nobody` | NFSv4 idmap domain mismatch | `/etc/idmapd.conf`, `nfsidmap` |
| Processes stuck on a dead server | hard mount, server gone | `umount -f -l`, `nfsstat -c` |
| Boot delayed by a share | no `nofail`/automount | fstab options |
| Wildcard map mounts nothing | `autofs` not reloaded | `systemctl reload autofs`, `automount -m` |
