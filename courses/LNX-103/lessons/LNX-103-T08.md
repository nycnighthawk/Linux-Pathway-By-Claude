# iSCSI target and initiator

This lesson follows the topic synthesis `synth/LNX-103/LNX-103-T08.md`, which carries the sources and the history.

## What you will be able to do

- Explain target, initiator, IQN, LUN, portal, ACL and session.
- Publish a logical volume with `targetcli` and log in with `iscsiadm`.
- Mount an iSCSI disk safely at boot and avoid two-writer corruption.

## Names and pieces

An IQN looks like `iqn.2025-06.lab.example:san.lun1`. A **target** exposes LUNs through one or more **portals** (IP and
TCP port 3260); an **initiator** discovers and logs in. A **backstore** supplies the data: `block`, `fileio`, `ramdisk`.

## Target (LIO, targetcli)

```
targetcli
/> backstores/block create name=lun1 dev=/dev/vg0/lun1
/> iscsi/ create iqn.2025-06.lab.example:san.lun1
/> iscsi/iqn.2025-06.lab.example:san.lun1/tpg1/luns create /backstores/block/lun1
/> iscsi/iqn.2025-06.lab.example:san.lun1/tpg1/acls create iqn.2025-06.lab.example:compute1
/> iscsi/iqn.2025-06.lab.example:san.lun1/tpg1/portals create 192.0.2.10 3260
/> saveconfig
```

Order matters: backstore and target first, then LUN, ACL and portal. `systemctl enable --now target` restores the saved
configuration at boot (`/etc/target/saveconfig.json`); open TCP 3260 in the firewall.

## Initiator (Open-iSCSI)

```bash
systemctl enable --now iscsid iscsi
cat /etc/iscsi/initiatorname.iscsi          # InitiatorName=... must match the target ACL
iscsiadm -m discovery -t sendtargets -p 192.0.2.10
iscsiadm -m node -T iqn.2025-06.lab.example:san.lun1 -p 192.0.2.10 --login
iscsiadm -m session -P 3
iscsiadm -m node -T <iqn> -p 192.0.2.10 -o update -n node.startup -v automatic
```

`/etc/iscsi/iscsid.conf` sets defaults: `node.startup = automatic`, `node.session.timeo.replacement_timeout` (default
120 s; lower it with multipath), CHAP (`node.session.auth.authmethod = CHAP`, `.username`, `.password`; keep the file
mode 0600). Use stable names: `/dev/disk/by-path/ip-...-iscsi-<iqn>-lun-0` or `by-id`, never `sdX`.

```
UUID=0c1d4a02-...  /srv/san  xfs  defaults,_netdev,nofail  0 0
```

## Safety rules

- One writer per LUN unless a cluster file system and fencing sit on top.
- Name devices by WWID or path; mount with `_netdev,nofail`.
- Treat the initiator name, ACL and CHAP secret as access control; iSCSI itself is not encrypted.
- Remove cleanly: unmount, `--logout`, `-o delete`; on the target `iscsi/ delete <iqn>`, `saveconfig`.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Login refused | initiator name not in the ACL | `initiatorname.iscsi` vs `acls` |
| Login ok, no disk | LUN not mapped to the ACL | `targetcli ls` |
| I/O freezes for two minutes | session lost, long timeout | `replacement_timeout`, multipath |
| Corrupted file system | two hosts mounted one LUN | cluster file system, fencing |
