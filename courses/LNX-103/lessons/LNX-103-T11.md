# Hardware RAID, Fibre Channel SAN and multipath

## What you will be able to do

- Read how a host sees an FC LUN through `/sys/class/fc_host` and the SCSI layer.
- Configure device-mapper multipath for several paths to one LUN.

## Hardware RAID and HBAs

A RAID controller presents a virtual disk and hides the members. Weigh the write cache (battery or flash backed or you
risk loss), vendor tools for monitoring, and controller lock-in: arrays are often unreadable on a different model. An
HBA in pass-through (JBOD) mode hands raw disks to Linux, where `mdadm`, ZFS or Btrfs manage redundancy.

## Fibre Channel in one page

Hosts reach a SAN through an HBA with a WWPN; the fabric zones restrict which ports see each other, and the array maps
LUNs to host WWPNs (LUN masking). Linux shows adapters in `/sys/class/fc_host/` and disks as ordinary SCSI devices
`sdX`. One LUN reached over two fabrics appears twice.

```bash
ls /sys/class/fc_host/
cat /sys/class/fc_host/host*/port_name       # the WWPN
lsscsi
echo "- - -" > /sys/class/scsi_host/host0/scan   # rescan, no reboot
```

## Multipath

`device-mapper-multipath` joins the `sdX` paths with the same WWID into one `/dev/mapper/mpathX` device.

```
defaults {
    user_friendly_names yes
    find_multipaths     yes
}
blacklist {
    wwid "3600508b1001c..."
}
multipaths {
    multipath {
        wwid  360000000000000000e00000000010001
        alias oradata
    }
}
```

```bash
systemctl enable --now multipathd
multipath -ll          # topology, path groups, path states
multipath -v2          # (re)create maps
```

The path policy (`path_grouping_policy`, `path_selector`, `failback`) and `no_path_retry` come from the array vendor's
recommendation. Use the mapper device in fstab, LVM and applications, never the individual `sdX`.

## Troubleshooting order

1. Is the link up and the WWPN visible (`fc_host`)? 2. Does the array show the LUN to this WWPN? 3. Did you rescan?
4. Is the disk in the blacklist? 5. Do `multipath -ll` states show `active ready`?

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| LUN seen twice | multipath not running or blacklisted | `multipath -ll`, `blacklist` |
| New LUN missing | no rescan or masking | `scan` file, array mapping |
| All paths fail, I/O hangs | `no_path_retry queue` | vendor guidance |
| Array unreadable after controller swap | hardware RAID metadata | controller model, export config |
