## What you will be able to do

- Limit space per user, group or project and read the reports.
- Grant extra users and groups access with POSIX ACLs, including inheritance, and explain the mask.
- Store, read and preserve extended attributes.

## Quotas

Each identity gets a **soft** limit (may be passed during a grace period) and a **hard** limit (never passed), for blocks
and inodes. Exceeding the hard limit gives `Disk quota exceeded`.

```bash
# ext4, native quota
tune2fs -O quota -Q usrquota,grpquota /dev/vg0/data       # shows as "User quota inode" in dumpe2fs -h
# fstab: ... ext4  defaults,usrquota,grpquota  0  2
setquota -u alice 900000 1000000 0 0 /srv/data            # block soft, block hard (KiB), inode soft, hard
edquota -t                                                # grace periods
quota -u alice;  repquota -s /srv/data
# XFS: choose at mount time (uquota, gquota, pquota); remount cannot enable them
xfs_quota -x -c 'limit bsoft=800m bhard=1g alice' /srv/data
xfs_quota -x -c 'report -h' /srv/data
```

XFS project quotas limit a directory tree whatever the owner: `/etc/projects` maps an ID to the tree, `/etc/projid`
names it, `xfs_quota -x -c 'limit -p bhard=20g web' /srv/data` sets the cap. Btrfs uses qgroups
(`btrfs qgroup limit`).

## POSIX ACLs

```bash
getfacl report.txt
setfacl -m u:alice:rw,g:auditors:r report.txt
setfacl -x u:alice report.txt            # remove one entry;  -b removes all
setfacl -R -m g:dev:rwX /srv/project     # X: execute only for directories or already-executable files
setfacl -d -m g:dev:rwX /srv/project     # default ACL: inherited by new children
getfacl -R /srv/project > acl.backup;  setfacl --restore=acl.backup
```

Entries: `user::` (owner), `user:name:`, `group::`, `group:name:`, `mask::`, `other::`, and `default:` forms. The **mask**
caps every entry except owner and other; `getfacl` marks reduced entries `#effective:`. `chmod g=...` on a file with an
ACL changes the **mask**. With a default ACL, the `umask` is not applied to new files. `ls -l` shows a `+` after the
mode.

## Extended attributes

```bash
setfattr -n user.classification -v internal report.txt
getfattr -d report.txt
getfattr -d -m - report.txt              # all namespaces you may read
setfattr -x user.classification report.txt
```

Namespaces: `user` (file permissions apply; regular files and directories only), `trusted` (needs `CAP_SYS_ADMIN`),
`security` (SELinux `security.selinux`, file capabilities `security.capability`), `system` (ACLs live here).
`chattr`/`lsattr` flags are a different thing.

## Keeping them in copies

`rsync -aAX`, `tar --xattrs --acls --selinux`, `cp -a` preserve them; plain `cp`, `tar` and many backup tools do not.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Named user cannot write although ACL says rw | mask is lower | `getfacl`, `#effective:` |
| New files lack the ACL | only an access ACL was set | `setfacl -d` |
| XFS quota not enforced | mount option missing | `xfs_quota -x -c state`, `mount` |
| Restore lost labels and ACLs | copy tool dropped them | `rsync -aAX`, `tar --acls --xattrs` |
