# Backup and restore: rsync, restic and borg

This lesson follows the topic synthesis `synth/LNX-103/LNX-103-T10.md`, which carries the sources and the history.

## What you will be able to do

- Plan a backup with the 3-2-1 rule, a retention policy and restore tests.
- Make hard-link snapshots with `rsync --link-dest`.
- Use a deduplicating, encrypted repository with restic (and know how borg compares).

## Plan first

Three copies of the data, on two kinds of media, one off site (the **3-2-1 rule**). A backup you have never restored is a
hope, not a backup: schedule restore tests and a `check`. Decide RPO (how much data you may lose) and RTO (how long a
restore may take), then the retention.

## rsync snapshots

```bash
rsync -aH --delete data/ /backup/day1/                       # archive, keep hard links
rsync -aH --delete --link-dest=/backup/day1 data/ /backup/day2/
rsync -aHn --delete data/ /backup/day2/                      # -n: dry run, shows what would change
```

`-a` keeps permissions, owners, times, symlinks and devices; `-H` keeps hard links; `-A -X` adds ACLs and xattrs.
`--link-dest` hard-links files that did not change, so each day looks like a full copy but costs only the changes.
A trailing slash on the source means "the contents of".

## restic

```bash
restic init --repo repo --password-file restic.pass
restic backup --repo repo --password-file restic.pass data
restic snapshots --repo repo --password-file restic.pass
restic check --repo repo --password-file restic.pass
restic restore latest --repo repo --password-file restic.pass --target restore
restic forget --keep-daily 7 --keep-weekly 4 --prune --repo repo --password-file restic.pass
```

The repository is encrypted and deduplicated by content-defined chunks. `forget` only removes snapshots; `--prune`
deletes data no snapshot references any more. Lose the password and the repository is unreadable.

## borg in short

BorgBackup is a similar deduplicating, encrypted tool with `borg init`, `borg create repo::name path`, `borg list`,
`borg extract`, `borg prune` and `borg compact`. It needs an SSH-reachable borg on the server side; restic talks to
object stores directly. This course lab uses rsync and restic only.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Backup is as big as the source every day | no `--link-dest` or wrong path | absolute path, `ls -li` |
| Restore misses ACLs or xattrs | rsync without `-A -X` | options used |
| Repository grows forever | no `forget --prune` | retention policy |
| Backup "succeeds" but cannot restore | never tested | scheduled `restore` and `check` |
