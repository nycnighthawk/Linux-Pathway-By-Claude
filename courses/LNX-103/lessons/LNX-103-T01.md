## Two label types

| | MBR (DOS) | GPT |
|---|---|---|
| Location | sector 0 | protective MBR in sector 0, header in LBA 1, backup header at the end |
| Entries | 4 primary, or 3 plus an extended partition holding logical ones | 128 by default, each 128 bytes |
| Size limit | 2 TiB (2^32 sectors of 512 bytes) | 8 ZiB (512-byte sectors) |
| Type | one byte (`83` Linux, `82` swap, `8e` LVM, `fd` RAID, `ef` ESP) | a GUID (Linux filesystem `0FC63DAF-...`, ESP `C12A7328-...`) |
| Safety | no copy, no checksum | two copies with checksums, signature `EFI PART` |
| Extras | active flag for BIOS boot | unique partition GUID (`PARTUUID`), 36-character name (`PARTLABEL`) |

A GPT disk still has an MBR in sector 0 with one entry of type `ee` covering the disk, so old tools do not mistake the
disk for empty. A BIOS machine that boots from GPT needs a small **BIOS boot** partition for GRUB; a UEFI machine needs
an **EFI System Partition** (FAT).

## Looking and listing

```bash
lsblk -o NAME,SIZE,TYPE,PTTYPE,PARTUUID,PARTLABEL /dev/sdb
sfdisk -l /dev/sdb          # table
sfdisk -d /dev/sdb          # dump as a script
sfdisk -F /dev/sdb          # free areas
blkid /dev/sdb1             # file-system signature, UUID
```

## Writing a table with sfdisk

`sfdisk` reads a script on standard input. Omit `start` and the next aligned sector is used; omit `size` and the rest of
the disk is used.

```bash
sfdisk /dev/sdb <<'EOF'
label: gpt
start=2048, size=512MiB, type=U, name="esp"
size=8GiB, type=S, name="swap"
type=L, name="data"
EOF
sfdisk -V /dev/sdb                       # verify
sfdisk -d /dev/sdb > sdb.layout          # save; replay with: sfdisk /dev/sdc < sdb.layout
```

Aliases for `type=`: `L` Linux, `S` swap, `U` EFI system, `V` LVM, `R` RAID. Useful switches: `-n` (rehearse, change
nothing), `-a` (append), `-N n` (change one entry), `--delete`, `-J` (JSON). Interactive tools are `fdisk` (buffers until
`w`), `gdisk` and `parted` (writes at once; careful).

## Telling the kernel and growing

After a change on a disk in use, `partx -u /dev/sdb` or `partprobe /dev/sdb` makes the kernel re-read it, and
`udevadm settle` waits for device nodes. To grow the last partition after enlarging the disk: `sgdisk -e` (move the
backup header to the new end), `sfdisk -N 3 --no-reread /dev/sdb <<< ',+'`, then `partx -u`, then grow whatever is
inside it, **bottom up**: partition, then volume or file system.

Start partitions at 1 MiB (sector 2048): it suits 4 KiB sectors, RAID stripes and flash. Use `PARTUUID` or file-system
`UUID` in fstab, not `/dev/sdb1`, because letters change.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| New partition not visible | kernel not told | `partx -u`, `udevadm settle` |
| "device busy" on re-read | a partition is mounted | `findmnt`, unmount or reboot |
| Cloned disk, backup header misplaced | disk was bigger than source | `sgdisk -e` |
| Two disks, same GUIDs | cloned disk | `sfdisk --disk-id`, `sgdisk -G` |
| Wrote to the wrong disk | device letters changed | `lsblk -o NAME,SERIAL` before writing |
