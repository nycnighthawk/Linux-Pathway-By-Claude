# Disk encryption with LUKS2

This lesson follows the topic synthesis `synth/LNX-103/LNX-103-T09.md`, which carries the sources and the history.

## What you will be able to do

- Explain what LUKS adds to dm-crypt: a header, key slots and a master key.
- Format, open, extend and close a LUKS2 container with `cryptsetup`.
- Back up the header and configure unlock at boot with `/etc/crypttab`.

## The model

A LUKS2 container starts with a header (16 MiB by default) that stores metadata, up to 32 key slots and tokens. Each
slot holds the **master key** encrypted by a key derived from one passphrase or key file. The data area is encrypted
with the master key, by default `aes-xts-plain64`. Changing a passphrase only rewrites a slot; the data is not
re-encrypted. Losing every slot, or the header, means losing the data.

## Everyday commands

```bash
cryptsetup luksFormat --type luks2 --label VAULT /dev/vg0/secure
cryptsetup open /dev/vg0/secure secure          # creates /dev/mapper/secure
mkfs.xfs /dev/mapper/secure
cryptsetup luksAddKey /dev/vg0/secure keyfile   # second slot, authorise with an existing key
cryptsetup luksDump /dev/vg0/secure             # version, UUID, slots, tokens, PBKDF
cryptsetup open --test-passphrase --key-file keyfile /dev/vg0/secure
cryptsetup luksHeaderBackup /dev/vg0/secure --header-backup-file secure.hdr
cryptsetup close secure
```

Key derivation uses `argon2id` by default, which is deliberately slow and memory hungry. `--pbkdf pbkdf2` is faster and
weaker; use it only for tests.

## Unlock at boot

```
# /etc/crypttab: name  device  key  options
secure  UUID=3f1c...-luks-uuid  none  luks,discard
```

`none` asks for a passphrase at boot. Use the UUID of the **LUKS container** (`blkid`), not of the file system inside.
Then `/etc/fstab` mounts `/dev/mapper/secure` or the file system UUID. Rebuild the initramfs when the root file system
is encrypted (`dracut -f` or `update-initramfs -u`).

## Safety rules

- Back up the header, and keep the copy off the encrypted disk; it is as sensitive as a key slot.
- Keep at least two key slots, one of them a recovery key stored offline.
- `luksErase` and re-formatting destroy access; `cryptsetup luksKillSlot` needs another working key.
- Encryption protects data at rest, not a running, unlocked system.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| "No key available with this passphrase" | wrong key file, layout or slot removed | `luksDump`, `--test-passphrase` |
| Boot waits for a device | crypttab UUID is the file system UUID | `blkid` TYPE=crypto_LUKS |
| Cannot open after disk damage | header overwritten | restore with `luksHeaderRestore` |
| Slow unlock | memory-hard PBKDF on a small machine | `luksDump` PBKDF memory and time |
