# ext4, XFS and Btrfs; fstab and mount units

This lesson follows the topic synthesis `synth/LNX-103/LNX-103-T02.md`, which carries the sources and the history.

## What you will be able to do

- Create ext4, XFS and Btrfs file systems and read their metadata.
- Mount persistently with `/etc/fstab` or a `.mount` unit, and prove it without rebooting.
- Choose the right type for a job and know what each can and cannot do online.

## Choosing and creating

| | ext4 | XFS | Btrfs |
|---|---|---|---|
| Grow online | `resize2fs` | `xfs_growfs <mount point>` | `btrfs filesystem resize` |
| Shrink | offline only | **not possible** | online |
| Snapshots | no | no | per subvolume |
| Check and repair | `e2fsck` | `xfs_repair` (unmounted) | `btrfs scrub`, `btrfs check` |
| Label | `tune2fs -L`, `e2label` | `xfs_admin -L` | `btrfs filesystem label` |

```bash
mkfs.ext4 -L data -m 1 /dev/vg0/data        # -m: percent reserved for root
mkfs.xfs -L logs /dev/vg0/logs              # -f overwrites a signature
mkfs.btrfs -L pool -d single -m dup /dev/vdb
dumpe2fs -h dev | grep -E 'features|Block size'     # ext4 superblock
xfs_info /srv/logs                          # XFS geometry: isize, agcount, bsize, crc, reflink
```

ext4 defaults (current e2fsprogs): `has_journal, extent, huge_file, flex_bg, metadata_csum, 64bit, dir_nlink,
extra_isize`. Journal modes: `data=ordered` (default), `writeback`, `journal`. `blkid` prints the UUID you will use
in fstab.

## fstab: six fields

```
UUID=0c1d4a02-...  /srv/data  ext4  noatime,nodev,nofail  0  2
```

1. device (`UUID=`, `LABEL=`, `PARTUUID=`, a `/dev/mapper/` path, or `host:/path`);
2. mount point; 3. type; 4. options (`defaults` = `rw,suid,dev,exec,auto,nouser,async`);
5. dump (0 or 1); 6. pass: boot-time check order (1 root, 2 others, 0 none; use 0 for XFS and Btrfs).

Common options: `noatime`, `relatime` (default), `nosuid`, `nodev`, `noexec`, `nofail`, `x-systemd.automount`,
`x-systemd.device-timeout=`, `_netdev`, `ro`, `discard` (prefer `fstrim.timer`), `usrquota`/`grpquota`, `subvol=`,
`compress=zstd`.

## Mount units

`systemd-fstab-generator` turns each fstab line into a unit named after the path:
`systemd-escape -p --suffix=mount /srv/data` prints `srv-data.mount`. Written by hand:

```ini
[Mount]
What=/dev/disk/by-uuid/0c1d4a02-...
Where=/srv/data
Type=ext4
Options=noatime,nodev
[Install]
WantedBy=local-fs.target
```

A failed mount without `nofail` makes `local-fs.target` fail and the boot drops to emergency mode. After editing fstab
run `systemctl daemon-reload`.

## Prove it before you reboot

```bash
findmnt --verify            # syntax and unknown devices
mount -a                    # mounts every line not yet mounted
findmnt /srv/data -o TARGET,SOURCE,FSTYPE,OPTIONS
```

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Boot stops in emergency mode | bad fstab line, missing device | `journalctl -xb`, `nofail` |
| Cannot shrink an XFS volume | XFS cannot shrink | back up, recreate smaller, restore |
| `df` and `btrfs filesystem usage` disagree | chunk allocation | `btrfs filesystem usage`, `balance` |
| Mounts fine, access denied (RHEL) | SELinux labels | `restorecon -R`, `ls -Z` |
