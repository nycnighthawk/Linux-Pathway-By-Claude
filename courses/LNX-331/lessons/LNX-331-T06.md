# Page allocator, slab, vmalloc, DMA API

This lesson follows the topic synthesis `synth/LNX-331/LNX-331-T06.md`. Allocator internals change; check `Documentation/core-api/memory-allocation.rst` (to verify).

## What you will be able to do

- Pick the right allocator for a size, context and lifetime.
- Choose GFP flags legally for the context.
- Use the DMA API correctly, coherent and streaming.
- Read `/proc/buddyinfo` and `/proc/slabinfo`.

## Which allocator

| Need | Use |
|---|---|
| small object, physically contiguous | `kmalloc` / `kzalloc` / `kmalloc_array` |
| many objects of one type | `kmem_cache_create` |
| big array, size from user input | `kvmalloc` |
| big, virtually contiguous only | `vmalloc` |
| whole pages | `alloc_pages(gfp, order)` |
| memory a device will read or write | the DMA API |
| device registers | `ioremap`, or `pcim_iomap` |

`kmalloc_array(n, size, gfp)` checks `n * size` for overflow. `kfree(NULL)` is fine. `devm_kzalloc` ties the memory to a device.

## GFP flags

| Flag | Meaning |
|---|---|
| `GFP_KERNEL` | may sleep and reclaim; process context, no spinlock held |
| `GFP_ATOMIC` | never sleeps, may use reserves, fails more often |
| `GFP_NOWAIT` | no sleep, no reserves |
| `__GFP_ZERO` | zero the memory |
| `__GFP_ACCOUNT` | charge to the memory cgroup |

In I/O paths prefer scoped `memalloc_noio_save()` and `memalloc_nofs_save()`. Always handle a NULL return.

## DMA API

```c
dma_set_mask_and_coherent(&pdev->dev, DMA_BIT_MASK(32));
ring = dma_alloc_coherent(&pdev->dev, SZ, &ring_dma, GFP_KERNEL);   /* long-lived */

addr = dma_map_single(&pdev->dev, buf, len, DMA_TO_DEVICE);        /* per I/O */
if (dma_mapping_error(&pdev->dev, addr)) return -ENOMEM;
/* device owns buf now; CPU must not touch it */
dma_unmap_single(&pdev->dev, addr, len, DMA_TO_DEVICE);
```

Give the device the **bus address**, never `virt_to_phys`. Not for stack or plain vmalloc memory. Match the direction.

## Looking

```
cat /proc/buddyinfo     # free blocks per order, per zone
slabtop                 # object caches
```

Free memory in low orders only means large contiguous requests will fail. Debug with `slub_debug`, KASAN, `kmemleak`, and fault injection (`failslab`, `fail_page_alloc`).
