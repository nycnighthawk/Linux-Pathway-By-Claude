## The machine

Registers `r0` (return value) to `r10` (read-only frame pointer), a 512-byte stack, 64-bit arithmetic, calls to helpers and kfuncs. `r1` to `r5` are arguments and are clobbered by a call; `r6` to `r9` survive calls. Programs load through `bpf(BPF_PROG_LOAD)` with a type, a licence and optional BTF.

## What the verifier proves

| Check | Example rejection |
|---|---|
| every path ends in exit | falls off the end |
| no uninitialised reads | using `r2` after a call |
| bounded execution | a backward jump it cannot bound |
| memory safety | `map_value + 12` for an 8-byte read of a 16-byte value |
| NULL checks | using a map lookup result before testing it |
| no pointer leaks | returning a context pointer |
| paired acquire and release | a reference never released |

Complexity limits matter: a program with too many paths is rejected even if safe. The load log shows register states.

## Tools

```
bpftool prog show ; bpftool prog dump xlated id 12 ; bpftool map dump id 3
bpftool btf dump file /sys/kernel/btf/vmlinux format c | head
clang -O2 -g -target bpf -c prog.bpf.c -o prog.bpf.o
```

CO-RE and BTF let one object run on several kernels.

## sched_ext

A scheduler is a BPF `struct_ops` filling `sched_ext_ops`:

| Callback | When |
|---|---|
| `select_cpu` | a task wakes; choose a CPU, maybe dispatch at once |
| `enqueue` | a task becomes runnable; insert into a dispatch queue |
| `dispatch` | a CPU needs work; move tasks to its local queue |
| `running`, `stopping` | accounting |
| `init`, `exit` | create queues, report why it ended |

Dispatch queues: per-CPU local, global, and custom queues. If the scheduler stalls a runnable task past the timeout, the kernel ejects it and returns to the default scheduler, so a bad policy degrades but does not hang the machine.

## Security

Loading needs `CAP_BPF` and friends; unprivileged BPF is usually disabled. The verifier is part of the trusted base, so it is fuzzed heavily.

## Self-check

Try each question before you read the answers below.

1. Why does the verifier reject a program that reads `r2` right after a helper call?
2. A program uses a map lookup result without testing it. What fix makes it load?
3. What happens if a sched_ext scheduler leaves a runnable task waiting too long?

### Answers

1. Calls clobber `r1` to `r5`, so `r2` holds no initialised value afterwards.
2. Check the pointer for NULL before dereferencing it.
3. The kernel ejects the BPF scheduler and returns tasks to the default scheduler.
