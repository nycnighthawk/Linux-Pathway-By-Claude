# Bring-up on a real board

This lesson follows the topic synthesis `synth/LNX-331/LNX-331-T12.md`. Board details come from your hardware manual; U-Boot commands vary by version (to verify).

## What you will be able to do

- Connect a serial console safely and capture a boot from power-on.
- Describe the boot chain from ROM to userspace and locate a failure in it.
- Boot a kernel and DTB over the network from U-Boot.
- Debug an early or silent boot using `earlycon` and the device tree.

## The boot chain

```
boot ROM -> SPL/first stage (DRAM init) -> U-Boot (or barebox, UEFI) -> kernel + DTB + initramfs -> init
```

The ROM chooses the boot source from pins or fuses and may demand a header on the image.

## Console first

- 3.3 V USB-serial adapter unless the manual says otherwise; check the level **before** connecting.
- Ground, then TX to RX and RX to TX. Usually 115200 8N1.
- Capture from power-on: `picocom -b 115200 /dev/ttyUSB0 | tee boot.log`.

## Fast iteration

```
=> setenv ipaddr 192.168.1.50 ; setenv serverip 192.168.1.10
=> tftpboot ${kernel_addr_r} Image
=> tftpboot ${fdt_addr_r} board.dtb
=> setenv bootargs console=ttyS0,115200 earlycon root=/dev/nfs nfsroot=192.168.1.10:/srv/nfs,v3,tcp ip=dhcp
=> booti ${kernel_addr_r} - ${fdt_addr_r}
```

`fdt addr ${fdt_addr_r}` then `fdt print /chosen` inspect the blob. Use `bootz` on 32-bit Arm.

## Where did it stop?

| Last output | Suspect |
|---|---|
| nothing, low current | boot source, image format, power |
| SPL banner then hang | DRAM init, clocks |
| U-Boot prompt, kernel will not start | load addresses, image format |
| `Starting kernel` then silence | DTB, `earlycon`, console device |
| kernel runs, devices missing | deferred probes, regulators, clocks, pinmux |

## Kernel-side tools

```
cat /sys/kernel/debug/devices_deferred
cat /sys/kernel/debug/clk/clk_summary
ls /sys/kernel/debug/pinctrl/
dmesg | grep -iE 'defer|fail|error'
```

## The device tree for a board

`#include` the SoC dtsi, then add memory, `chosen/stdout-path`, enabled peripherals, regulators, pin groups, GPIOs, PHY settings. Validate with `make dtbs_check`.

## Safety

Unpowered when wiring probes. Level-check serial lines. Current-limited supply for prototypes. Keep a recovery boot path.

## Self-check

Try each question before you read the answers below.

1. The board prints the SPL banner and then nothing. What is the first suspect?
2. Why check the voltage level before connecting a serial adapter?
3. Which U-Boot command boots an arm64 `Image` with a separate device tree?

### Answers

1. DRAM initialisation or clocks in the first stage, before U-Boot proper loads.
2. A 5 V adapter on a 1.8 V or 3.3 V UART can damage the SoC.
3. `booti ${kernel_addr_r} - ${fdt_addr_r}`; the dash means no initramfs.
