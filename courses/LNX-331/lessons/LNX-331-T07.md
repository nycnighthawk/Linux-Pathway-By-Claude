# VFS: write a simple filesystem

This lesson follows the topic synthesis `synth/LNX-331/LNX-331-T07.md`. VFS interfaces change often (folios, the new mount API); read `Documentation/filesystems/vfs.rst` for your version (to verify).

## What you will be able to do

- Name the four VFS objects and what each holds.
- List the minimum operations of a read-only filesystem.
- Trace `ls` and `cat` through the VFS into a driver.
- Choose between a kernel filesystem, FUSE and an overlay.

## The objects

| Object | One per | Key operations table |
|---|---|---|
| `super_block` | mounted instance | `super_operations` |
| `inode` | file or directory | `inode_operations`, `file_operations`, `address_space_operations` |
| `dentry` | name in a directory (or negative) | `dentry_operations` |
| `file` | open file description | `file_operations` |

Caches: dcache (names), icache (inodes), page cache (file data).

## Registering

```c
static struct file_system_type tfs_type = {
	.owner = THIS_MODULE,
	.name = "tinyfs",
	.init_fs_context = tfs_init_fs_context,
	.kill_sb = kill_block_super,
	.fs_flags = FS_REQUIRES_DEV,
};
/* module init: register_filesystem(&tfs_type); */
```

`fill_super`: read and validate the on-disk superblock, set `s_magic`, `s_blocksize`, `s_op`, build the root inode, `d_make_root`.

## Minimum for read-only

1. `fill_super`.
2. Directory `lookup`: scan entries, `iget_locked`, fill the inode from disk, `d_splice_alias`.
3. Directory `iterate_shared`: `dir_emit` for each entry.
4. File data: `read_iter = generic_file_read_iter` with `read_folio` or `readahead` mapping file offset to block.

Read-write adds allocation, `create`, `mkdir`, `unlink`, `rename`, write paths, `fsync` and crash safety.

## Following `cat hello.txt`

`openat` resolves the path with dcache lookups, calling `lookup` on a miss. `read` goes to `read_iter`, which finds the folio in the page cache or calls the filesystem to read it. Data past `i_size` is never returned.

## Pitfalls

- Treat on-disk data as hostile: bound every block number and length.
- Follow the VFS lock order; rename has special rules.
- Return the right errors: `ENOENT`, `ENOTDIR`, `EISDIR`.
- Test with `xfstests` and corrupted images.

## Alternatives

`FUSE` for user-space filesystems, `overlayfs` for layered images, `virtiofs` and `9p` for sharing with VMs, `libfs` for synthetic filesystems.

## Self-check

Try each question before you read the answers below.

1. Which VFS object represents an open file, and which represents a name in a directory?
2. What does a read-only filesystem need at minimum?
3. Why bound every block number read from disk?

### Answers

1. `struct file` is the open file description; `struct dentry` is the name, which can also be negative.
2. `fill_super`, directory `lookup`, directory iteration and a data read path such as `read_folio`.
3. The image may be corrupt or hostile, and an unchecked number can read outside the device or crash the kernel.
