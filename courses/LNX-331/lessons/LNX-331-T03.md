# PCI driver for the QEMU 'edu' device

This lesson follows the topic synthesis `synth/LNX-331/LNX-331-T03.md`. Helper names and the exact edu register map should be checked in your kernel and in the QEMU edu documentation (to verify).

## What you will be able to do

- Inspect PCI devices with `lspci` and sysfs.
- Write the PCI driver skeleton and a correct `probe`.
- Access registers with `readl` and `writel`, with bounded polling.
- Choose between polling and an interrupt, and set up DMA safely.

## Look first

```
qemu-system-x86_64 ... -device edu
lspci -nn            # 1234:11e8
lspci -vv -s 00:04.0 # BARs, capabilities, driver in use
ls /sys/bus/pci/devices/0000:00:04.0/
```

## Skeleton

```c
static const struct pci_device_id edu_ids[] = {
	{ PCI_DEVICE(0x1234, 0x11e8) }, { }
};
MODULE_DEVICE_TABLE(pci, edu_ids);

static int edu_probe(struct pci_dev *pdev, const struct pci_device_id *id)
{
	void __iomem *regs;
	int ret = pcim_enable_device(pdev);
	if (ret) return ret;
	pci_set_master(pdev);
	ret = pcim_iomap_regions(pdev, BIT(0), "edu");
	if (ret) return ret;
	regs = pcim_iomap_table(pdev)[0];
	if ((readl(regs + 0x00) & 0xff) != 0xed) return -ENODEV;
	ret = pci_alloc_irq_vectors(pdev, 1, 1, PCI_IRQ_ALL_TYPES);
	if (ret < 0) return ret;
	return devm_request_irq(&pdev->dev, pci_irq_vector(pdev, 0), edu_irq, 0, "edu", pdev);
}
static struct pci_driver edu_driver = {
	.name = "edu_demo", .id_table = edu_ids, .probe = edu_probe,
};
module_pci_driver(edu_driver);
```

## Registers

| Offset | Meaning (verify in the QEMU docs) |
|---|---|
| 0x00 | ID: major, minor, 0xed |
| 0x04 | liveness: write x, read ~x |
| 0x08 | factorial: write n, read n! when done |
| 0x20 | status: bit 0 busy, bit 0x80 interrupt on completion |

Always use `readl` and `writel`. PCI writes are posted: read back to flush. Poll with a bound (`readl_poll_timeout` exists), never forever.

## Interrupt handler rules

Read and acknowledge the status, record the result, wake the waiter, return `IRQ_HANDLED` (or `IRQ_NONE` if it was not your device). No sleeping. Use a threaded handler or workqueue for long work.

## DMA

Set the mask (`dma_set_mask_and_coherent`), then use `dma_alloc_coherent` for a buffer that both sides read and write, or the streaming API for existing buffers. Program the **bus address**, not a pointer or physical address, and read the buffer only after completion.

## Self-check

Try each question before you read the answers below.

1. Why read a register back after writing it?
2. What should a driver do if the busy bit never clears?
3. Which address do you program into a device for DMA?

### Answers

1. PCI memory writes are posted. The read forces earlier writes to reach the device before you continue.
2. Give up after a bounded wait, for example with `readl_poll_timeout`, and return an error instead of spinning forever.
3. The bus (DMA) address returned by the DMA API, never a kernel virtual or physical address.
