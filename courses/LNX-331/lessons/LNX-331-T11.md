# arm64 cross-build, boot on QEMU virt

This lesson follows the topic synthesis `synth/LNX-331/LNX-331-T11.md`. Options such as `gic-version` defaults and CPU names depend on your QEMU version (to verify).

## What you will be able to do

- Cross-build an arm64 kernel with `ARCH` and `CROSS_COMPILE` (or `LLVM=1`).
- Boot it on QEMU `virt` with a console and an initramfs.
- Read the Image header and diagnose a silent boot failure.
- Name the main arm64 differences that affect driver code.

## Build

```
sudo apt install gcc-aarch64-linux-gnu qemu-system-arm flex bison bc libssl-dev libelf-dev
export ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu-
make O=../build-arm64 defconfig
make O=../build-arm64 -j"$(nproc)" Image dtbs modules
# alternative toolchain
make ARCH=arm64 LLVM=1 O=../build-arm64 defconfig
```

Use a separate `O=` directory per architecture. `Image` is the flat bootable file, `vmlinux` the ELF for GDB.

## Boot

```
qemu-system-aarch64 -M virt -cpu cortex-a57 -smp 2 -m 1G -nographic \
  -kernel ../build-arm64/arch/arm64/boot/Image -initrd rootfs.cpio.gz \
  -append "console=ttyAMA0 earlycon panic=-1" -no-reboot
```

| Option | Why |
|---|---|
| `-M virt` | the guest-oriented platform: GIC, PL011, virtio |
| `-cpu` | `cortex-a57`, `max` (TCG) or `host` (KVM on an arm64 host) |
| `console=ttyAMA0` | the PL011 UART, not `ttyS0` |
| `earlycon` | messages before the console driver loads |
| `-machine dumpdtb=virt.dtb` | see the device tree QEMU generates |

## Debug a silent boot

1. `earlycon` on? Right console name?
2. Parse the Image header (`magic`, `text_offset`, page size flag).
3. `-s -S`, then `gdb-multiarch`: `target remote :1234`, `file vmlinux`, `hbreak start_kernel`.
4. Panic about no init means the kernel booted: supply a root filesystem.

## Differences that bite

| Area | arm64 detail |
|---|---|
| memory model | weak ordering: use acquire and release or barriers |
| page size | 4K, 16K or 64K: never assume 4096 |
| interrupts | GIC, not APIC |
| description | device tree (or ACPI) |
| privilege | EL0 to EL3; kernel at EL1 or EL2 |
| firmware calls | PSCI and SMCCC |

## Root filesystem tips

Static BusyBox in an initramfs is enough. To build a Debian rootfs on x86, use `qemu-user-static` and `binfmt_misc` so arm64 binaries run in a chroot.
