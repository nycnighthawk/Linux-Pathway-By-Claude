# Network drivers and NAPI

This lesson follows the topic synthesis `synth/LNX-331/LNX-331-T08.md`. Function names (`napi_build_skb`, page pool helpers) change between versions (to verify).

## What you will be able to do

- Describe `net_device_ops` and the transmit and receive paths.
- Explain NAPI: interrupt, schedule, poll with a budget, complete.
- Handle transmit backpressure with queue stop and wake.
- Observe a driver with `ethtool`, `/proc/net/softnet_stat` and tracepoints.

## The driver object

```c
dev = alloc_etherdev_mq(sizeof(struct priv), nqueues);
dev->netdev_ops = &my_ops;
dev->ethtool_ops = &my_ethtool;
netif_napi_add(dev, &q->napi, my_poll);
register_netdev(dev);
```

Operations: `ndo_open`, `ndo_stop`, `ndo_start_xmit`, `ndo_set_rx_mode`, `ndo_change_mtu`, `ndo_get_stats64`, `ndo_tx_timeout`, `ndo_bpf`.

## Receive with NAPI

```
interrupt:  disable queue irq in the device; napi_schedule(&q->napi)
poll(budget):
    while done < budget and descriptors ready:
        skb = build around the buffer; eth_type_trans; napi_gro_receive
    refill the ring
    if done < budget: napi_complete_done(); enable queue irq
    return done          /* never more than budget */
```

Under light load: one interrupt per packet or few. Under heavy load: polling continues, no interrupts, bounded work per round, fair between devices.

## Transmit

`ndo_start_xmit` maps the buffer for DMA, fills a descriptor, rings the doorbell. If the ring is nearly full: `netif_stop_queue`. The completion path unmaps and frees buffers and calls `netif_wake_queue`. A missing wake freezes transmission until `ndo_tx_timeout` fires.

## Features that matter

| Feature | What it does |
|---|---|
| checksum offload | card computes or verifies checksums |
| TSO, GSO | big buffer split into frames by card or stack |
| GRO | merge received packets of a flow before the stack |
| RSS | hash flows to several queues and CPUs |
| coalescing | delay the interrupt for a few packets or microseconds |
| XDP | eBPF program in the receive path before an skb exists |

## Observing

```
ethtool -S eth0 ; ethtool -c eth0 ; ethtool -K eth0 gro off
ip -s link show eth0
cat /proc/net/softnet_stat       # processed, dropped, time_squeeze per CPU
perf trace -e 'napi:napi_poll'
```

## Self-check

Try each question before you read the answers below.

1. What must a poll function return, and when does it re-enable the interrupt?
2. Transmission stops until the watchdog fires. Which call is probably missing?
3. `time_squeeze` keeps growing in `/proc/net/softnet_stat`. What does that mean?

### Answers

1. The number of packets processed, never more than the budget. It completes NAPI and re-enables the interrupt only when it did less than the budget.
2. `netif_wake_queue` in the completion path after the driver stopped the queue.
3. Receive processing ran out of budget or time while packets were still waiting, so the CPU cannot keep up.
