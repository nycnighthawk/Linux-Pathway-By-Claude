# Interrupts, softirqs, workqueues, timers

This lesson follows the topic synthesis `synth/LNX-331/LNX-331-T04.md`. API details move between versions; check `Documentation/core-api/` (to verify).

## What you will be able to do

- Write a correct interrupt handler and know what it may not do.
- Defer work with a threaded handler or a workqueue.
- Arm, re-arm and safely stop timers.
- Choose the right mechanism for a job.

## Contexts and what they allow

| Context | May sleep | `GFP_KERNEL` | `mutex_lock` | `copy_to_user` |
|---|---|---|---|---|
| hardirq | no | no | no | no |
| softirq, tasklet, timer callback | no | no | no | no |
| workqueue, threaded handler | yes | yes | yes | no |
| system call | yes | yes | yes | yes |

`GFP_ATOMIC` and spinlocks are fine everywhere. `CONFIG_DEBUG_ATOMIC_SLEEP` catches violations.

## A handler

```c
static irqreturn_t edu_irq(int irq, void *dev_id)
{
	struct edu *e = dev_id;
	u32 st = readl(e->regs + 0x24);
	if (!st)
		return IRQ_NONE;          /* not ours (shared line) */
	writel(st, e->regs + 0x64);       /* acknowledge */
	e->result = readl(e->regs + 0x08);
	complete(&e->done);
	return IRQ_HANDLED;
}
```

Short, acknowledges the device, no sleeping. Locks shared with process context: `spin_lock_irqsave` there. Locks shared with softirq: `spin_lock_bh`.

## Deferral

```c
/* threaded: sleeps allowed in the second function */
devm_request_threaded_irq(dev, irq, quick, thread, IRQF_ONESHOT, "x", e);

/* workqueue */
INIT_WORK(&e->work, edu_work);
queue_work(system_wq, &e->work);
/* on remove */
cancel_work_sync(&e->work);
```

## Timers

```c
timer_setup(&e->t, edu_timeout, 0);
mod_timer(&e->t, jiffies + msecs_to_jiffies(2000));
del_timer_sync(&e->t);        /* never from the callback itself */
```

Use `hrtimer` for sub-tick precision and delayed work when the callback must sleep. `msleep` sleeps, `udelay` spins.

## Looking at it
