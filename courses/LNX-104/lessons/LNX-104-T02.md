# apt, dpkg, sources, pinning and holds

This lesson follows the topic synthesis `synth/LNX-104/LNX-104-T02.md`, which carries the sources and the history.

## What you will be able to do

- Use `dpkg` for single packages and `apt` for repositories, and know which layer a problem lives in.
- Declare sources in one-line and deb822 form.
- Read `apt-cache policy`, write a pin, and hold a package.

## Two layers

`dpkg` unpacks `.deb` files, runs maintainer scripts and records state in `/var/lib/dpkg/`; it fetches nothing. `apt`
reads the sources, downloads indexes, picks versions by priority, resolves dependencies and calls `dpkg`. Use `apt` at
the prompt and `apt-get`, `apt-cache` and `dpkg-query` in scripts, because the `apt` output format is not stable.

## dpkg essentials

```bash
dpkg -l 'lib*ssl*'      # ii installed, rc removed with config left, hi held
dpkg -L foo; dpkg -S /usr/bin/ssh; dpkg -s foo
dpkg -i foo.deb; dpkg -r foo; dpkg -P foo
dpkg --configure -a; dpkg -C
dpkg --compare-versions 1:2.0-1 gt 1.9-5 && echo newer
dpkg-query -W -f='${Package} ${Version}\n' 'openssl*'
```

## Sources

```
deb [signed-by=/etc/apt/keyrings/example.gpg] https://deb.example.org/apt stable main
```

The deb822 form uses `Types:`, `URIs:`, `Suites:`, `Components:`, `Signed-By:` in a `.sources` file under
`/etc/apt/sources.list.d/`. Suites include pockets such as `bookworm-updates`, `bookworm-security` and
`bookworm-backports`. `apt update` downloads the signed `InRelease` and the `Packages` indexes into `/var/lib/apt/lists/`.

## Priorities and pins

Each version has a priority. Defaults: 500 for a normal source, 990 for the target release, 100 for the installed
version and for sources marked `NotAutomatic` such as backports. 1000 or more forces an install even as a downgrade;
a negative value forbids the version. Pins live in `/etc/apt/preferences.d/`:

```
Package: nginx nginx-*
Pin: release n=bookworm-backports
Pin-Priority: 700
```

Always check with `apt-cache policy <pkg>`, which shows installed, candidate and every version with its priority.
Install one package from backports with `apt install -t bookworm-backports foo`; keep pins narrow and low.

## Holds

`apt-mark hold foo` stops upgrades, removal and reinstall; `apt-mark showhold` lists them and `unhold` releases them.
A hold also hides security fixes and can block an upgrade of something that depends on the held package, so give each
hold an owner and an end date. Unattended security updates are configured in `50unattended-upgrades` and
`20auto-upgrades` under `/etc/apt/apt.conf.d/`.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| `apt upgrade` pulls a new major version | broad pin or mixed suites | `apt-cache policy`, `/etc/apt/preferences.d/` |
| Could not get lock | another apt or the timer is running | `fuser` on the lock file before deleting anything |
| Package not upgraded | hold or pin below the installed priority | `apt-mark showhold`, policy output |
| Hash sum mismatch | mirror in the middle of a sync | retry later, change mirror |
