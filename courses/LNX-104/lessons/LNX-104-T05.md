# Building from source and shared libraries

This lesson follows the topic synthesis `synth/LNX-104/LNX-104-T05.md`, which carries the sources and the history.

## What you will be able to do

- Fetch, verify, configure, build, test and stage a source build.
- Explain real name, soname and linker name of a shared library.
- Diagnose library lookups with `ldd`, `readelf`, `ldconfig -p` and `LD_DEBUG`.

## The procedure

```bash
gpg --verify foo-1.4.2.tar.xz.asc foo-1.4.2.tar.xz      # or sha256sum -c
sudo dnf builddep foo        # or: sudo apt build-dep foo
./configure --prefix=/usr/local && make -j"$(nproc)" && make check
make DESTDIR=/tmp/stage install      # stage first, then package or copy
```

CMake: `cmake -S . -B build -DCMAKE_INSTALL_PREFIX=/usr/local`, `cmake --build build`,
`DESTDIR=/tmp/stage cmake --install build`. Meson: `meson setup build --prefix=/usr/local`, `meson compile -C build`,
`DESTDIR=/tmp/stage meson install -C build`. `PREFIX` is compiled into the program; `DESTDIR` only moves where files
land during the install. Use `/usr/local` or `/opt/<name>`, never `/usr`, and prefer turning the staged tree into a
package (`rpmbuild`, `dpkg-deb`, `fpm`) over leaving loose files.

## Compiler options that matter

`-I<dir>` header search, `-L<dir>` link-time library search, `-l<name>` link `libname`, `-fPIC -shared` build a shared
object, `-Wl,-soname,libfoo.so.1` set the soname, `-Wl,-rpath,'$ORIGIN/../lib'` embed a search path. A missing header
usually means a missing `-devel` (RPM) or `-dev` (Debian) package; `pkg-config --cflags --libs foo` prints the flags.

## Library names

`libfoo.so.1.4.2` is the real file, `libfoo.so.1` is the **soname** recorded in programs, `libfoo.so` is the linker name
for `-lfoo`. The soname changes only when the binary interface breaks. `ldconfig` creates the soname links and the cache
`/etc/ld.so.cache`.

## How the loader finds libraries

Order from `ld.so(8)`: `DT_RPATH` (only without `DT_RUNPATH`), `LD_LIBRARY_PATH`, `DT_RUNPATH`, the cache, then `/lib` and
`/usr/lib`. The cache comes from `/etc/ld.so.conf` and `/etc/ld.so.conf.d/*.conf`. `/usr/local/lib` is listed on Debian
family systems but usually not on Red Hat family systems.

```bash
ldd /usr/bin/foo | grep 'not found'
readelf -d /usr/bin/foo | grep -E 'NEEDED|SONAME|RPATH|RUNPATH'
ldconfig -p | grep libfoo
sudo ldconfig
LD_DEBUG=libs /usr/bin/foo 2>&1 | head
patchelf --set-rpath '$ORIGIN/../lib' /opt/foo/bin/foo
```

Prefer a `RUNPATH` with `$ORIGIN` or a drop-in file in `ld.so.conf.d`; keep `LD_LIBRARY_PATH` for debugging only.
Do not run `ldd` on untrusted programs; use `readelf -d`.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| `xyz.h: No such file` | development package missing | install `-devel` or `-dev` |
| error while loading shared libraries | directory not in cache | `ldd`, `ldconfig -p`, `ld.so.conf.d` |
| Works on one host only | two copies of one soname | `LD_DEBUG=libs` on both |
| Cannot remove a source install | no staging, no package | rebuild with `DESTDIR`, package it |
