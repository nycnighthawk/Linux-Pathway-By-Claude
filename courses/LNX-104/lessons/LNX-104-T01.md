# Querying, verifying and undoing with rpm and dnf

This lesson follows the topic synthesis `synth/LNX-104/LNX-104-T01.md`, which carries the sources and the history.

## What you will be able to do

- Ask the package database which package owns a file, what a package contains and what it needs.
- Verify installed files against the recorded size, mode and digest, and read the flag field.
- Review `dnf history` and choose between `undo`, `redo` and `rollback`.

## Two layers

`rpm` installs and inspects single package files and keeps the database of what is installed. `dnf` reads repository
metadata, solves dependencies, downloads, runs one transaction through the RPM library and records it in its history.
A package name has five parts: `name-epoch:version-release.arch`, for example `openssl-1:3.2.2-6.el10.x86_64`.

## Query with rpm

```bash
rpm -qa --last              # everything installed, newest first
rpm -qi bash                # name, version, install date, signature, summary
rpm -ql bash                # files in the package
rpm -qc openssh-server      # configuration files only
rpm -qf /etc/ssh/sshd_config   # which package owns this file
rpm -qR bash                # requirements; --provides and --whatrequires work too
rpm -qp ./foo.rpm           # inspect a file before installing (-p with -i, -l, -R)
rpm -q --qf '%{NAME}-%{VERSION}-%{RELEASE}.%{ARCH}\n' bash
```

`rpm --querytags` lists every tag usable in `--qf`.

## Query with dnf

`dnf` also knows packages that are not installed: `dnf info`, `dnf provides /usr/bin/dig`,
`dnf repoquery --requires bash`, `dnf repoquery --whatrequires glibc`, `dnf updateinfo list --security`,
`dnf check-update` (exit status 100 when updates exist) and `dnf needs-restarting -r`.

## Verify

`rpm -V pkg` compares each file with the package record and prints one line per difference. The nine-character field
uses a dot for "matches": `S` size, `M` mode, `5` digest, `D` device, `L` link target, `U` user, `G` group, `T` mtime,
`P` capabilities. A letter after it marks the file category: `c` config, `d` doc, `l` licence, `g` ghost. Config files
are expected to differ; a changed binary is a red flag. `rpm -K file.rpm` checks digests and the signature of a package
file. Verification detects accidents and clumsy tampering, not an attacker who also altered the database.

## History and undo

```bash
dnf history list              # id, command line, date, actions, altered
dnf history info 42           # packages of transaction 42
dnf history undo 42           # reverse that one transaction
dnf history redo 42           # repeat it
dnf history rollback 42       # reverse everything after transaction 42
```

`undo` needs the older packages to be available in a repository or in the cache, and it cannot reverse changes to data
(a database server schema). Snapshot the file system before large transactions.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| `undo` fails, package unavailable | mirror dropped old versions, no cache | `dnf history info`, repository retention |
| `rpm -Va` is noisy | config files and ghosts differ by design | filter `c` lines, verify binaries only |
| `rpm -qf` says not owned | file placed by hand or by a scriptlet | `rpm -qf` on the directory, timestamps |
| Package "installed" but missing files | interrupted transaction | `rpm -V`, `dnf reinstall` |
