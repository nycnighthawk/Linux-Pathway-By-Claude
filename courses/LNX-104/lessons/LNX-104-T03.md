## The trust chain

A package signature protects the file. A signed index protects the list of files and prevents replay of old data.
APT signs `Release` (as `InRelease` or `Release.gpg`), which carries the checksums of every `Packages` index, which
carry the checksum of every `.deb`. RPM repositories sign each package and may also sign `repodata/repomd.xml`
(`repo_gpgcheck`). HTTPS adds privacy, but a compromised mirror over TLS still serves what it chooses.

## dnf repositories

```ini
[example-appstream]
name=Example AppStream $releasever - $basearch
baseurl=https://repo.example.org/el$releasever/$basearch/appstream/
enabled=1
gpgcheck=1
repo_gpgcheck=0
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-example
priority=50
```

`baseurl`, `metalink` or `mirrorlist` give the location; `exclude` and `includepkgs` limit what a repository may
supply; `localpkg_gpgcheck` covers locally supplied files. Commands: `dnf repolist --all`, `dnf repoinfo`,
`dnf config-manager --set-enabled crb`, `dnf --enablerepo=epel install htop`, `dnf clean all`, `dnf makecache`,
`createrepo_c dir` and `reposync`. Hardening baselines require `gpgcheck` everywhere and may forbid EPEL.

## RPM keys

```bash
rpm --import /etc/pki/rpm-gpg/RPM-GPG-KEY-example
rpm -qa 'gpg-pubkey*'
gpg --show-keys --with-fingerprint keyfile       # inspect first, compare with the vendor's page
rpm -K package.rpm                               # NOKEY: key unknown; BAD: content altered
rpmsign --addsign package.rpm                    # with %_gpg_name and %_gpg_path set
```

Never answer yes to a key prompt in automation unless the key was checked beforehand.

## APT keys

```bash
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://repo.example.org/key.gpg | sudo gpg --dearmor -o /etc/apt/keyrings/example.gpg
gpg --show-keys --with-fingerprint /etc/apt/keyrings/example.gpg
```

Reference the file with `signed-by` on that one source. Avoid `apt-key add`, which trusts a key for every source.
`[trusted=yes]` switches verification off and is only for a local repository you built.

## Your own repository

RPM: `createrepo_c`, sign packages (and optionally `repomd.xml`), publish `.repo` and the public key. Debian:
`reprepro`, `aptly` or `apt-ftparchive` build and sign `Packages` and `Release`. Keep the signing key on a machine that
is not the build host and give it an expiry.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| `NO_PUBKEY` or `NOKEY` | key never imported | vendor page, fingerprint, `signed-by` or `gpgkey` |
| Key expired | vendor rotated keys | push the new key before the old one expires |
| SHA-1 signature rejected | crypto policy | re-sign with a modern digest |
| Third-party package replaces a base package | higher version, same name | `priority`, `exclude`, pin |
