# Flatpak remotes and packages

This lesson follows the topic synthesis `synth/LNX-104/LNX-104-T04.md`, which carries the sources and the history.

## What you will be able to do

- Explain refs, runtimes, remotes and installations.
- Add, modify and remove remotes; install, update and remove applications.
- Inspect and override sandbox permissions.

## The model

A ref is `kind/name/arch/branch`, for example `app/org.mozilla.firefox/x86_64/stable`. Applications use shared
**runtimes** such as `org.freedesktop.Platform`. A **remote** is an OSTree repository (or OCI registry) with a signing
key. An **installation** is where refs live: the system installation (`/var/lib/flatpak`), the per-user installation
(`~/.local/share/flatpak`) and any named installation from `/etc/flatpak/installations.d/`. Remotes belong to one
installation. RHEL 10 delivers Firefox and Thunderbird as Flatpaks by default, which is why this is an exam topic.

## Remotes

```bash
flatpak remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo
flatpak remotes -d                         # details: URL, options, priority
flatpak remote-ls flathub --app
flatpak remote-modify --prio=5 flathub     # also --disable, --enable, --url, --filter=FILE
flatpak remote-delete flathub
```

System-wide remotes can be preconfigured by dropping `.flatpakrepo` files into `/usr/share/flatpak/remotes.d/` or
`/etc/flatpak/remotes.d/`. Keep signature verification on; `--no-gpg-verify` is for tests only.

## Applications

```bash
flatpak search gimp
flatpak install flathub org.gimp.GIMP          # add --user for the per-user installation
flatpak list --app --columns=application,branch,installation
flatpak info --show-permissions org.gimp.GIMP
flatpak update; flatpak uninstall --unused
flatpak mask 'org.example.*'; flatpak pin org.freedesktop.Platform//23.08
flatpak repair; flatpak history
flatpak create-usb /mnt/usb org.gimp.GIMP      # offline distribution
```

## Sandbox and permissions

Each application runs under `bubblewrap` with a seccomp filter and sees only its runtime and `~/.var/app/<id>/`.
Permissions are granted in the application metadata and changed with overrides: `--share=network`,
`--socket=wayland`, `--device=dri`, `--filesystem=xdg-documents:ro`, `--nofilesystem=host`, `--talk-name=`.
`flatpak override --show <id>` prints the effective override; portals let a program receive one file the user picked
instead of broad access. Broad grants such as `--filesystem=host` or `--socket=session-bus` make the sandbox
cosmetic, so review them.

## Administration

Polkit actions such as `org.freedesktop.Flatpak.app-install` control who may install system-wide. Updates come from
GNOME Software, timers or `flatpak update --noninteractive -y`. Treat Flatpak updates as part of patching, and track
runtime end-of-life dates.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Remote not found | remote added in the other installation | `flatpak remotes -d` with and without `--user` |
| Application cannot see a folder | sandbox, no permission | `flatpak info --show-permissions`, override |
| Disk use keeps growing | unused runtimes | `flatpak uninstall --unused` |
| Old runtime with known flaws | end-of-life branch | runtime branch and support dates |
