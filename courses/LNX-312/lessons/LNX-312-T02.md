## What you will be able to do

- State the CNI contract: executable, environment variables, JSON in and out.
- Read a configuration list and explain chaining and IPAM delegation.
- Write a minimal ADD, DEL and VERSION plugin and test it without a cluster.

## The contract

The runtime creates the network namespace, then runs the plugin with:

| Variable | Meaning |
|---|---|
| `CNI_COMMAND` | `ADD`, `DEL`, `CHECK`, `VERSION` (and `STATUS`, `GC` in spec 1.1) |
| `CNI_CONTAINERID` | unique id of the sandbox |
| `CNI_NETNS` | path of the namespace, such as `/run/netns/test1` |
| `CNI_IFNAME` | interface name to create inside it |
| `CNI_ARGS` | extra `K=V;K=V` (Kubernetes passes pod name and namespace) |
| `CNI_PATH` | where to find other plugins (for IPAM delegation) |

Standard input carries the network configuration JSON (`cniVersion`, `name`, `type`, plugin fields, optional `ipam`). On success the plugin prints a result JSON (`cniVersion`, `interfaces`, `ips`, `routes`, `dns`). On failure it prints `{"cniVersion":..., "code":N, "msg":"..."}` and exits non-zero. **DEL must succeed when things are already gone.**

## Configuration and chaining

Files live in `/etc/cni/net.d`; binaries in `/opt/cni/bin`. The runtime uses the **first file in lexical order**, so stale files can win. A `.conflist` chains plugins: ADD runs them in order, each receiving the previous result as `prevResult`; DEL runs in reverse. Typical chain: `bridge` (with `host-local` IPAM) then `portmap`, plus `loopback`.

## How Kubernetes uses it

The kubelet asks the runtime (containerd, CRI-O) for a sandbox; the runtime creates the namespace and calls the chain with the pod name and namespace in `CNI_ARGS`. No valid configuration means the network is not ready and the node stays NotReady.

## A minimal plugin

For ADD: open the namespace, create a veth pair, move one end in as `CNI_IFNAME`, give it the address from the configuration, add the default route, attach the host end to a bridge, print the result. For DEL: delete the host-side link, ignore errors. For VERSION: print the supported versions. Drive it by hand:

```bash
ip netns add test1
echo '{"cniVersion":"1.0.0","name":"labnet","type":"minimal"}' | \
  CNI_COMMAND=ADD CNI_CONTAINERID=test1 CNI_NETNS=/run/netns/test1 CNI_IFNAME=eth0 CNI_PATH=/opt/cni/bin ./minimal
```

## Worked example: leaked addresses

After a node crash DEL never ran, so `host-local` still holds files for dead pods and new pods fail with an exhausted range. Clean the leaked reservations; spec 1.1 GC exists for this.
