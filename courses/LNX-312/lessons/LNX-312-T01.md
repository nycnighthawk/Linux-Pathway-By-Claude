# netns + veth + bridge + NAT: a container network by hand

This lesson follows the topic synthesis `synth/LNX-312/LNX-312-T01.md`, which carries the sources, the history and the failure cases.

## What you will be able to do

- Rebuild by hand what a container runtime builds: namespace, veth pair, bridge, address, route, NAT.
- Publish a port with destination NAT and explain why it works from outside but not always from the host.
- Locate where packets disappear using counters, `tcpdump` and the routing and neighbour tables.

## The five elements

| Element | Linux part |
|---|---|
| Isolation | network namespace (own interfaces, routes, firewall, sockets) |
| Connection | veth pair (one end per side), or macvlan, tap |
| Switching | Linux bridge (MAC learning, flooding), or routing |
| Addressing | static, or an IPAM service |
| Reachability policy | forwarding, NAT, filtering |

## Build it

```bash
ip link add lab0 type bridge && ip addr add 10.10.0.1/24 dev lab0 && ip link set lab0 up
for n in c1 c2; do ip netns add $n; done
ip link add v-c1 type veth peer name eth0 netns c1
ip link set v-c1 master lab0 up
ip -n c1 addr add 10.10.0.2/24 dev eth0
ip -n c1 link set lo up; ip -n c1 link set eth0 up
ip -n c1 route add default via 10.10.0.1       # repeat for c2 with .3
sysctl -w net.ipv4.ip_forward=1
nft add table ip lab
nft 'add chain ip lab post { type nat hook postrouting priority srcnat; }'
nft add rule ip lab post ip saddr 10.10.0.0/24 oifname != lab0 masquerade
nft 'add chain ip lab pre { type nat hook prerouting priority dstnat; }'
nft add rule ip lab pre tcp dport 8080 dnat to 10.10.0.2:80
```

## Verify layer by layer

`ping` the gateway from the namespace, then the host's uplink address, then an outside address, then a name. `ip -n c1 route`, `bridge link`, `bridge fdb show`, `nft list ruleset` (read the counters), `conntrack -L`, `tcpdump -ni lab0`.

## Traps

- Forward chain policy drop, or a second rule manager (firewalld, ufw) rewriting your chains.
- DNAT in `prerouting` does not see traffic generated on the host itself; add an `output` rule or use the bridge address.
- Two tools allocating from one subnet give duplicate addresses and flapping neighbours.
- A private subnet that overlaps a VPN route makes hosts unreachable.

## Worked example: no way out

`c1` pings its gateway but not the Internet. `nft list ruleset` shows the masquerade rule with zero packets and a forward chain with policy drop. Add accept rules for traffic to and from `lab0`, then watch the counters move.
