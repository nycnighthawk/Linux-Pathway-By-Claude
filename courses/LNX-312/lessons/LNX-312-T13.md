# BGP to physical top-of-rack switches

This lesson follows the topic synthesis `synth/LNX-312/LNX-312-T13.md`, which carries the sources, the history and the failure cases.

## What you will be able to do

- Describe a leaf-spine fabric with BGP on every server link and say why it replaces stretched VLANs.
- Configure a node to announce its Pod range and service addresses, with graceful restart and BFD.
- State what the switch must filter and limit, and check a session on both ends.

## Design

Every leaf connects to every spine; servers connect to leaves over routed links. eBGP everywhere, a private AS per rack (or per node), ECMP across the spines. BGP unnumbered lets a session run over the IPv6 link-local address of the interface, carrying IPv4 prefixes, so no per-link addresses are needed.

## What the node announces

| Prefix | Why |
|---|---|
| node loopback | stable identity of the node |
| Pod CIDR (native routing) | the fabric can reach Pods directly |
| service /32 addresses | ECMP to nodes that have endpoints |

In Cilium this is cluster configuration, peer configuration and advertisement resources; on a plain host it is FRR.

## What the switch enforces

Inbound prefix list per neighbour, maximum-prefix limit, session authentication, short AS-path limit, and a default-only or filtered route feed back to the host. Graceful restart on both sides keeps forwarding during an agent restart; BFD detects real failure quickly. Agree timers with the network team.

## Worked example: gaps during upgrades

Pods are unreachable for a minute at each rolling upgrade. The switch withdraws routes when the agent restarts because graceful restart is on for the node only. Enable it on the switch with a restart time longer than the agent restart.
