# Flannel, Calico, Cilium compared

This lesson follows the topic synthesis `synth/LNX-312/LNX-312-T03.md`, which carries the sources and the trade-off analysis.

## What you will be able to do

- Name what each of the three plugins does on the node (data plane, address management, policy).
- Choose overlay or routed networking from the properties of the underlay.
- Write the minimal configuration for each plugin that selects a given mode.

## One job, three answers

Every cluster network must give each Pod a routable address, carry packets between nodes, and (optionally) enforce policy.

| Plugin | Address handling | Cross-node transport | Policy |
|---|---|---|---|
| Flannel | one subnet per node cut from a cluster range | VXLAN by default, host-gw as the routed option | none; pair it with another component |
| Calico | IP pools split into per-node blocks | BGP routes, or IP-in-IP or VXLAN encapsulation | NetworkPolicy plus its own richer policy objects |
| Cilium | cluster pool or cloud IPAM | VXLAN or Geneve tunnel, or native routing | NetworkPolicy plus identity-based L3 to L7 policy, eBPF datapath |

## Choosing between overlay and routed

An overlay needs nothing from the physical network but pays a header per packet (about 50 bytes for VXLAN over IPv4), so the Pod MTU must shrink. Routed designs keep the full MTU and make traffic visible to the fabric, but they need the underlay to learn Pod prefixes (same L2 segment for host-gw, BGP otherwise) and cloud route tables may cap the number of entries. A mixed mode such as Calico's cross-subnet encapsulation tunnels only when a packet leaves its subnet.

## Worked example: a node that cannot reach remote Pods

Pods on one node talk fine; cross-node traffic dies. Check in order: the tunnel port is open between nodes (UDP 8472 for Flannel VXLAN), the node address Calico or Cilium picked is the one on the right interface, and MTU is not larger than the underlay allows. Large transfers hanging while pings pass is the classic MTU signature.
