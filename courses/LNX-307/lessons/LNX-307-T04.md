## Why ship logs off the box

Local logs vanish with the host, are scattered across hosts, and can be edited by an intruder. Central logging sends a copy as it is written to a place the source cannot alter. The path: application (stdout, `/dev/log`, files) to journald and/or rsyslog, then transport, then a store, then queries.

## journald and journalctl

```bash
journalctl -u nginx --since "1 hour ago" -p warning     # one unit, priority warning and up
journalctl -b -1 -k                                     # kernel log of the previous boot
journalctl -o json -n 5 _SYSTEMD_UNIT=sshd.service      # structured fields
journalctl --disk-usage ; journalctl --verify
```

In `journald.conf` set `Storage=persistent` (or create `/var/log/journal`), `SystemMaxUse=` and rate limits. `logrotate` keeps plain files bounded: `rotate 14`, `daily`, `compress`, `missingok`, and a `postrotate` reload (or `copytruncate` when the program cannot reopen files). A rotation without a reload leaves the service writing into the renamed file.

## rsyslog forwarding

```text
action(type="omfwd" target="logs.example.org" port="6514" protocol="tcp"
       StreamDriver="gtls" StreamDriverMode="1" StreamDriverAuthMode="x509/name"
       StreamDriverPermittedPeers="logs.example.org"
       queue.type="LinkedList" queue.filename="fwd" queue.saveOnShutdown="on"
       queue.maxDiskSpace="1g" action.resumeRetryCount="-1")
```

UDP (`@host`) can drop silently, TCP (`@@host`) is better, TLS with authentication is the compliance standard. The queue settings decide whether a collector outage means buffered or lost messages. Validate with `rsyslogd -N1`; test with `logger -p local0.info test`.

## Aggregation and labels

Loki indexes only a small label set per stream (`{host, unit}`) and stores compressed text, so it is cheap; Elasticsearch indexes every field, so it is rich and costly. Query Loki with LogQL: `{unit="sshd.service"} |= "Failed password"`, and turn logs into a metric with `sum by (host) (rate({unit="sshd.service"} |= "Failed" [5m]))` for alerts ([T03](lesson:LNX-307-T03)). Rule: bounded labels, variable text in the message, explicit retention. Put a request or trace id in every record and keep clocks in sync (chrony) so one request can be followed across hosts.

## Failure patterns

- Silence read as health: alert when a source stops sending.
- Secrets and personal data in logs: scrub at the source.
- Log storms and journald rate limits dropping messages during the incident.
- Multi-line stack traces split into separate records.

Evidence for diagnosis, such as the OOM kill lines ([T08](lesson:LNX-307-T08)) or the kernel log before a crash ([T06](lesson:LNX-307-T06)), only helps if it was shipped.
