# SELinux: contexts, booleans, audit2why

This lesson follows the topic synthesis `synth/LNX-204/LNX-204-T04.md`, which carries the sources and the history.

## What you will be able to do

- Explain type enforcement: contexts, types, domains and why a compromised root daemon is still contained.
- Read `ls -Z`, `ps -Z` and AVC records, and classify a denial as boolean, label, port or missing policy.
- Apply the smallest persistent fix with `setsebool -P`, `semanage fcontext`, `restorecon` and `semanage port`.
- Use permissive mode and `audit2allow` sparingly and correctly.

## The model

Ordinary permissions are checked first. If they allow, the kernel asks SELinux whether the process **domain** (type of the
process) may perform the permission on the object **type** (file, port, socket). Contexts look like `user:role:type:level`; the
type does most of the work. A web server runs as `httpd_t` because the binary is labelled `httpd_exec_t` and policy has a type
transition. Modes: enforcing, permissive (log only), disabled (module not loaded; returning needs a full relabel).
`getenforce`, `sestatus`, `setenforce 0|1` (until reboot), `/etc/selinux/config` (persistent).

## Triage in order

1. **Reproduce and read:** `ausearch -m AVC,USER_AVC,SELINUX_ERR -ts recent -i`; pipe to `audit2why`, or use `sealert`.
2. **Boolean?** `getsebool -a | grep httpd`, `semanage boolean -l`; fix with `setsebool -P httpd_can_network_connect_db on`.
3. **Label?** Files keep their label when moved. `ls -Z`, `matchpathcon`; persistent rule:
   `semanage fcontext -a -t httpd_sys_content_t '/srv/web(/.*)?'`, then `restorecon -Rv /srv/web`. `chcon` is temporary.
4. **Port?** `semanage port -l | grep http`; `semanage port -a -t http_port_t -p tcp 8081`.
5. **Policy gap?** Only now consider `audit2allow -M mylocal`, read the generated `.te` first, then `semodule -i`.
6. To debug one daemon: `semanage permissive -a httpd_t`, not `setenforce 0`. `semodule -DB` shows hidden dontaudit denials; `semodule -B` restores them.

Useful queries: `sesearch -A -s httpd_t -t httpd_sys_content_t`, `sepolicy manpage -a` (per-domain pages listing booleans and file types).
Containers and VMs also get a category pair (`s0:c123,c456`) so two instances of the same type cannot touch each other's files;
mount options `context=` and `fscontext=` label volumes that lack xattrs (NFS, FUSE).

## A worked example

nginx serves `/srv/web` but returns 403. Modes are fine. `ls -Zd /srv/web` shows `default_t`. `ausearch -m AVC -ts recent | audit2why`
reports a type mismatch, not a boolean. Fix: the `semanage fcontext` rule plus `restorecon -Rv /srv/web`. The same fix survives a full relabel.

A failing habit: moving a home directory into `/var/www/html`, seeing the break, running `setenforce 0` and setting `SELINUX=disabled`.
The cause was one `restorecon -R`. Later, files created while disabled have no labels and re-enabling forces a relabel.
