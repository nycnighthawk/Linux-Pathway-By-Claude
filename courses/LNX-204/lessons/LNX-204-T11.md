# CVE and errata triage

This lesson follows the topic synthesis `synth/LNX-204/LNX-204-T11.md`, which carries the sources and the history.

## What you will be able to do

- Use CVE, CVSS, KEV, EPSS and vendor severity and say what each tells you.
- Read a vendor advisory and check whether a host has the fixed build, even when the upstream version looks old.
- Apply a triage routine: applicability, exposure, exploitation, mitigation, deployment, verification.
- Deploy fixes in stages and confirm that running processes use them.

## Vocabulary

A **CVE** names a flaw. **CVSS** scores severity in the abstract. **KEV** (CISA's Known Exploited Vulnerabilities catalogue) lists flaws seen exploited;
**EPSS** estimates the probability of exploitation. Vendors issue **errata**: security, bug-fix and enhancement advisories (RHSA, RHBA, RHEA; Rocky RLSA; Debian
DSA; Ubuntu USN) with a CVE list, severity (Low to Critical), fixed package builds and notes. Enterprise distributions **backport** fixes into the shipped
version, so `openssl 1.1.1k` can be fixed: the release number or changelog says so.

## Commands

```
dnf updateinfo list security            # applicable advisories
dnf updateinfo info RHSA-...            # details and CVEs
dnf upgrade --security                  # only security errata
dnf history / dnf history undo N        # record and rollback
needs-restarting -r                     # is a reboot needed?
needs-restarting -s                     # services running old libraries
rpm -q --changelog openssl | grep CVE-  # was it backported?
apt list --upgradable; apt changelog pkg; debsecan; needrestart
oscap oval eval --results r.xml feed.xml
```

## The triage routine

1. **Does it apply?** Installed, at a build older than the fixed one, loaded or running.
2. **Is the vulnerable feature enabled?** Check configuration and attack vector (network, local, needs authentication).
3. **Who can reach it?** Firewall policy and listening sockets answer this ([lesson](lesson:LNX-204-T06)).
4. **Is it exploited or likely?** KEV and EPSS before the base score.
5. **Mitigation if patching waits:** disable a module, restrict access, SELinux boolean or confinement, AppArmor profile.
6. **Deploy in rings:** canary, then groups; restart services or reboot; live patching bridges the gap. Rebuild images, since updating the host does not
   fix a vulnerable base image.
7. **Verify:** re-scan, check package build and that the process restarted; record the decision, owner and evidence. Accepted risks need an expiry.

## A worked example

A scanner flags `openssl-1.1.1k`. `rpm -q --changelog openssl | head` shows "Resolves: CVE-..." in the installed build, so the finding is a false
positive and the changelog is the evidence. Another advisory lists `sudo` as Important and local, but it is on the KEV list: patch now, because a local user
on a shared host can exploit it. A third affects a library statically bundled into an application: `dnf updateinfo` shows nothing, the scanner shows nothing, and the
host stays vulnerable until the application vendor ships a build.
