# auditd

This lesson follows the topic synthesis `synth/LNX-204/LNX-204-T07.md`, which carries the sources and the history.

## What you will be able to do

- Describe the audit pipeline: kernel rules, `auditd`, log files, plugins.
- Write watch rules and system call rules with keys, and place `-e 2` correctly.
- Read multi-line events and answer "who, what, when" with `ausearch` and `aureport`.
- Size retention and forward records off the host.

## The pipeline

The kernel emits records to a netlink socket; `auditd` writes `/var/log/audit/audit.log`; rules are loaded with `auditctl` or, persistently,
from `/etc/audit/rules.d/*.rules` merged by `augenrules --load`. `/etc/audit/auditd.conf` sets rotation (`max_log_file`, `num_logs`,
`max_log_file_action`), disk behaviour (`space_left_action`, `disk_full_action`) and flushing. Plugins (`/etc/audit/plugins.d/`)
forward to syslog or a remote server.

## Rules

```
-b 8192                                              # backlog
-w /etc/passwd -p wa -k identity                     # watch writes and attribute changes
-a always,exit -S execve -F arch=b64 -F auid>=1000 -k exec
-a always,exit -S execve -F arch=b32 -F auid>=1000 -k exec
-e 2                                                 # last: immutable until reboot
```

`auid` is the login uid, set at login and kept through `su` and `sudo`; it names the human. 32-bit and 64-bit calls need separate
`arch=` rules. The first matching rule decides, so exclusions go first. Do not audit every `open`: the log drowns and the backlog
overflows, so more logging yields less evidence. Choose events that matter: identity files, sudoers, time changes, module loading, mounts,
privileged commands, failed access, SELinux policy changes, logins.

## Reading events

One event is several lines with one serial: `SYSCALL`, `PATH`, `CWD`, `EXECVE`, `PROCTITLE`, plus typed messages (`USER_LOGIN`,
`USER_CMD`, `AVC`, `CONFIG_CHANGE`). Commands:

```
ausearch -k identity -ts today -i
ausearch -m USER_LOGIN --success no -i
aureport -x --summary        # executables
aureport -au --failed        # authentication failures
ausearch -if audit.log -k sshd_config -i   # read an offline log
```

`-i` interprets numbers and hex. Offline analysis is how you work on a copy of a compromised host's log.

## A worked example

Someone changed `/etc/ssh/sshd_config`. With the rule `-w /etc/ssh/sshd_config -p wa -k sshd_config` loaded beforehand,
`ausearch -k sshd_config -i` shows the executable, the login uid and the terminal. Without the watch there is nothing to find, so
watches are written before they are needed. A failing design: `-a always,exit -S open` for everyone, a gigabyte of log per hour,
`backlog limit exceeded` in the kernel log, and a 64-bit-only `execve` rule that a 32-bit binary walks around.

Operational cautions: `-f 2` (panic on failure) and `disk_full_action = halt` can stop production; test rule sets in a lab; send events off
the host (`audisp-remote` or syslog) because a root attacker can edit the local trail.
