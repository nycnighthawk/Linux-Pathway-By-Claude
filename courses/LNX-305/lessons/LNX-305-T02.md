# Playbooks, handlers, loops and Jinja2

This lesson follows the topic synthesis `synth/LNX-305/LNX-305-T02.md`, which carries the history and the sources.

## What you will be able to do

- Read and write a play: hosts, tasks, handlers, variables, privilege escalation.
- Use `loop`, `when`, `register`, `block` and `rescue` correctly.
- Render a configuration file from data with a Jinja2 template, and trigger a handler only when it changed.

## Anatomy of a play

```yaml
- name: Web tier
  hosts: web
  become: true
  vars: {http_port: 8080}
  tasks:
    - name: Render the site configuration
      ansible.builtin.template:
        src: site.conf.j2
        dest: /etc/nginx/conf.d/site.conf
        mode: "0644"
        validate: nginx -t -c %s
      notify: Reload nginx
  handlers:
    - name: Reload nginx
      ansible.builtin.service: {name: nginx, state: reloaded}
```

A play runs its tasks in order, one task across all hosts of the current batch before the next task (the `linear`
strategy). `forks` limits parallel connections, `serial` splits the hosts into batches for a rolling change, and
`delegate_to` or `run_once` send a step to one other host. Use the fully qualified module name (`ansible.builtin.copy`).

## Handlers

A handler runs only if a task that names it reported `changed`. It runs once per play and host, after the tasks section, in
the order the handlers are defined. `meta: flush_handlers` runs the queued ones now. If a host fails before the handlers
run, they do not run for it, and a rerun does not queue them again because nothing changes: this is the classic trap. Put the
risky work before the configuration task, or flush handlers right after it.

## Loops and conditions

`loop` takes a list; the current element is `item` unless `loop_control: {loop_var: name}`. Use `dict2items` for
dictionaries and `label` to keep the output short. `when` takes a bare expression, evaluated per item:
`when: ansible_facts['os_family'] == 'RedHat'` or `when: result is changed`. Never write `when: "{{ x }}"`; since
ansible-core 2.19 a condition that does not give a boolean is an error. `register` stores a result; in a loop it holds a
`results` list. `until` with `retries` and `delay` waits for a state. A `block` shares keywords and adds `rescue` and `always`.

## Jinja2

`{{ expression }}` prints a value, `{% for %}` and `{% if %}` control flow in template files, `{# comment #}` is ignored.
Filters transform values: `default`, `mandatory`, `join`, `map`, `select`, `selectattr`, `regex_replace`, `combine`,
`to_nice_yaml`, `password_hash`. A value that starts with a Jinja expression must be quoted in YAML. Write `true` and `false`,
never `yes` and `no`. The template module renders on the control node, then copies; `validate` checks the result before it is installed.

```jinja
{% for u in upstreams %}
server {{ u.host }}:{{ u.port }} weight={{ u.weight }};
{% endfor %}
```

## Worked example

A play creates a user per entry of `admins` with one looping task, renders `app.conf` from `upstreams`, and notifies
`Reload app`. The first run changes three things and reloads once. The second run changes nothing and reloads nothing. Edit
one upstream, run again, and only the template changes and the handler fires once. If the template contained a timestamp,
every run would reload: see [idempotence](lesson:LNX-305-T07).

## How this connects

- Variables come from [inventory and precedence](lesson:LNX-305-T01); a play variable outranks anything set in a group.
- [Roles](lesson:LNX-305-T03) package tasks, handlers and templates, so what you write here moves into a role later.
- Secrets used in templates need [Vault](lesson:LNX-305-T04) and `no_log`.
- [ansible-lint](lesson:LNX-305-T06) flags unnamed tasks, short module names, `yes` and risky `shell` use.
- cloud-init user-data accepts Jinja too (LNX-306-T03).

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Service not reloaded after a fixed run | earlier failure skipped the handler | `flush_handlers`, `force_handlers` |
| Brace error on a quoted value | unquoted `{{ }}` at the start of a YAML value | quoting |
| `when` is always true | string not evaluated, or truthy text | `| bool`, 2.19 error message |
| A file changes every run | timestamp or unordered data in the template | `| sort`, `ansible_managed` |
