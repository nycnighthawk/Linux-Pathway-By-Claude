# Idempotence and check mode

This lesson follows the topic synthesis `synth/LNX-305/LNX-305-T07.md`, which carries the history and the sources.

## What you will be able to do

- Recognise tasks that are not idempotent and repair them.
- Preview a run with `--check` and `--diff`, and say what the preview cannot show.
- Test the property on every change.

## The idea

An operation is idempotent when doing it twice leaves the same state as doing it once. Ansible modules describe a target
state (`state: present`), compare it with reality and act only on a difference; the result says `changed` or `ok`. So an
Ansible run is as idempotent as its least careful task. The recap line `changed=0` on a second run is the evidence.

## Where it goes wrong

- `command`, `shell` and `raw` always report `changed` unless you add `creates`, `removes` or `changed_when`.
- Appending (`echo x >> file`) adds a line every run. Use `lineinfile` (with `regexp`) or `blockinfile`, or own the whole file with `template`.
- Time and order: a timestamp in a template, an unsorted list built from a dictionary, a random value. Use `ansible_managed`, `| sort`, fixed seeds.
- `state: latest` on packages changes whenever a repository moves; pin versions in steady-state runs.
- `changed_when: false` hides a real change. Use it only on read-only probes.
- Two tasks that write different values to one setting change it twice every run.

## Check mode

`ansible-playbook site.yml --check` asks modules to report what they would do without doing it; `--diff` adds a before and
after for files (`copy`, `template`, `lineinfile`, `blockinfile`). Per task: `check_mode: false` makes a read-only task
run even in a dry run, `check_mode: true` forces a task to always be a dry run, `diff: false` hides a diff that contains a
secret. The variable `ansible_check_mode` is true during a dry run. A module that does not support check mode is skipped,
so the preview omits it; `command` and `shell` are skipped unless `creates` or `removes` is given. A later task that depends
on the effect of an earlier one (a binary the package would have installed) cannot be previewed honestly: guard it with
`when: not ansible_check_mode` or accept a gap.

## A test routine

1. Run once for real, then run again: the recap must say `changed=0`.
2. Run `--check --diff` on a converged host: nothing predicted. Edit a managed file by hand and run it again: the change is
   predicted and the file is untouched until a real run repairs it.
3. Automate step 1 with the idempotence step of [Molecule](lesson:LNX-305-T06).
4. In production, run a scheduled check run and parse the changed count: that is a drift report (LNX-306-T09).

## Worked example

A play appends `setting=1` with `shell`, renders a motd with the current time, and rebuilds a data directory with `command`.
Run twice: three tasks say `changed`. Replace the append with `lineinfile` (`regexp: '^setting='`, which also repairs
`setting=2`), the time with `{{ ansible_managed }}`, and add `creates: .../PG_VERSION` to the command. A final probe,
`command: cat .../PG_VERSION`, needs `check_mode: false` and `changed_when: false` so `--check` can read it on a fresh host.
Now the second run says `changed=0`.

## How this connects

- Handlers from [playbooks](lesson:LNX-305-T02) fire only on `changed`, so a non-idempotent task causes needless restarts.
- Variable layers from [inventory and precedence](lesson:LNX-305-T01) can make two runs differ if a value depends on a fact.
- Roles from [RHEL System Roles](lesson:LNX-305-T05) are written to be idempotent and to support check mode where they can.
- The same rule appears in other tools: Terraform plan, `kubectl --dry-run`, retry-safe HTTP PUT (see also LNX-306-T05).
- Controller jobs can run in check mode first ([AWX](lesson:LNX-305-T08)).

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Recap never shows `changed=0` | `command` without guard, timestamp | the tasks marked `changed` on run two |
| `--check` fails on a fresh host | a task reads state a skipped task would create | `check_mode: false`, guard with `ansible_check_mode` |
| Preview misses a risky task | module does not support check mode | the `skipping` lines |
| Preview shows no diff for a secret | `diff: false` is on | intentional; verify another way |
