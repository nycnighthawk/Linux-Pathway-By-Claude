# Managing Windows hosts

This lesson follows the topic synthesis `synth/LNX-305/LNX-305-T09.md`, which carries the history and the sources.

## What you will be able to do

- Choose a connection method and an authentication method for Windows nodes.
- Write an inventory group, run `win_ping` and use the main `win_*` modules.
- Name the common failures and the security mistakes to avoid.

## How it differs from Linux

Windows has no Python for Ansible to run, so modules are PowerShell scripts that the control node sends over a remote
connection. Module names carry `win_` and live in the collections `ansible.windows`, `community.windows` and `microsoft.ad`.
The Python modules `command`, `shell`, `copy` and `file` do not work; use `win_command`, `win_shell`, `win_copy`, `win_file`.

## Connecting

| Plugin | Transport | Notes |
|---|---|---|
| `winrm` | WinRM, ports 5985 (HTTP) and 5986 (HTTPS), library `pywinrm` | authentication: kerberos, ntlm, certificate, credssp, basic |
| `psrp` | PowerShell remoting over WinRM, library `pypsrp` | negotiate tries Kerberos then NTLM; usually faster |
| `ssh` | OpenSSH on the Windows host | supported officially from ansible-core 2.18; set `ansible_shell_type` to `powershell` or `cmd` |

```yaml
windows:
  vars:
    ansible_connection: psrp
    ansible_port: 5986
    ansible_psrp_auth: negotiate
    ansible_psrp_cert_validation: validate
    ansible_user: svc-ansible@EXAMPLE.ORG
    ansible_password: "{{ vault_windows_password }}"
```

Prefer Kerberos for domain hosts (no password crosses the network; it needs `krb5` libraries and DNS, and clocks within five
minutes). Over SSH, the connection plugin cannot fetch a Kerberos ticket from a password, so get the ticket first. Use an
HTTPS listener with a certificate your CA issued and keep certificate validation on.

## Modules you will use

`ansible.windows.win_ping` (a full-path test), `ansible.windows.setup` (facts), `win_feature`, `win_service`, `win_package`,
`win_updates` (with `reboot`), `win_reboot`, `win_regedit`, `win_user`, `win_file`, `win_copy`, `win_shell`; and from
collections `chocolatey.chocolatey.win_chocolatey`, `community.windows.win_firewall_rule`, `microsoft.ad.user`. `win_shell`
reports `changed` every time unless you add `changed_when` or a guard, like `shell` ([idempotence](lesson:LNX-305-T07)). In YAML,
backslashes in double quotes are escapes: use single quotes or forward slashes. Escalation is `become_method: runas`.

## Security rules

1. No Basic authentication over HTTP, ever. No `cert_validation: ignore` outside a throwaway lab.
2. CredSSP forwards the user's credentials to the target; prefer Kerberos and constrained delegation, or `become` with
   explicit credentials when a task must reach a second host (the double-hop problem).
3. Scope the automation account to the tier of hosts it manages. A domain administrator account on a shared controller is a
   credential-theft target.
4. Store the password in [Vault](lesson:LNX-305-T04) or the controller's credential store, or avoid it with Kerberos.

## Worked example

`ansible windows -m ansible.windows.win_ping` returns `pong`. A play installs IIS with `win_feature` (`Web-Server`,
`include_management_tools: true`), copies a site, opens a firewall rule and starts a service; the second run says `ok`. If the
run from the controller fails with a Kerberos realm error while it works from your laptop, check three things in order: the
`krb5.conf` inside the execution environment, the DNS answers for the domain, and the clock.

## How this connects

- Hosts and connection variables are inventory data ([T01](lesson:LNX-305-T01)); the group variables select the plugin.
- The control-node prerequisites (pywinrm, pypsrp, Kerberos libraries) belong in an [execution environment](lesson:LNX-305-T03).
- The [controller](lesson:LNX-305-T08) runs mixed Linux and Windows jobs with typed credentials.
- Linux joins to Active Directory use the `ad_integration` system role ([T05](lesson:LNX-305-T05)); time sync matters for Kerberos.
- Windows image builds with Packer are related to LNX-306-T04.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Kerberos error: realm or ticket | missing `krb5.conf`, DNS, clock skew | EE image, resolver, time |
| Access denied on a share | double hop | `become` with credentials |
| Works as admin, fails as service user | UAC filtering of a local account | domain account or `LocalAccountTokenFilterPolicy` |
| Module not found | collection missing | `requirements.yml`, EE |
