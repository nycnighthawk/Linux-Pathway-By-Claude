# Inventories and variable precedence

This lesson follows the topic synthesis `synth/LNX-305/LNX-305-T01.md`, which carries the history and the sources.

## What you will be able to do

- Write an inventory with groups, child groups and per-host connection settings, in YAML.
- Predict which value a host receives when a variable is set in several places, and prove it with `ansible-inventory`.
- Choose the one place where each kind of variable should live.

## Inventory in one page

An inventory lists hosts and arranges them in groups. Two groups always exist: `all` and `ungrouped`. A group can contain
hosts and child groups, and a host can belong to many groups. Connection settings are ordinary variables with reserved names:
`ansible_host`, `ansible_port`, `ansible_user`, `ansible_connection`, `ansible_become`, `ansible_python_interpreter`.

```yaml
all:
  children:
    prod:
      children:
        web: {hosts: {web01: {}, web02: {ansible_host: 10.0.0.12}}}
        db:  {hosts: {db01: {}}}
```

Put data in `group_vars/<group>.yml` and `host_vars/<host>.yml` next to the inventory, not in the host lines. Select hosts
with patterns: `web:db` (union), `web:&prod` (both), `web:!web02` (exclude), and narrow a run with `--limit`.

## Which value wins

Ansible has a fixed ranking of 22 sources, weakest first. The shape matters more than the whole list:

1. role defaults (weakest, built to be overridden);
2. inventory group variables, then playbook group variables, with `all` before specific groups;
3. host variables, which beat every group;
4. facts, then play variables, `vars_files`, and role `vars`;
5. block and task variables, `include_vars`, `set_fact` and registered values;
6. role and include parameters;
7. extra variables from `-e`, which beat everything.

Within one host, groups merge from `all` down: a parent group first, then its children, and among groups at the same depth in
alphabetical order, so the last one wins. `ansible_group_priority` on a group in the inventory source shifts that order (a
higher number is applied later). Dictionaries are replaced, not merged: build a merged value with the `combine` filter.

## Look, do not guess

```bash
ansible-inventory --graph --vars          # the tree and the variables at each level
ansible-inventory --host web02 --yaml     # the merged result for one host
ansible web02 -m ansible.builtin.debug -a var=http_port
```

## Worked example

`group_vars/all.yml` sets `http_port: 80`, `group_vars/prod.yml` sets 8443, `group_vars/web.yml` sets 8080 and
`host_vars/web02.yml` sets 8081. `web01` gets 8080 because `web` is a child of `prod`, and `web02` gets 8081 because a host
beats groups. If `rack_a` and `edge` both set `log_level` and a host is in both, `rack_a` wins today only because its name
sorts later; renaming `edge` to `zone_edge` flips the result. Fix it by defining the variable in one group, or by giving the
group that should win a larger `ansible_group_priority`.

## Rules of thumb

- Define each variable in exactly one layer; if a name appears twice, ask why.
- Defaults go in role `defaults/`; environment data in `group_vars`; exceptions in `host_vars`; emergencies in `-e`.
- Avoid `set_fact` for a value that inventory also supplies: it outranks inventory for the rest of the play. Use a new name.
- Do not keep secrets in plain `group_vars`; see [Vault](lesson:LNX-305-T04).

## How this connects

- [Playbooks and Jinja2](lesson:LNX-305-T02) read these variables; play vars, loops and templates sit higher in the ranking.
- [Roles](lesson:LNX-305-T03) put their tunables in `defaults/` so every layer in this lesson can override them.
- [System roles](lesson:LNX-305-T05) publish their variables as a documented interface that you set from `group_vars`.
- Inventory sources fed by cloud APIs connect to provisioning in LNX-306-T10.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| A host gets the wrong value | same variable in two groups | `ansible-inventory --host`, then the group files |
| `-u` ignored | `ansible_user` set in a group | the group variables |
| A list lost its first items | a specific group replaced the whole list | the group chain of the host |
| Play runs on nothing | an empty dynamic inventory | `ansible-inventory --graph` before the run |

## Self-check

1. Which wins: a group variable or a host variable? An `-e` value or `set_fact`?
2. Two sibling groups define the same variable. Which one applies, and how do you change it?
3. Why does a more specific group not append to a list defined in `all`?
4. What command shows what one host will receive?
