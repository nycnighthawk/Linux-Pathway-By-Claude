# Milestone 4: policy: Pod Security, Kyverno and signed images only

This milestone follows the topic synthesis `synth/LNX-402/LNX-402-T04.md`. Versions and defaults change; confirm them in current project documents (to verify).

## Goal

Allow only least-privilege, approved and signed workloads, with clear refusals.

## Lessons this milestone relies on

- LNX-314-T04 (Pod Security Admission, Kyverno and Gatekeeper)
- LNX-314-T06 (cosign, SBOM, admission checks)
- LNX-310-T08 (supply chain: SBOM, cosign, Trivy)
- LNX-313-T02 (SecurityContext and limits)

## Steps

1. Label namespaces with a Pod Security level; run in warn mode first, then enforce.
2. Write policies for approved registries, no privileged pods and verified signatures.
3. Sign a test image and show that an unsigned one is refused with a readable message.
4. Write tests that apply sample workloads and expect accept or reject; run them in CI.
5. Document every exception with an owner and an expiry.

## Acceptance

- The grader passes on your decision logic.
- The policy tests run in CI and cover at least six cases.
- No exception lacks an owner or expiry.
