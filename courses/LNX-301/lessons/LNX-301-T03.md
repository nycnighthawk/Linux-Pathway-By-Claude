## How it works

Programs ask libc for users with calls such as `getpwnam`. `/etc/nsswitch.conf` lists the sources in order (`files sss`). The `sss` module forwards the request to SSSD over a local socket. Authentication goes the other way: `sshd`, `login` and `sudo` call PAM, whose stacks (auth, account, password, session) include `pam_sss.so`. SSSD owns the network clients, TLS, Kerberos, caching and access policy, so applications never carry LDAP code.

A domain in `sssd.conf` picks four providers independently: `id_provider` (where users come from), `auth_provider` (how passwords are checked), `access_provider` (who may log in) and `chpass_provider`. The file must be mode 0600 and owned by root.

```text
[sssd]
services = nss, pam, ssh, sudo
domains = corp

[domain/corp]
id_provider = ldap
auth_provider = ldap
access_provider = simple
simple_allow_groups = linux-users
ldap_uri = ldaps://ldap1.example.com, ldaps://ldap2.example.com
ldap_search_base = dc=example,dc=com
ldap_tls_cacert = /etc/pki/tls/certs/corp-ca.pem
ldap_tls_reqcert = demand
cache_credentials = true
entry_cache_timeout = 600
enumerate = false
```

`sssctl config-check` validates the file before a restart.

## authselect and the stacks

`authselect select sssd with-mkhomedir` writes the PAM and nsswitch files for a profile plus features; it never configures SSSD itself. Read the stacks for four things. Does `auth` end with `pam_deny.so`? Is `nullok` absent? Does `account` consult `pam_sss.so` with `[default=bad success=ok user_unknown=ignore]`? Does `session` create home directories? A wrong control flag (`sufficient` where `required` belongs) changes who can log in.

## The cache

Lookups are answered from a memory cache, then an on-disk cache, then the server. `entry_cache_timeout` bounds staleness (default 5400 seconds). `cache_credentials` stores a salted hash after an online login so the user can log in offline. After a directory change, `sss_cache -u alice` or `-E` marks entries stale. Enumeration is off by default; `getent passwd` without a name will not list everyone, and scripts must ask by name.

## Worked example

A new engineer exists in the directory but `ssh` says permission denied. `getent passwd erin` works, so identity is fine. `sssctl user-checks erin -a acct -s sshd` reports access denied: `simple_allow_groups` does not include her group. Adding her to `linux-users` and running `sss_cache -u erin` fixes the case in two steps, and nothing about TLS or Kerberos was involved.
