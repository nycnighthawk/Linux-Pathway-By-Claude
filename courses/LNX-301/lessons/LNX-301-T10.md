# Smart-card login

This lesson follows the topic synthesis `synth/LNX-301/LNX-301-T10.md`, which carries the sources and the history.

## What you will be able to do

- Name the layers from reader to PAM: `pcscd`, PKCS#11 module, `p11-kit`, SSSD `p11_child`, PAM.
- Enable smart-card login with `pam_cert_auth` and `authselect` features, and roll out the strict mode safely.
- Write a certificate mapping rule that binds a certificate to exactly one account.
- Use PKINIT to turn one PIN entry into Kerberos single sign-on, and verify each layer.

## The stack

The card sits in a CCID reader. `pcscd` brokers access; a PKCS#11 module (`opensc-pkcs11.so` for most cards, or a vendor library) exposes keys without exporting them; `p11-kit` registers modules. SSSD's `p11_child` helper lists certificates, checks them against the CA bundle and revocation settings, and signs a challenge after the PIN. PAM completes the login. Finally the Kerberos provider can obtain a TGT by PKINIT, so ssh and web access need no further PIN.

## Configuration

```text
[pam]
pam_cert_auth = True
# trust anchors: /etc/sssd/pki/sssd_auth_ca_db.pem
```

`authselect select sssd with-smartcard` allows card or password; `with-smartcard-required` insists on the card; `with-smartcard-lock-on-removal` locks the session when the card leaves. Revocation checking is tuned with `certificate_verification` (`no_ocsp`, `soft_ocsp`); `no_verification` removes the security benefit and should never be a fix.

## Mapping a certificate to a user

In IdM you can store the certificate on the user, or write a rule: a **matching rule** chooses which certificates it handles (`<ISSUER>...`), a **mapping rule** produces an LDAP filter from certificate fields (`{cert!bin}`, `{subject_principal}`). Against AD the filter targets `altSecurityIdentities`, and Windows strong certificate mapping needs explicit values (issuer and serial, or a key identifier). Evaluate a rule without logging in: `sssctl cert-eval-rule` prints the filter that would result.

## Verify layer by layer

```bash
pcsc_scan                                         # reader and card
pkcs11-tool --module opensc-pkcs11.so -L          # token visible
openssl verify -CAfile ca.pem card.pem            # chain
sssctl cert-eval-rule "$CERT" --match=... --map=...   # mapping
sssctl user-checks alice -a auth -s login         # PAM result
klist                                             # PKINIT ticket
```

## Worked example

After a fleet-wide `with-smartcard-required`, one image without the reader driver leaves nobody able to log in. Recovery uses the console break-glass account to run `authselect select sssd`. Lesson: canary first, test break-glass, issue two cards per administrator.
