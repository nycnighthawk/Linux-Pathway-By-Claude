# realmd and adcli joins to a Samba AD DC

This lesson follows the topic synthesis `synth/LNX-301/LNX-301-T04.md`, which carries the sources and the history.

## What you will be able to do

- Explain what a domain join does: discover, authenticate, create a computer account, store a keytab, configure SSSD.
- Provision a Samba AD domain controller in outline and test that it is ready to be joined.
- Join with `realm join`, verify with `getent` and `klist -ke`, and restrict access with `realm permit`.
- Run the four pre-join checks (name, discovery, time, ports) and read the common failures.

## How it works

`realm` is a front end. It discovers the domain through SRV records, picks the packages and client software, and calls `adcli`, which authenticates with the join account, creates the computer object with a random secret and writes the keytab (`host/` principals and `HOSTNAME$`). `realm` then writes `sssd.conf` with `id_provider = ad`, and calls `authselect`. SSSD later rotates the machine password on a schedule.

```bash
realm discover ad.example.com
realm join -v -U administrator --computer-ou='OU=Linux,DC=ad,DC=example,DC=com' ad.example.com
realm list
getent passwd alice@ad.example.com
realm permit -g linux-users@ad.example.com
```

## Samba on the server side

`samba-tool domain provision --use-rfc2307 --realm=AD.EXAMPLE.COM --domain=AD --server-role=dc --dns-backend=SAMBA_INTERNAL` creates the domain. `--use-rfc2307` adds the POSIX attributes to the schema. Copy the generated `krb5.conf`, start `samba-ad-dc`, then check `host -t SRV _ldap._tcp.ad.example.com`, `kinit administrator` and `samba-tool domain level show`. Samba has no Windows-style global catalog, so SSSD falls back to port 389.

## The checks that decide most failures

1. **Name.** `hostname -f` must be a fully qualified name inside the domain, the first label at most 15 characters, and not mapped to `127.0.1.1`.
2. **Discovery.** The resolver must serve the AD zone; `dig +short SRV _ldap._tcp.dc._msdcs.ad.example.com` must answer.
3. **Time.** Kerberos tolerates five minutes; stay far below that.
4. **Ports.** DNS 53, Kerberos 88 and 464, LDAP 389 (and 3268 against a Windows forest), SMB 445.

## ID mapping decision

`ldap_id_mapping = True` (default) computes UIDs from SIDs, so every SSSD host agrees. `False` reads `uidNumber` from the directory, which suits a Samba DC provisioned with RFC 2307. Decide once; changing it renumbers users ([ID mapping and sssctl](lesson:LNX-301-T08)).

## Worked example

`realm join` stops with `KDC has no support for encryption type`. The client policy no longer allows RC4 and the join account has no AES keys. Prefer fixing the server side: reset the account password (which generates AES keys) before lowering the client crypto policy. If an old trust or DC forces RC4, `update-crypto-policies --set DEFAULT:AD-SUPPORT` is the documented but weaker workaround.
