## LUKS2 in one page

A LUKS2 header stores a random **master key** encrypted separately under each key slot. A passphrase unlocks a slot, the slot yields the master key, and the master key encrypts the data. That is why you can change a passphrase without re-encrypting the disk, and why up to 32 slots can coexist.

```bash
cryptsetup luksFormat --type luks2 /dev/vdb          # argon2id key derivation by default
cryptsetup luksDump /dev/vdb                         # segments, keyslots, tokens, digests
cryptsetup luksAddKey /dev/vdb                       # add a slot
cryptsetup luksHeaderBackup /dev/vdb --header-backup-file hdr.img   # keep it offline
cryptsetup open /dev/vdb data                        # appears as /dev/mapper/data
```

Boot-time opening goes through `/etc/crypttab`: `data UUID=... none luks,discard,tries=3`. Add `_netdev` when the key needs the network. Argon2 costs are calibrated on the machine that creates a slot; a slot made on a large host can be too memory-hungry for a small VM.

## Releasing the key automatically

| Policy | Released when | Defeated by |
|---|---|---|
| TPM2 sealed to PCRs | the boot measurements match | an attacker who boots the genuine software, or sniffs an unprotected TPM bus |
| Tang (network-bound) | the machine can reach the server | an attacker who puts the stolen machine on your network |
| `sss` threshold | any *t* of *n* sub-policies succeed | needs *t* of its parts to fail |
| Recovery passphrase | a person types it | losing it; keep it in a vault |

**TPM with systemd:** `systemd-cryptenroll --tpm2-device=auto --tpm2-pcrs=7 /dev/vdb` seals a new random key. PCR 7 records the Secure Boot state, so the binding survives kernel and bootloader updates. Adding `--tpm2-with-pin=yes` demands a PIN as well.

**Tang with Clevis:** a Tang server keeps no client state; the client and server derive the key by an exchange that the server never sees the result of.

```bash
clevis luks bind -d /dev/vdb tang '{"url":"http://tang.example"}'   # compare the thumbprint with tang-show-keys
clevis luks list -d /dev/vdb
clevis luks bind -d /dev/vdb sss '{"t":2,"pins":{"tang":[{"url":"http://t1"},{"url":"http://t2"}],"tpm2":{"pcr_ids":"7"}}}'
```

With that threshold a stolen machine fails (it reaches neither server), one server outage does not stop boot, and a firmware change that spoils the TPM policy is covered by the network. The initramfs needs the network for Tang: on dracut systems install the Clevis module and pass `rd.neednet=1` plus addressing on the kernel command line.

## Practising with swtpm

```bash
swtpm_setup --tpm2 --tpmstate dir=/tmp/vtpm --createek
swtpm socket --tpm2 --tpmstate dir=/tmp/vtpm --ctrl type=unixio,path=/tmp/vtpm/sock &
qemu-system-x86_64 ... -chardev socket,id=c,path=/tmp/vtpm/sock -tpmdev emulator,id=t,chardev=c -device tpm-tis,tpmdev=t
```

Inside the guest, `tpm2_pcrread` and `systemd-cryptenroll --tpm2-device=list` show what it sees. A software TPM is a test double: anyone with host access can read it.

## Worked example: why the fleet stopped

Two hundred servers were bound to PCRs 0, 2, 4 and 7. A bootloader update changed PCR 4, so every host stopped at a passphrase prompt. Recovery meant typing each recovery passphrase and re-binding. The fix is a policy that names the authority (PCR 7, or a signed policy) instead of every component, a threshold with Tang, and a rehearsal of the next update on one host first. A second trap: the Tang server itself lived on an encrypted datastore that needed Tang. A cold-start order and a TPM-only slot for the Tang host breaks the loop.
