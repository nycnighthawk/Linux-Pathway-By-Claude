# Linux forensics basics

This lesson follows the topic synthesis `synth/LNX-303/LNX-303-T10.md`, which carries the sources, the history and the failure cases.

## What you will be able to do

- Apply the order of volatility on a suspect Linux host.
- Run a short live triage that does not trust the host's own tools.
- Find persistence mechanisms and build a timeline.
- Image a disk and memory, and mount the copy safely.

## Four rules

1. **Preserve.** Change as little as possible; analyse copies, mount read-only.
2. **Document.** Keep a timestamped log of every command and hash everything you collect.
3. **Volatility first.** Memory, network state and processes before disk; disk before backups.
4. **Distrust the host.** A rootkit can filter what `ps` and `ls` show. Use static tools from read-only media, or analyse an image and a memory dump.

Contain by cutting the network at the switch or firewall, which stops exfiltration and keeps memory and processes. Do not power off, do not reboot, do not "clean up".

## Live triage

Send every output to external storage, not the suspect disk.

```bash
date; uptime; uname -a; who; w; last | head
ps auxwwf                       # odd parents, paths in /tmp or /dev/shm, fake kernel-thread names
ss -tanp; ss -tulpen            # connections with owning processes
lsof -nP +L1                    # open files that were deleted from disk
cp /proc/PID/exe /evidence/     # recover a deleted running binary
lsmod; ls /sys/module           # compare for hidden modules
```

## Where attackers persist

Cron (`/etc/cron*`, `/var/spool/cron`), systemd units and timers, `rc.local`, shell start-up files, `~/.ssh/authorized_keys` (and `AuthorizedKeysCommand`), `/etc/ld.so.preload`, PAM modules, `modules-load.d`, accounts with UID 0, setuid files (`find / -xdev -perm -4000`). Verify packaged files with `rpm -Va` or `debsums -c`, remembering that a root attacker can change the database too.

## Timeline

Files carry mtime, atime, ctime and, on ext4 and XFS, a birth time. Users can set mtime with `touch -d`, but not ctime, so a mismatch is a clue. `fls -m / -r image > body; mactime -b body -d` builds a timeline from an image; Plaso merges file times with logs. Record the host's clock offset at acquisition.

## Acquisition

```bash
sha256sum /dev/sdX                                   # then image with ddrescue or dc3dd, which log errors
avml /evidence/mem.lime                              # memory; or LiME built for the exact kernel
losetup -rP /dev/loop0 sdX.img
mount -o ro,noload,nodev,noexec,noatime /dev/loop0p1 /mnt/evidence
```

Memory analysis with Volatility 3 needs symbols for the exact kernel; a difference between `linux.pslist` and `linux.psscan` can expose hidden processes. For encrypted volumes the key is in memory, so capture it before shutdown. For VMs and cloud, snapshot from outside the guest.

## Worked example: deleted but running

`lsof +L1` shows PID 4242 running `/tmp/.x (deleted)`, and `ss` shows that process connected to a remote address. Kill nothing yet. Copy `/proc/4242/exe` to evidence storage, hash it, record the connection, capture memory, then image the disk. Killing the process or rebooting first would have destroyed the only copy of the implant and the key to the network infrastructure behind it.
