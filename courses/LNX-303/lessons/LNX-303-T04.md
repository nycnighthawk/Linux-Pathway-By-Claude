## Three mechanisms, three jobs

| Mechanism | Job | Where the reference lives |
|---|---|---|
| IMA measurement | record a hash of each file used, extend it into TPM PCR 10 | the kernel log in `/sys/kernel/security/ima/ascii_runtime_measurements` |
| IMA appraisal | refuse access when a file's hash or signature does not match | `security.ima` extended attribute |
| EVM | protect the attributes (`security.ima`, SELinux label, mode, owner) so they cannot be edited offline | `security.evm`, an HMAC or a signature |
| Lockdown | stop root from bypassing the above by changing the running kernel | none; it is a kernel policy |

Appraisal with locally generated hashes (`ima_appraise=fix`) stops offline edits but not a root attacker who writes files while the system runs, because the kernel rebuilds the hash. **Signatures** made with a key that is not on the machine are the strong form; `evmctl ima_sign --key key.pem FILE` writes one, and RPM can carry them through `rpm-plugin-ima`.

## Policy: first match wins

```
dont_measure   fsmagic=0x9fa0            # procfs
dont_measure   fsmagic=0x1021994         # tmpfs
dont_appraise  fsmagic=0x9fa0
measure        func=BPRM_CHECK           # programs being executed
measure        func=MMAP_CHECK mask=MAY_EXEC
appraise       func=BPRM_CHECK appraise_type=imasig
appraise       func=MODULE_CHECK appraise_type=imasig
```

Exclusions come first. Do not appraise `FILE_CHECK` for all reads: the init system then cannot read its own unit files, which carry no signature, and the machine stops in the initramfs. Kernel parameters pick the mode: `ima_appraise=off|log|fix|enforce`, `ima_hash=sha256`, `ima_policy=tcb`.

## A staged rollout

1. Build or sign files at image or package time.
2. Load the IMA certificate into the `.ima` keyring.
3. Boot with `ima_appraise=log`; read the kernel and audit logs for would-be denials.
4. Fix exceptions, exclude mutable paths (`/var`, `/home`, `/tmp`), mount scratch areas `noexec`.
5. Switch to `enforce` on a canary host, then the fleet. Keep a controlled recovery path.

## Lockdown

`/sys/kernel/security/lockdown` shows `none [integrity] confidentiality`. **Integrity** blocks `/dev/mem`, unsigned modules, unsigned `kexec`, hibernation and similar; **confidentiality** also blocks reading kernel memory, which limits some tracing tools. The level can be raised at runtime but never lowered. Many distributions set `integrity` automatically when Secure Boot is on.

## Worked example: the script bypass

Policy appraises executables. An attacker runs `python3 /dev/shm/x.py`. The kernel sees only the signed interpreter being executed, so the script runs. Mitigations: mount `/dev/shm` and `/tmp` with `noexec`, remove interpreters from hosts that do not need them, use a path- or hash-based allow list such as `fapolicyd` for scripts, and opt in to interpreter script checks where your kernel and interpreter support them (to verify). IMA is one layer, not a sandbox.
