## What a certificate says

A certificate is a signed statement: this key belongs to this subject, for these uses, until this date. The extensions carry the meaning that matters in practice.

| Extension | What it controls |
|---|---|
| Basic Constraints | whether the subject may act as a CA, and `pathlen`, how many CA levels may sit below it |
| Key Usage / Extended Key Usage | permitted purposes: signing, key agreement, `serverAuth`, `clientAuth`, code signing |
| Subject Alternative Name | the DNS names, IPs, emails or URIs the certificate is valid for; clients ignore the common name when a SAN is present |
| Name Constraints | the namespaces an intermediate may issue for |
| CRL Distribution Points, Authority Information Access | where the revocation list and the OCSP responder are, and where the issuer certificate can be fetched |

A client builds a path from the certificate it was given to a **trust anchor** it already holds, and checks signature, dates, constraints and revocation at every link. A server must send its leaf and its intermediates, never the root.

## A two-tier CA with OpenSSL

Keep the root offline and sign day-to-day certificates with an intermediate.

```bash
openssl genpkey -algorithm EC -pkeyopt ec_paramgen_curve:P-256 -out inter.key
openssl req -new -key inter.key -subj "/O=Example/CN=Example Intermediate CA" -out inter.csr
openssl x509 -req -in inter.csr -CA root.pem -CAkey root.key -CAcreateserial \
  -days 1825 -extfile ca.cnf -extensions v3_inter -out inter.pem
openssl verify -CAfile root.pem inter.pem
```

The `v3_inter` section sets `basicConstraints=critical,CA:TRUE,pathlen:0` and `keyUsage=critical,keyCertSign,cRLSign`. With `pathlen:0` the intermediate can sign leaves but not further CAs. For leaves, `openssl ca` is worth its configuration file, because it keeps a database (`index.txt`), a serial counter and revocation state:

```bash
openssl ca -config ca.cnf -batch -notext -in app.csr -out app.pem
openssl ca -config ca.cnf -revoke app.pem -crl_reason keyCompromise
openssl ca -config ca.cnf -gencrl -out crl.pem
openssl crl -in crl.pem -noout -text            # serials, reasons, nextUpdate
openssl verify -crl_check -CAfile root.pem -untrusted inter.pem -CRLfile crl.pem app.pem
```

## Revocation: CRL, OCSP, stapling

- A **CRL** is a signed list of revoked serial numbers with a `nextUpdate` time. It works offline and grows until entries expire. If the CRL goes stale, strict clients reject every certificate from that issuer.
- **OCSP** answers for one serial: good, revoked or unknown. It is small, but the responder sees which sites clients visit, and many clients accept the certificate if no answer arrives (soft fail).
- **Stapling** lets the server fetch and attach a fresh signed response. `openssl s_client -connect host:443 -status` shows whether one arrived. **Must-Staple** makes a missing response fatal.
- **Short lifetimes** avoid the problem: a certificate valid for days needs no revocation. ACME automation (certbot, lego, step-ca) makes this practical.

## Trust stores on Linux

On Enterprise Linux, copy a PEM file to `/etc/pki/ca-trust/source/anchors/` and run `update-ca-trust`. On Debian and Ubuntu, copy a `.crt` file to `/usr/local/share/ca-certificates/` and run `update-ca-certificates`. Java, Firefox and Python's `certifi` keep separate stores. PAM smart-card settings take policies such as `crl_auto` and `ocsp_on`; STIG-style rules require a local cache of revocation data so that login works offline without ignoring revocation. FreeIPA's CA generates its CRL on one designated server, and retiring that server without moving the role stops CRL updates.

## Worked example: why the script fails but the browser works

A service sends only its leaf. Browsers succeed because they cache intermediates or fetch them through Authority Information Access; `curl` in a minimal container reports an unknown issuer. Run `openssl s_client -connect host:443 -showcerts`: one certificate appears. The fix is on the server, which must send leaf plus intermediate. Test with `openssl verify -CAfile root.pem -untrusted inter.pem leaf.pem`, which fails without the intermediate and passes with it.
