# Drift detection and secure wipe

This lesson follows the topic synthesis `synth/LNX-306/LNX-306-T09.md`, which carries the sources, the history and the failure cases.

## What you will be able to do

- Define drift and detect it with file-integrity tools, configuration-management check mode and package verification.
- Decide what to do with a difference: reconcile, absorb or investigate.
- Choose a sanitisation method for disks, SSDs, NVMe and encrypted volumes, and verify it.
- Keep the records that make a wipe auditable.

## Drift

Drift is the gap between the recorded intended state of a host and its actual state.

| Tool | What it compares | Notes |
|---|---|---|
| AIDE | files against a hash database | update the database after approved changes; protect it |
| IMA | file hashes against extended attributes | can also enforce policy |
| Ansible `--check --diff` | declared state against the host | blind to non-idempotent tasks |
| `rpm -Va` / `debsums` | installed files against the package | finds hand edits |
| OpenSCAP | configuration against a profile | compliance drift |

Responses: **reconcile** (restore), **absorb** (put the change in code and baseline), **investigate** (unexplained: keep evidence first).

## Sanitisation

Levels (NIST SP 800-88 terms): clear, purge, destroy.

| Medium | Method |
|---|---|
| Magnetic disk | one full overwrite (`shred -n 1 -z`), or ATA secure erase |
| SATA SSD | device sanitise or `blkdiscard --secure` where supported; host overwrite is unreliable |
| NVMe | `nvme sanitize` (block erase, crypto erase) or `nvme format` with secure erase |
| LUKS volume | `cryptsetup erase` removes all key slots (cryptographic erase) |
| Cloud | encrypt with your own keys and delete them; rely on the provider for media |

Always verify: read back zeros (`cmp /dev/zero DEVICE`), check `cryptsetup luksDump` shows no key slots, or read the drive's sanitise log.

## Records

Asset tag, serial number, medium, method, tool and version, operator, approver, date, verification result. Without the record the work cannot be proved.

## Safety rules for wipe scripts

- Address devices by serial number or `/dev/disk/by-id`, never by a name like `sda`.
- Refuse mounted devices and the root device.
- Require the operator to type the serial number.
- Log before and after.

## Worked example: swapped names

A script wiped `/dev/sdb`, a retired data disk the day before and the boot disk of another host after the controller order changed. The fix: resolve devices by serial number and refuse mounted ones.
