# Real BMC firmware

This lesson follows the topic synthesis `synth/LNX-306/LNX-306-T11.md`, which carries the sources, the history and the failure cases.

## What you will be able to do

- Identify BMC and platform firmware versions and the update path for a model.
- Plan a staged firmware campaign with a sacrificial test machine, a pilot, waves and a stop rule.
- Explain the trust chain: signed updates, Secure Boot, roots of trust.
- Say what emulators cannot teach and why this topic needs real hardware.

## Why it is different from the simulation

Real firmware is vendor-specific, an interrupted update can leave the BMC unresponsive, and the BMC is the tool you would use to repair it. Some boards keep two images and fall back; others do not, so read the vendor's documentation for your model before you flash.

## Vendor tools

Dell `racadm`, HPE `ilorest`, Supermicro update manager, Lenovo `OneCLI`/XClarity; Redfish offers an update service and firmware inventory; `fwupd` covers UEFI capsule updates for many devices.

## General rules

1. Download only from the vendor's support site; verify the checksum or signature.
2. Read the release notes.
3. Stable power or a UPS; never reboot or power off during the update.
4. Back up the configuration.
5. Keep a console open (serial-over-LAN or remote KVM).

## The campaign

Classify by model and version → test on a sacrificial machine → pilot a few → waves of growing size with a check after each → stop on any failure → update the inventory.

After each update check the version, the network settings, the accounts (no default account), the event log and power control, and re-run the security checks.

## Trust

Verify and authenticate every update before applying it, and restrict who can start one. Secure Boot extends the chain to the boot loader and kernel (`mokutil --sb-state`). Record firmware versions and Secure Boot state as part of the host baseline.

## Worked example: the whole rack

Forty BMCs updated at once fell off the network because the new version reset them to DHCP on a VLAN without a DHCP server. A pilot and waves would have cost only the pilot group.
