# Foreman/MAAS bare metal

This lesson follows the topic synthesis `synth/LNX-306/LNX-306-T06.md`, which carries the sources, the history and the failure cases.

## What you will be able to do

- Describe the lifecycle of a physical server and the platform pieces that manage it.
- Compare Foreman (host lifecycle manager) with MAAS (machine allocator) and name the alternatives.
- Design the safeguards around a provisioning platform: build mode, BMC security, access and recovery.
- Decide where the platform stops and infrastructure as code or configuration management begins.

## The lifecycle

racked → discovered or enrolled → prepared (firmware, RAID, tests, BMC credentials) → ready → assigned and deployed → in service → released, wiped, reused or retired.

## Two platforms

| | Foreman (with Katello, or Satellite) | MAAS |
|---|---|---|
| Model | host lifecycle: the host keeps an OS and role that the tool tracks | pool of machines: allocate, deploy, release |
| Pieces | smart proxies (DHCP, DNS, TFTP, BMC), host groups, ERB templates, compute resources | region and rack controllers, commissioning images |
| Discovery | discovery image reports facts | enlist, then commission (hardware tests) |
| Installer | Kickstart, preseed, AutoYaST templates | Curtin plus cloud-init |
| Scripting | `hammer`, API, Ansible and Terraform | `maas` CLI, API, Terraform, Juju |

Others: OpenStack Ironic and Metal³ for clouds and clusters, Tinkerbell, Matchbox, and FIDO Device Onboard for edge devices.

## Safeguards

1. Build mode is a state, off by default, switched on by an approved action and off after the first successful install.
2. BMC network isolated; default credentials changed; secrets in a vault and rotated.
3. DHCP snooping so that a second DHCP server cannot answer.
4. Templates in version control; installation source pinned to a snapshot.
5. Role-based access: viewing is not reinstalling. Audit log.
6. Platform backup and a tested rebuild.

## Where the platform stops

The platform owns physical machines and their lifecycle; infrastructure as code owns logical resources; configuration management owns what runs inside. Each calls the others through APIs.

## Worked example: the double DHCP

A test lab on the provisioning VLAN answered DHCP. Machines did not reinstall because the platform's state said "boot from disk", but some lost network configuration until DHCP snooping was enabled.
