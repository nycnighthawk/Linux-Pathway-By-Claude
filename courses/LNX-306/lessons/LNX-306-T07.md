- Practise without hardware, using mock services and emulators.

## Concepts

A BMC is a small computer on the server board with its own network port, firmware and accounts. It works when the host is off, so it can power the machine, show the console and mount virtual media. That makes it the foundation of unattended provisioning, and also a prime target.

| | IPMI | Redfish |
|---|---|---|
| Transport | binary messages over UDP 623 (RMCP+ for version 2.0) | HTTPS with JSON |
| Client | `ipmitool`, FreeIPMI | `curl`, any HTTP library, `sushy` |
| Scope | power, sensors, event log, serial-over-LAN | all of that plus inventory, BIOS settings, firmware update, accounts, events |
| Weak points | RAKP hash disclosure, cipher suite 0, UDP | vendor differences, old TLS, default accounts |

## IPMI with ipmitool

```bash
export IPMI_PASSWORD=...        # never put passwords on the command line
ipmitool -I lanplus -H bmc01 -U admin -E chassis power status
ipmitool -I lanplus -H bmc01 -U admin -E chassis bootdev pxe options=efiboot
ipmitool -I lanplus -H bmc01 -U admin -E chassis power cycle
ipmitool -I lanplus -H bmc01 -U admin -E sol activate
```

The boot device is one-time unless you add `options=persistent`. Provisioning wants one-time.

## Redfish with curl

```bash
sys=https://bmc01/redfish/v1/Systems/1
curl -sf --cacert bmc-ca.pem -u "$U:$P" "$sys"
curl -sf --cacert bmc-ca.pem -u "$U:$P" -X PATCH -H 'Content-Type: application/json' \
     -d '{"Boot":{"BootSourceOverrideTarget":"Pxe","BootSourceOverrideEnabled":"Once"}}' "$sys"
curl -sf --cacert bmc-ca.pem -u "$U:$P" -X POST -H 'Content-Type: application/json' \
     -d '{"ResetType":"ForceRestart"}' "$sys/Actions/ComputerSystem.Reset"
```

Do not assume `Systems/1`: list `/redfish/v1/Systems`. Read the allowable values from the resource itself, because vendors differ.

## Hardening checklist

1. Put BMCs on an isolated management network; never expose them to the internet.
2. Change default credentials, give each machine its own secret, rotate and keep it in a vault.
3. Disable IPMI over LAN if Redfish suffices; if not, use cipher suite 17 (RAKP-HMAC-SHA256 with AES-128) where the BMC offers it, and no null authentication. Some BMCs advertise suite 17 but do not implement it, so check `ipmitool lan print` and test with `-C 17`.
4. Keep BMC firmware current; check time and logging.
5. Verify the target before any power command; automation must use one authoritative inventory.

## Worked example: the wrong host

A script took the BMC address from a stale spreadsheet and sent a restart to a database server instead of the intended spare. The fix: read the BMC address from the platform inventory, check the serial number against the Redfish resource before acting, and require an explicit confirmation flag for anything that is not a spare.
