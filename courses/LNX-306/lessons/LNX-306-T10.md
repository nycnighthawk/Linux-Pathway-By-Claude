# Cloud provisioning

This lesson follows the topic synthesis `synth/LNX-306/LNX-306-T10.md`, which carries the sources, the history and the failure cases.

## What you will be able to do

- Explain how a cloud instance gets its operating system, its identity and its configuration.
- Prepare an image for a platform and choose between a golden image and bootstrap at first boot.
- Use the metadata service safely and give machines narrow roles instead of stored keys.
- Describe a fleet as code and roll out a new image.

## The four questions

1. **Which image?** From your own pipeline, not an unknown public listing.
2. **How does it learn who it is?** The first-boot agent (cloud-init, or Ignition for immutable systems) reads the platform's metadata and user data.
3. **How does it prove who it is?** A role bound to the instance by the platform; short-lived tokens, no stored keys.
4. **How is it described?** As code, in a reviewed plan, with remote locked state.

## Preparing an image

Install the first-boot agent and the platform's guest drivers and daemons, select the datasource, enable reporting, put swap only on the ephemeral disk (it is lost on deallocation), and test by launching an instance and reading the console and cloud-init logs. Image formats and boot modes differ by cloud, so check the provider's image import documentation.

## Metadata service

A link-local address serves identifiers, user data and temporary credentials. It is a prime target for server-side request forgery.

- Require tokens (on Amazon, the second-generation service).
- Block containers on a node from the address with network policy.
- Give the instance role the minimum permissions.
- Never put secrets in user data; fetch them from a secret manager at runtime.

## Fleets

Groups (auto scaling groups, managed instance groups, scale sets) create machines from a template that names an image. A new image is a template change followed by a rolling replacement. Nodes must register themselves.

## Worked example: the leaked role

A request-forgery flaw let an attacker fetch role credentials from the metadata address. Fix: require tokens, shrink the role to one bucket and one action, filter egress, alert on credentials used from outside the cloud.

## Self-check

2. What is stored on the ephemeral disk, and what should be?
3. Why are secrets kept out of user data?
4. How does an instance role replace a stored key?
5. How do you roll out a new image to a group?
