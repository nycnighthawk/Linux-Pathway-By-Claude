# Kickstart, preseed, autoinstall

This lesson follows the topic synthesis `synth/LNX-306/LNX-306-T01.md`, which carries the sources, the history and the failure cases.

## What you will be able to do

- Read and write a Kickstart file, a Debian preseed file and an Ubuntu autoinstall file.
- Limit destruction to the intended disk and keep secrets out of answer files.
- Deliver an answer file to an installer and validate it before use.
- Decide what belongs in the installer and what belongs in configuration management.

## Three formats

| | Kickstart | Preseed | Autoinstall |
|---|---|---|---|
| Installer | Anaconda | Debian installer (debconf) | Subiquity |
| Style | commands and `%sections` | answers to named questions | YAML in cloud-init user-data |
| Delivery | `inst.ks=URL`, `OEMDRV` volume, embedded in ISO | `auto url=URL`, initrd, media | `autoinstall ds=nocloud-net;s=URL`, `cidata` volume |
| Validate | `ksvalidator` | `debconf-set-selections --checkonly` | JSON schema check by the installer |

```
ignoredisk --only-use=vda
clearpart --all --initlabel --drives=vda
rootpw --lock
sshkey --username=ops "ssh-ed25519 AAAA..."
%post --log=/root/ks-post.log
...
%end
```

## Safety rules

1. Name the disk (`ignoredisk --only-use`, `clearpart --drives`, `partman-auto/disk`, an explicit `storage` section). An unattended wipe takes every disk it can see.
2. Lock root and use keys; never a plaintext password, and a hash only for a single-use bootstrap credential.
3. Install from a pinned repository snapshot, enable SELinux or AppArmor and the firewall, and keep the package set minimal.
4. Log `%post` and late commands; a script that fails silently leaves a half-configured host.

## What belongs where

The answer file does what only an installer can: disk layout, minimal packages, first account, network for first contact, repository, and a hand-over hook. Everything repeatable (services, users, applications) goes to configuration management. A file with hundreds of lines of shell is a role waiting to be written.

## Test in CI

Validate the syntax, install into a virtual machine with a serial console and a timeout, then log in and assert: partition layout, SELinux mode, services, a clean `%post` log. Test hardware differences (disk names, UEFI versus BIOS) separately.

## Worked example: the wiped data disk

`clearpart --all` with no drive filter erased a RAID volume of data on a storage server. Fix: an `ignoredisk` filter, a `%pre` check that refuses to continue when it sees more disks than expected, and masked data disks during reinstall.

## Self-check

1. Why does `rootpw --lock` plus `sshkey` beat a plaintext root password?
2. What does `clearpart --all` do without `--drives`?
3. Which boot argument tells Anaconda where its Kickstart file is?
4. Why does preseed timing matter for network questions?
5. What should a `%post` hand over to?
