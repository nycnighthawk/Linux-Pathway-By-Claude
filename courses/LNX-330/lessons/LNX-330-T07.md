# KUnit (UML)

This lesson follows the topic synthesis `synth/LNX-330/LNX-330-T07.md`. Script options and macro names change; check `Documentation/dev-tools/kunit/` in your tree (to verify).

## What you will be able to do

- Write a KUnit case, suite and registration.
- Choose between `EXPECT` and `ASSERT`, and write table-driven tests.
- Run tests with `kunit.py` on UML, with a `.kunitconfig`.
- Judge a test suite by whether it catches wrong code.

## Anatomy

```c
static void parse_ok(struct kunit *test)
{
	KUNIT_EXPECT_EQ(test, foo_parse("42"), 42);
}

static struct kunit_case foo_cases[] = {
	KUNIT_CASE(parse_ok),
	{}
};
static struct kunit_suite foo_suite = {
	.name = "foo",
	.test_cases = foo_cases,
};
kunit_test_suite(foo_suite);
```

- A Kconfig option depends on `KUNIT` and defaults to off.
- `KUNIT_EXPECT_*` records a failure and continues. `KUNIT_ASSERT_*` stops the case: use it when later lines would crash, such as after a failed allocation.
- `kunit_kzalloc` memory is freed automatically at the end of the case.
- `KUNIT_CASE_PARAM` runs one body over a table of inputs and reports each row.
- Tests may `#include` the `.c` file under test to reach static functions.

## Running

```
./tools/testing/kunit/kunit.py run --kunitconfig=lib/.kunitconfig
./tools/testing/kunit/kunit.py run 'foo*'
./tools/testing/kunit/kunit.py run --arch=x86_64 --raw_output
```

UML (`ARCH=um`) runs the kernel as a normal process, which makes the loop fast. `--arch` switches to QEMU for architecture code. Output is TAP: `ok N name` or `not ok N name` with the file, line and values.

## Good tests

- One behaviour per case, named after it.
- Boundaries and error paths, not only the happy path.
- No dependence on timing, hardware or global state.
- Check the exact value, not a vague property.

A suite is only useful if breaking the code makes it fail. Try a deliberate bug and see.

## Where KUnit stops

UML has no real hardware. Tests of device behaviour, user-space interfaces or timing belong in a QEMU or board test, or in kselftest (next topic).
