# checkpatch, get_maintainer, sparse and Coccinelle

This lesson follows the topic synthesis `synth/LNX-330/LNX-330-T05.md`. Options evolve; run each script with `--help` in your tree (to verify).

## What you will be able to do

- Run `checkpatch.pl` on a patch, a commit and a file, and decide which findings to act on.
- Find the right recipients with `get_maintainer.pl` and explain its `MAINTAINERS` rules.
- Use sparse (`C=1`, `C=2`) to catch byte-order and address-space errors.
- Run and read a Coccinelle check with `make coccicheck`.

## checkpatch

```
scripts/checkpatch.pl --strict 0001-fix.patch
scripts/checkpatch.pl --git HEAD~3..HEAD
scripts/checkpatch.pl -f drivers/foo/bar.c
```

Levels: ERROR, WARNING, CHECK (CHECK only with `--strict`). `--fix-inplace` repairs simple style issues; always review the diff afterwards. It matches patterns per line and does not parse C, so it gives false positives. Ignore a message when surrounding code or the subsystem says so, and tell the reviewer why. Never post patches whose only purpose is to silence it.

## get_maintainer

```
scripts/get_maintainer.pl 0001-fix.patch
scripts/get_maintainer.pl --no-git -f drivers/foo/bar.c
```

`MAINTAINERS` sections: `M:` maintainer, `R:` reviewer, `L:` list, `S:` status, `F:` files, `X:` exclusions. `F:` with a trailing `/` covers a tree; `*` stays inside one directory level. A file may match several sections. Put maintainers in `To`, lists in `Cc`. Status `Orphan` means nobody owns the code, so use the list.

## sparse

```
make C=1    # check recompiled files
make C=2    # check every file
```

Typical messages: different base types (byte order), different address spaces (user vs kernel pointer), context imbalance (locks). Fix with `le32_to_cpu`, `copy_from_user`, a matching unlock. `__force` documents an intentional cast.

## Coccinelle

```
make coccicheck MODE=report
make coccicheck MODE=patch COCCI=scripts/coccinelle/api/foo.cocci M=drivers/foo
```

A semantic patch uses `-` and `+` lines like a diff, with metavariables for expressions and identifiers and `...` for code in between. Its strength is changing many call sites consistently; the rule goes in the commit message so reviewers read the rule, not every hunk.

## Routine before posting

1. Build with `W=1` and `C=1`. 2. `coccicheck` on the directory. 3. `checkpatch --strict` on every commit. 4. `get_maintainer` on every patch of the series.
