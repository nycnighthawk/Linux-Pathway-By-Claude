# Kconfig, defconfig, localmodconfig and cross-compiling

This lesson follows the topic synthesis `synth/LNX-330/LNX-330-T02.md`. Config target names and the default assembler differ between kernel versions; check `make help` in the tree you build (to verify).

## What you will be able to do

- Read a Kconfig entry and predict whether a symbol can be set.
- Build a small configuration from `defconfig` plus a fragment, and verify the result.
- Explain why a requested symbol can vanish from the final `.config`.
- Cross-compile for another architecture with `ARCH`, `CROSS_COMPILE` or `LLVM=1`.

## Kconfig in one screen

```
config VIRTIO_BLK
	tristate "Virtio block driver"
	depends on BLOCK
	select VIRTIO
```

- `depends on` makes the symbol available only if the expression is true; otherwise it is forced to `n`.
- `select` forces another symbol on and ignores that symbol's own dependencies. Use it only for promptless symbols.
- `imply` is a weak `select`. A symbol with no prompt cannot be set by the user at all.
- Types: `bool`, `tristate` (`y`, `m`, `n`), `int`, `hex`, `string`.

A `.config` holds `CONFIG_X=y`, `=m`, a value, or `# CONFIG_X is not set`.

## Targets

| Command | Use |
|---|---|
| `make defconfig` | architecture default |
| `make savedefconfig` | minimal config with only non-default symbols |
| `make olddefconfig` | update a config, defaults for new symbols |
| `make localmodconfig` | keep only the modules loaded now (fast builds, only for this machine) |
| `make kvm_guest.config` | merge a named fragment from `kernel/configs/` |
| `make allmodconfig`, `randconfig` | build-test extremes |

## Fragments

A fragment lists only the lines you need. Merge with `scripts/kconfig/merge_config.sh -m .config frag.config`, then `make olddefconfig`. If a requested symbol's dependencies are not met it is **dropped silently**, apart from a warning (a `Value requested…` warning). Always check that every requested symbol is in the final file; treat the warning as a failure.

## Cross-compiling

```bash
make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- O=build/arm64 defconfig
make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- O=build/arm64 -j$(nproc) Image dtbs
make ARCH=arm64 LLVM=1 O=build/arm64 -j$(nproc) Image     # clang toolchain
```

Give `ARCH` and the toolchain to every `make` call. Use a separate `O=` per target so stale objects do not leak. The image is `bzImage` on x86, `Image` on arm64. Missing `flex`, `bison`, `bc`, `libssl-dev` and `libelf-dev` are the usual first failures.

## Worked example

A developer writes `CONFIG_KVM_INTEL=y` and gets `# CONFIG_KVM_INTEL is not set`: its parents `VIRTUALIZATION` and `KVM` were not enabled. The lab gives a small Kconfig and asks for a fragment for a guest kernel; the check resolves it with the same drop rule.

## What goes wrong

Reusing a config across compiler versions without `olddefconfig`. `localmodconfig` kernels missing a device that was unplugged. `ARCH` set only on one of the commands. A `select` that bypasses a dependency and breaks the link.
