# format-patch, b4, send-email and list etiquette

This lesson follows the topic synthesis `synth/LNX-330/LNX-330-T06.md`. Check b4 and SMTP details against current documentation (to verify).

## What you will be able to do

- Turn commits into a numbered, versioned patch series with a cover letter.
- Record the base and the changelog so reviewers can follow versions.
- Send with `git send-email` or `b4`, and collect review trailers.
- Behave correctly on a kernel mailing list.

## Producing the series

```
git format-patch -v2 --cover-letter -s --base=<commit> \
    --to=maint@example.org --cc=list@example.org -o outgoing base..topic
```

| Option | Effect |
|---|---|
| `-v2` | subjects read `[PATCH v2 1/3]` |
| `--cover-letter` | message 0, where the changelog goes |
| `-s` | adds `Signed-off-by` |
| `--base` | adds `base-commit:` |
| `-o` | output directory |

Edit the cover letter's subject and body; send it with a `Changes in v2` list. Per-patch notes go below the `---` line so they are not committed.

## Commit message anatomy

- Subject: `subsystem: imperative summary`.
- Body: the problem, why this fix, alternatives; wrapped near 75 columns.
- Trailers: `Fixes: <12-char id> ("subject")`, `Cc: stable@vger.kernel.org`, `Reported-by:`, `Link:`, `Signed-off-by:`.

`Signed-off-by` certifies you may submit the code under the project licence (Developer Certificate of Origin).

## Sending

- `git send-email --dry-run outgoing/*` first, then send to yourself.
- Never paste patches into a mail client; wrapping and HTML break them.
- `b4 send` offers a web endpoint when SMTP is a problem; `b4 am <message-id>` downloads a series with trailers; `b4 trailers -u` updates yours.

## After sending

- Reply inline, trim quotes, answer every comment.
- Wait a day or more before v2; send one revision with all fixes.
- Keep `Reviewed-by` and `Acked-by` unless the patch changed a lot.
- Ping once after about two weeks if nothing happens.

## Etiquette

Plain text, no top-posting, technical and specific, public (no private mail), trimmed Cc lists, no cross-posting to unrelated lists.
