# kselftest

This lesson follows the topic synthesis `synth/LNX-330/LNX-330-T08.md`. Targets and helper names vary by kernel version; read `Documentation/dev-tools/kselftest.rst` in your tree (to verify).

## What you will be able to do

- State the kselftest contract: exit codes and TAP output.
- Write a test that passes, fails and skips in the right places.
- Build and run one subsystem's tests, and install a kit for another machine.
- Choose between KUnit and kselftest.

## The contract

| Exit code | Meaning |
|---|---|
| 0 | pass |
| 1 | fail |
| 2 / 3 | expected fail / unexpected pass (rare) |
| 4 | skip |

Output is TAP: `1..N` plan, `ok 1 name`, `not ok 2 name`, `ok 3 name # SKIP reason`, diagnostics after `#`.

A test must detect a missing feature (ENOSYS, absent file, missing config or privilege) and skip. Failing on a kernel that never had the feature is noise.

## Writing a test

```c
#include "../kselftest_harness.h"

TEST(sealing_blocks_grow)
{
	int fd = memfd_create("t", MFD_ALLOW_SEALING);
	ASSERT_GE(fd, 0);
	ASSERT_EQ(0, fcntl(fd, F_ADD_SEALS, F_SEAL_GROW));
	EXPECT_EQ(-1, ftruncate(fd, 8192));
	EXPECT_EQ(EPERM, errno);
}
TEST_HARNESS_MAIN
```

The harness forks each test, so a crash fails one case only. Simpler tests use `kselftest.h` helpers such as `ksft_test_result_pass()` and `ksft_exit_skip()`.

The directory Makefile sets `TEST_GEN_PROGS` and `TEST_PROGS` and includes `../lib.mk`. A `config` file lists needed kernel options, `settings` can raise the timeout.

## Running

```
make -C tools/testing/selftests TARGETS=net run_tests
make -C tools/testing/selftests TARGETS="timers size" kselftest-install
```

The install target produces a kit with `run_kselftest.sh` for a machine with no compiler. Run risky tests in a disposable VM.

## KUnit or kselftest

| Need | Use |
|---|---|
| internal function, pure logic | KUnit |
| system call, `/proc`, ioctl, real scheduler or device | kselftest |

## Habits

Deterministic, seconds not minutes, self-cleaning, one new interface equals one new selftest in the same series.

## Self-check

Try each question before you read the answers below.

1. Which exit code and TAP line should a test produce when the kernel lacks the feature?
2. Why does the kselftest harness fork each test?
3. A new system call needs a test. Is KUnit or kselftest the better choice?

### Answers

1. Exit 4 with an `ok N name # SKIP reason` line. Failing there would report a bug that does not exist.
2. So a crash or fatal signal fails only that test and the rest still run and report.
3. kselftest, because it exercises the call from user space through the real interface.
