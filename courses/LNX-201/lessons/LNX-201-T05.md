## How a route is chosen

For each outgoing packet the kernel picks the route with the **longest matching prefix**; the default route (`0.0.0.0/0`)
matches everything and loses to any more specific match. Ties go to the lower metric. `ip route get <addr>` shows the
decision, including interface and source address. `ip rule` adds policy routing: rules select a table by source address,
mark or interface, and `ip route show table 100` lists a non-default table.

```bash
ip route show
ip route add 198.51.100.0/24 via 192.0.2.254 dev eth1
ip route replace default via 192.0.2.1 metric 100
ip route get 198.51.100.7
ip rule add from 192.0.2.50/32 table 100
ip route add default via 203.0.113.1 table 100
```

All of these are runtime changes. Persist them in the profile (`nmcli ... +ipv4.routes`), in netplan `routes:`, or
in a networkd `[Route]` section.

## Forwarding

A host forwards packets between interfaces only if `net.ipv4.ip_forward=1` (and `net.ipv6.conf.all.forwarding=1`
for IPv6); persist it in `/etc/sysctl.d/`. Forwarding needs a return path: the other hosts must route replies back
through this host, either by a route on each side or by NAT (masquerade) on the router.

## Multi-NIC hosts

With two interfaces on different networks and one default gateway, replies to requests that arrive on the second NIC may
leave through the first. The reverse-path filter (`rp_filter`) may then drop packets, and stateful firewalls on the path
see half a conversation. Fixes: policy routing so replies use the interface that received the request, or a second
routing table selected by source address; or keep one default route and add specific routes for the other network. The
sysctls `arp_ignore` and `arp_announce` also matter when several interfaces share a subnet.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Ping goes out, no reply | missing return route | the other end's `ip route get` |
| Works from one NIC only | asymmetric routing, `rp_filter` | `ip rule`, `sysctl net.ipv4.conf.all.rp_filter` |
| Forwarding does nothing | `ip_forward` is 0 | `sysctl net.ipv4.ip_forward` |
| Route gone after reboot | runtime-only change | persistent configuration |
