## nftables model

A **table** belongs to a family (`ip`, `ip6`, `inet`, `arp`, `bridge`, `netdev`) and holds **chains**, sets and maps. A **base chain**
attaches to a hook (`prerouting`, `input`, `forward`, `output`, `postrouting`) with a type (`filter`, `nat`, `route`), a priority and an
optional default policy. Every base chain on a hook is evaluated, so a packet must be accepted by all of them; a drop anywhere is final.

```
table inet lab {
    chain input {
        type filter hook input priority 10; policy drop;
        iif lo accept
        ct state established,related accept
        ip protocol icmp accept
        ip6 nexthdr ipv6-icmp accept
        tcp dport 22 accept
    }
}
```

Commands: `nft list ruleset`, `nft -a list chain inet lab input` (rule handles), `nft -c -f file` (check only), `nft -f file`
(atomic load: all or nothing), `nft delete rule inet lab input handle 7`, `nft monitor trace` with a `meta nftrace set 1` rule.
`flush ruleset` at the top of a file replaces the policy in one step. Persistence: `nftables.service` loads the distribution's
file at boot. A rule added only with `nft add` is gone after a reboot.

## firewalld

Zones (`public`, `internal`, `external`, `trusted`, `drop`, ...) are trust levels bound to interfaces or source ranges; services are
named port bundles; policies govern traffic between zones. There are two configurations: **runtime** (enforced now) and
**permanent** (stored). A command without `--permanent` changes only runtime; one with it changes only the store until `--reload`.

```bash
firewall-cmd --state
firewall-cmd --get-active-zones
firewall-cmd --zone=public --add-service=https --timeout=300   # test, then:
firewall-cmd --runtime-to-permanent
firewall-cmd --permanent --zone=internal --add-source=10.20.0.0/16
firewall-cmd --reload
firewall-cmd --list-all
```

An omitted `--zone` means the default zone, not the zone of your interface. firewalld owns its own tables; custom nft tables
coexist but a custom accept cannot override a firewalld drop. Pick one owner per host.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Port opened, still blocked | wrong zone or another chain drops | `firewall-cmd --list-all`, `nft list ruleset` |
| Rule vanished after reboot | runtime only | `--permanent` or the saved file |
| Lost SSH after a change | missing established rule | use `--timeout` or a scheduled revert |
| IPv6 open while IPv4 closed | only an `ip` table | use `inet` |
