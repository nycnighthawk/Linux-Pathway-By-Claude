# NetworkManager, netplan and systemd-networkd

This lesson follows the topic synthesis `synth/LNX-201/LNX-201-T03.md`, which carries the sources and the history.

## What you will be able to do

- Create and inspect profiles with `nmcli`, and write a netplan file that renders to networkd.
- Apply a configuration with a safe rollback.

## Who owns the interfaces

RHEL, Fedora and Rocky use **NetworkManager** (profiles in `/etc/NetworkManager/system-connections/` as keyfiles).
Ubuntu Server uses **netplan**, a YAML front end in `/etc/netplan/` that renders to systemd-networkd or NetworkManager.
**systemd-networkd** reads `.network`, `.netdev` and `.link` files from `/etc/systemd/network/` and `/run/systemd/network/`.
Run exactly one manager per interface; two managers fight over addresses and routes.

## nmcli

```bash
nmcli device status
nmcli connection show
nmcli connection add type ethernet ifname eth0 con-name lan ipv4.method manual \
    ipv4.addresses 192.0.2.10/24 ipv4.gateway 192.0.2.1 ipv4.dns 192.0.2.53
nmcli connection modify lan +ipv4.routes "198.51.100.0/24 192.0.2.254"
nmcli connection up lan
nmcli --offline connection add type ethernet con-name lan ifname eth0 ipv4.method auto   # prints a keyfile
```

`modify` changes the stored profile; `up` reactivates it. Keyfiles must be owned by root with mode 0600.

## netplan

```yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    eth0:
      addresses: [192.0.2.10/24]
      routes:
        - to: default
          via: 192.0.2.1
      nameservers:
        addresses: [192.0.2.53]
        search: [lab.test]
```

`netplan generate` renders to `/run/systemd/network/` (or NetworkManager); `netplan apply` applies; `netplan try`
applies and rolls back after a timeout unless you confirm, which is the safe way to change a remote host. `netplan
generate --root-dir DIR` renders into a scratch directory without touching the machine. Netplan files should be mode 0600.

## systemd-networkd

```ini
[Match]
Name=eth0
[Network]
Address=192.0.2.10/24
Gateway=192.0.2.1
DNS=192.0.2.53
Domains=lab.test
```

`networkctl` lists links and `networkctl status eth0` shows the applied state; `systemctl restart systemd-networkd`
re-reads files. Files are read in lexical order and the first matching `.network` for a link wins.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Config applied, address missing | file not matched or wrong renderer | `netplan generate`, `networkctl status` |
| Settings reappear after edit | another manager owns the link | `nmcli device`, `networkctl` |
| Lost remote access after change | no rollback | use `netplan try` or a timed revert |
| Profile ignored | keyfile permissions | owner root, mode 0600 |
