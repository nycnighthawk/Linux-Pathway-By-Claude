# Wi-Fi and 802.1X

This lesson follows the topic synthesis `synth/LNX-201/LNX-201-T09.md`, which carries the sources and the history.

## What you will be able to do

- Join a wireless network from the command line and read the link state.
- Explain personal versus enterprise (802.1X) authentication and the roles in it.
- Configure a client for PEAP or EAP-TLS with `nmcli` and know why server validation matters.

## Tools

```bash
rfkill list                       # soft and hard blocks
nmcli radio wifi on               # or off
nmcli device wifi list            # scan, with SECURITY column
nmcli device wifi connect "SSID" password "secret"
iw dev wlp3s0 link               # association, frequency, signal
iw reg get                        # regulatory domain
```

The regulatory domain (a country code) limits channels and power; on RHEL it can be set in `/etc/sysconfig/regdomain`, otherwise
with `iw reg set` or the distribution's regulatory database. A wrong domain hides channels.

## Authentication

**Personal** mode shares one passphrase (WPA2-PSK, WPA3-SAE). **Enterprise** mode uses IEEE 802.1X with EAP: a **supplicant** (client,
usually `wpa_supplicant`), an **authenticator** (access point or switch) and an **authentication server** (RADIUS, for example FreeRADIUS).
EAP-TLS uses client and server certificates; PEAP and EAP-TTLS use a server certificate and a password inside a tunnel.

```bash
nmcli connection modify wlp1s0 802-1x.eap peap 802-1x.identity alice \
    802-1x.phase2-auth mschapv2 wireless-security.key-mgmt wpa-eap
nmcli connection modify wlp1s0 802-1x.ca-cert /path/to/ca.pem
nmcli connection modify wlp1s0 802-1x.password-flags agent-owned
nmcli connection up wlp1s0
```

Without a CA certificate the client accepts any server, which lets a rogue access point harvest passwords. The key management,
EAP type, inner method and identity must be set in one command. The `wpa_supplicant` package must be installed.

## Baselines

Servers rarely need Wi-Fi. Hardening guides ask to disable wireless adapters on systems with radios (`nmcli radio all off`, or blacklist the driver).

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Radio listed but no scan | blocked | `rfkill list` |
| Some channels missing | regulatory domain | `iw reg get` |
| EAP fails at TLS | certificate chain, dates, old TLS settings | supplicant and RADIUS logs |
| Connects to any lookalike SSID | no server validation | `802-1x.ca-cert` |
