## Structure

FRR is a set of daemons: `zebra` and `staticd` always run, and `ospfd`, `bgpd`, `isisd` and others are enabled in `/etc/frr/daemons`. Zebra installs the best routes in the kernel. The CLI is `vtysh`; the configuration lives in `/etc/frr/frr.conf`.

```
router ospf
 ospf router-id 10.255.0.1
 passive-interface default
 no passive-interface eth1
 network 10.0.12.0/24 area 0
exit
interface eth1
 ip ospf network point-to-point
 ip ospf hello-interval 2
 ip ospf dead-interval 8
exit
router bgp 65001
 bgp router-id 10.255.0.1
 no bgp ebgp-requires-policy
 neighbor 192.0.2.2 remote-as 65002
 address-family ipv4 unicast
  network 198.51.100.0/24
  neighbor 192.0.2.2 activate
 exit-address-family
exit
```

## Reading state

```bash
vtysh -c 'show ip ospf neighbor'        # Down, Init, 2-Way, ExStart, Exchange, Loading, Full
vtysh -c 'show ip route ospf'
vtysh -c 'show bgp summary'             # state and prefixes received
vtysh -c 'show bgp ipv4 unicast neighbors 192.0.2.2 advertised-routes'
vtysh -C -f frr.conf                    # offline syntax check
```

Enable forwarding (`net.ipv4.ip_forward=1`) and allow OSPF (IP protocol 89, multicast 224.0.0.5 and 224.0.0.6) and TCP port 179. Current FRR needs a route map on an eBGP neighbour, or `no bgp ebgp-requires-policy`, before it sends or accepts routes. BFD speeds up failure detection when configured on both sides.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Neighbour stuck in ExStart | MTU mismatch | interface MTUs, `ip ospf mtu-ignore` as a stopgap |
| BGP Established, 0 prefixes | eBGP policy requirement, or address family not activated | `show bgp summary`, config |
| Route learned but not installed | a better route from another source | `show ip route`, administrative distance |
| No adjacency at all | protocol 89 or TCP 179 blocked | firewall, `tcpdump` |
