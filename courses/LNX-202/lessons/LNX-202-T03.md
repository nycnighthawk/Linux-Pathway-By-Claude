## Who tells the host what

Only router advertisements (ICMPv6 type 134) carry the default router. A host sends a router solicitation, learns prefixes from the prefix options and builds an address under each prefix that has the A flag and a 64-bit length. The M flag says addresses are available from DHCPv6; the O flag says other settings (DNS, domain) are. RDNSS and DNSSL options put DNS settings in the advertisement itself, so SLAAC alone can be complete.

```bash
sysctl net.ipv6.conf.eth0.accept_ra net.ipv6.conf.all.forwarding
ip -6 addr show dev eth0; ip -6 route show
rdisc6 eth0                                  # solicit and print advertisements
tcpdump -ni eth0 icmp6 and 'ip6[40] == 134'
```

`accept_ra` is 0 to ignore, 1 to accept when not forwarding and 2 to accept even when forwarding. A Linux router needs 2 on its upstream interface.

## radvd and DHCPv6

```
interface eth1 {
    AdvSendAdvert on;
    AdvManagedFlag off;
    AdvOtherConfigFlag on;
    prefix 2001:db8:42:7::/64 { AdvOnLink on; AdvAutonomous on; };
    RDNSS 2001:db8:42:7::53 { AdvRDNSSLifetime 600; };
};
```

`radvd -c -C file` checks the syntax; the router must forward (`net.ipv6.conf.all.forwarding=1`). The prefix length is fixed at 64 here. DHCPv6 uses UDP 546 (client) and 547 (server), multicast `ff02::1:2`, identifies clients by DUID and can also delegate prefixes (IA_PD). It never carries a gateway.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Link-local address only | no advertisements (radvd not running, forwarding off) | `rdisc6`, `journalctl -u radvd` |
| Address but no default route | `accept_ra` is 0 on a forwarding host | `sysctl net.ipv6.conf.eth0.accept_ra` |
| Route but no DNS | no RDNSS and no DHCPv6 O flag | `radvdump`, DHCPv6 server |
| Everything times out | firewall drops ICMPv6 | allow neighbour and router discovery and path MTU |
