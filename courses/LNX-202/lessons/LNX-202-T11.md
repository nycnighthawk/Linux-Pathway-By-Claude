## LACP against a switch

On Linux: mode 802.3ad, `lacp_rate fast` if the switch uses fast PDUs, a hash policy that suits the traffic (`layer3+4`, `layer2+3`) and `miimon 100`. On the switch: a port-channel (LAG) with the member ports, LACP in active mode on at least one side, the same speed and duplex on every member, and matching trunk or access mode and VLANs. Servers attached to two switches need the vendor's multi-chassis scheme (MLAG, vPC). Verify with `/proc/net/bonding/bond0` (one Aggregator ID, the partner system MAC) and with the switch's port-channel summary. A switch fallback option lets a port work as an individual link until LACPDUs arrive, which network boot needs.

## SR-IOV

```bash
lspci -nn | grep -i ethernet
cat /sys/class/net/eth0/device/sriov_totalvfs
echo 4 > /sys/class/net/eth0/device/sriov_numvfs
ip link set eth0 vf 0 mac 52:54:00:12:34:56 vlan 20 spoofchk on trust off
ip link show eth0
```

Enable VT-d or AMD-Vi and SR-IOV in firmware, and the IOMMU in the kernel (`intel_iommu=on` or `amd_iommu=on`). A VF is a lightweight PCI function that you give to a guest with VFIO or libvirt `hostdev`. The PF still sets MAC, VLAN, rate and anti-spoofing. systemd can create and configure VFs from `[SR-IOV]` sections in `.link` and `.network` files.

VF traffic bypasses the host network stack: lower latency and CPU, but no host bridge, no host firewall, harder live migration, and driver-specific limits on VF count and offloads.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Bond carries traffic on one port only | switch group static or not LACP | Aggregator IDs, switch port-channel mode |
| Network boot fails with a bond | no fallback to an individual link | switch LACP fallback setting |
| VFs exist but guests have no network | VLAN not allowed on the switch port, or spoof check | `ip link show`, switch trunk |
| Cannot create VFs | IOMMU or SR-IOV disabled | firmware, kernel command line, `sriov_totalvfs` |
