## Namespaces and veth

A network namespace has its own devices, protocol stacks, routing tables, firewall rules, `/proc/net`, ports and sysctls. A physical device lives in exactly one namespace; a veth pair is a virtual cable whose ends can sit in different ones.

```bash
ip netns add red
ip link add veth-r type veth peer name veth-h
ip link set veth-r netns red
ip -n red addr add 10.10.1.2/24 dev veth-r; ip -n red link set veth-r up; ip -n red link set lo up
ip addr add 10.10.1.1/24 dev veth-h; ip link set veth-h up
ip -n red route add default via 10.10.1.1
ip netns exec red ping -c1 10.10.1.1
```

`ip -n NAME` runs ip inside a namespace and `ip netns exec NAME CMD` runs any command. Loopback starts down. To reach the outside, enable forwarding in the host and add NAT or a return route.

## VRF

```bash
ip link add vrf-a type vrf table 10
ip link set vrf-a up; ip link set eth1 master vrf-a
ip route add default via 192.0.2.254 vrf vrf-a
ip vrf exec vrf-a ping -c1 192.0.2.254
```

A VRF owns a routing table; enslaved interfaces route only inside it. Sockets and firewall stay shared, so daemons must bind to the VRF (`ip vrf exec`, or an option of the daemon).

## Policy routing

```bash
ip route add default via 198.51.100.1 dev eth2 table 100
ip rule add from 198.51.100.7 lookup 100 priority 1000
ip rule add fwmark 0x2 lookup 100 priority 1100
ip rule show; ip route get 203.0.113.9 from 198.51.100.7
```

Rules are evaluated lowest priority number first: 0 for the local table, 32766 for main, 32767 for default. Selectors include `from`, `to`, `iif`, `oif`, `fwmark` and `uidrange`. Asymmetric flows meet reverse-path filtering; loose mode (`rp_filter=2`) is the usual compromise.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Namespace pings the host but not beyond | forwarding off or no return route | `sysctl net.ipv4.ip_forward`, upstream routes |
| Service works in `ip vrf exec`, not under systemd | unit runs in the default VRF | bind the service to the VRF |
| Replies leave on the wrong link | no rule for that source address | `ip route get ... from ...` |
| Route disappears after reboot | `ip` changes are runtime only | network manager or unit file |

## Self-check

1. What is shared between VRFs and what is not shared between namespaces?
2. Which rule is evaluated first, priority 0 or 32766?
3. Why does the loopback device need to be brought up in a new namespace?
4. How do you ask the kernel which route a packet from a given source would use?
