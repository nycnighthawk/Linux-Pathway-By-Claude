## What you will be able to do

- Configure HAProxy frontends and backends with health checks, in `http` and `tcp` mode.
- Float a virtual IP with keepalived and tie its priority to a health script.
- Validate both configurations and read the state of a failover.

## HAProxy

Sections: `global`, `defaults`, `frontend`, `backend` and `listen`. A frontend binds addresses and chooses a backend by rules; a backend lists servers and a balancing algorithm.

```
frontend web
    bind 192.0.2.80:80
    default_backend app
backend app
    balance roundrobin
    option httpchk GET /health
    server app1 192.0.2.11:8080 check inter 2s fall 3 rise 2
    server app2 192.0.2.12:8080 check inter 2s fall 3 rise 2
```

`mode http` parses requests (routing by path, host or header); `mode tcp` forwards bytes. Algorithms: `roundrobin`, `leastconn`, `source`, `uri`, `random`. `check` enables health checks; `fall` and `rise` count failures and successes. Validate with `haproxy -c -f haproxy.cfg`; `systemctl reload haproxy` swaps workers without dropping connections. The stats socket answers `show stat` and `set server BACKEND/SERVER state drain`.

## keepalived

VRRP uses IP protocol 112, multicast 224.0.0.18, one advertisement per `advert_int` seconds. The highest priority wins; nodes of one virtual router share `virtual_router_id`.

```
global_defs {
    enable_script_security
    script_user root
}
vrrp_script chk_haproxy {
    script "/usr/bin/pgrep haproxy"
    interval 2
    weight -30
    fall 2
    rise 2
}
vrrp_instance VI_1 {
    state BACKUP
    interface eth0
    virtual_router_id 51
    priority 110
    advert_int 1
    virtual_ipaddress {
        192.0.2.80/24 dev eth0
    }
    track_script {
        chk_haproxy
    }
}
```

A failing script lowers the priority by `weight`, so the standby can win. `nopreempt` stops a recovered master from taking the address back; `unicast_peer` replaces multicast where it is blocked. Do not combine unicast with `vrrp_strict`, which forbids it. HAProxy must bind the VIP while it is on the other node: set `net.ipv4.ip_nonlocal_bind=1`. Test with `keepalived -t -f FILE`; see who holds the address with `ip -br addr`.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Both nodes claim the VIP | VRRP blocked or multicast dropped | `tcpdump -ni eth0 proto 112`, unicast mode |
| HAProxy fails to start on the standby | cannot bind the VIP | `ip_nonlocal_bind` |
| Dead backend still receives traffic | no health check | `check`, `option httpchk` |
| Address flaps | check script wrong or too sensitive | `fall`, `rise`, the script itself |
