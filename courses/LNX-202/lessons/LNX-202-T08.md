# tcpdump and tshark

This lesson follows the topic synthesis `synth/LNX-202/LNX-202-T08.md`, which carries the history and the sources.

## What you will be able to do

- Choose where to capture and select traffic with a BPF capture filter.
- Record long captures with bounded files and avoid offload artefacts.
- Turn a capture into numbers with tshark display filters, fields and statistics.

## Where and what to capture

A host capture is taken after the host's own transmit processing and before its receive processing, so offloads (TSO, GSO, GRO, checksum offload) can show frames larger than the MTU and wrong checksums. Capture on the physical interface for the wire, on a veth or bridge port for a guest, on the VLAN or tunnel device for inner traffic, on a mirror port or tap for an independent view. In a namespace, run the tool inside it.

```bash
tcpdump -ni eth0 -s0 -w web.pcap 'host 192.0.2.10 and tcp port 443'
tcpdump -ni eth0 -G 300 -W 12 -w '/var/tmp/cap-%H%M.pcap' 'not port 22'
tcpdump -ni eth0 -C 100 -W 10 -w ring.pcap
tcpdump -ni eth0 -e vlan and icmp
tcpdump -ni eth0 'tcp[tcpflags] & (tcp-syn|tcp-rst) != 0'
ip netns exec red tcpdump -ni veth-r
```

`-n` skips lookups, `-s0` takes whole packets, `-w` writes pcap, `-G` rotates by time and `-C` by size. The exit report of dropped packets tells you if the capture is complete. Capture filters are BPF and run in the kernel.

## tshark

```bash
tshark -r web.pcap -Y 'tcp.analysis.retransmission' -T fields -e frame.time_relative -e ip.src
tshark -r web.pcap -q -z conv,tcp
tshark -r web.pcap -q -z io,stat,1
tshark -r web.pcap -Y http.request -T fields -e http.host -e http.request.uri
tshark -r web.pcap -o tls.keylog_file:/tmp/keys.log -Y 'tls.handshake.type == 1'
```

`-Y` is a display filter, applied after decoding; it is a different language from BPF. The expert fields `tcp.analysis.retransmission`, `duplicate_ack` and `zero_window` summarise TCP trouble. `-z` selects statistics. TLS is decrypted only with a key log from the client (`SSLKEYLOGFILE`). `dumpcap` is the lean capture engine; `xdpdump` captures at the XDP hook, including packets an XDP program drops.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Capture is empty | wrong interface or filter | `ip -br link`, drop the filter |
| Huge frames and bad checksums | offloads on the capturing host | `ethtool -k`, capture elsewhere |
| Missing the event | ring too small | time-based rotation, trigger |
| Packets missing in the file | kernel drops | the drop report, `-B`, narrower filter |
