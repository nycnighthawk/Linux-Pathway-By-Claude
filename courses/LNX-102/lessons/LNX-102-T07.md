# Time and chrony

This lesson follows the topic synthesis `synth/LNX-102/LNX-102-T07.md`, which carries the sources and the history.

## What you will be able to do

- Configure `chronyd` with pools, step rules, a drift file and an allowed client network.
- Inspect synchronisation with `chronyc` and `timedatectl`.

## Three separate things

The **system clock** counts UTC seconds. The **hardware clock** (RTC) keeps time while powered off, stored as UTC on
Linux by default. The **time zone** only changes display, through the link `/etc/localtime` to a file under
`/usr/share/zoneinfo`.

```bash
timedatectl                             # clocks, zone, sync state
timedatectl list-timezones | grep Berlin
timedatectl set-timezone Europe/Berlin
timedatectl set-ntp true
```

## chrony

`chronyd` disciplines the clock against NTP servers and tolerates intermittent connections. Its file is
`/etc/chrony.conf` (`/etc/chrony/chrony.conf` on Debian family).

```
pool 2.pool.ntp.org iburst
driftfile /var/lib/chrony/drift
makestep 1.0 3
rtcsync
allow 192.168.10.0/24
log tracking measurements statistics
```

| Directive | Meaning |
|---|---|
| `pool`, `server` | where to get time; `iburst` speeds up the start |
| `makestep 1.0 3` | step the clock if offset exceeds 1 s, during the first 3 updates only |
| `rtcsync` | copy system time to the hardware clock periodically |
| `allow` | serve time to clients in this network |
| `driftfile` | remember the oscillator error |

Normally the clock is **slewed** (sped up or slowed down), because stepping backwards confuses databases and logs.
Check with `chronyc tracking`, `chronyc sources -v`, `chronyc makestep`. Validate a file with `chronyd -p -f file`.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Clock off by hours | Zone set wrongly, or RTC treated as local | `timedatectl` |
| Not synchronised in a VM | Blocked UDP 123, or no source | `chronyc sources` |
| Clients cannot sync from this host | No `allow`, firewall | `chronyc clients`, port 123 |
| Big jump during running service | Manual step | Prefer slew; `makestep` limits |
