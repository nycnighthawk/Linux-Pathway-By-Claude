# systemd units, targets, dependencies and overrides

This lesson follows the topic synthesis `synth/LNX-102/LNX-102-T03.md`, which carries the sources and the history.

## What you will be able to do

- Name the unit types and the directories that systemd searches, in order of precedence.
- Tell ordering (`After=`) from requirement (`Requires=`, `Wants=`).
- Change a vendor unit with `systemctl edit`, a drop-in file, and verify with `systemd-analyze` and `systemctl cat`.

## Units and where they live

A unit is a file named `name.type`: `.service`, `.socket`, `.timer`, `.mount`, `.path`, `.target` and others. Search
order, highest first: `/etc/systemd/system` (administrator), `/run/systemd/system` (runtime), then the vendor directory
`/usr/lib/systemd/system`. Never edit vendor files; the next package update would overwrite your change.

## Dependencies are two separate ideas

| Directive | Meaning |
|---|---|
| `Wants=` | Pull this unit in; start anyway if it fails |
| `Requires=` | Pull this unit in; fail or stop if it fails |
| `After=` / `Before=` | Order only; says nothing about whether the other unit runs |
| `Conflicts=` | Stop one when the other starts |
| `WantedBy=` (in `[Install]`) | Which target pulls this unit in when you `enable` it |

Without an ordering directive, two units start in parallel. A target such as `multi-user.target` groups units and is the
modern replacement for a runlevel.

## Overriding

```bash
systemctl edit nginx.service              # writes /etc/systemd/system/nginx.service.d/override.conf
systemctl edit --full nginx.service       # copy of the whole unit into /etc/systemd/system
systemctl cat nginx.service               # file plus all drop-ins, in effect order
systemctl daemon-reload                   # after editing files by hand
systemctl revert nginx.service            # remove your overrides
```

A drop-in is a `.conf` file in `name.service.d/`. Drop-ins are applied in lexicographic order and later settings win.
For list-type settings such as `ExecStart=`, first assign an empty value to clear the vendor entry, then set yours:

```ini
[Service]
ExecStart=
ExecStart=/usr/sbin/nginx -c /etc/nginx/custom.conf
Restart=on-failure
```

Other states to know: `enable` creates symlinks from the `[Install]` section, `mask` links the unit to `/dev/null` so it
cannot start at all, `systemctl list-dependencies unit` shows the tree, and `systemd-analyze verify unit-file` checks
syntax before you rely on it.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Two `ExecStart=` error | Drop-in did not clear the old one | Add an empty `ExecStart=` first |
| Change has no effect | Forgot reload, or a higher-priority file wins | `systemctl cat`, `daemon-reload` |
| Service starts too early | Only `Wants=` set, no `After=` | Add `After=` |
| `Failed to enable` | No `[Install]` section | Read the unit, use `WantedBy=` |
