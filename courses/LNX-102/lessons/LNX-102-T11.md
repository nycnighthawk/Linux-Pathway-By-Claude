# Physical console and firmware setup

This lesson follows the topic synthesis `synth/LNX-102/LNX-102-T11.md`, which carries the sources and the history.

## What you will be able to do

- Enter firmware setup and tell UEFI from BIOS from inside Linux.
- Boot once with a changed kernel command line and confirm it.
- Set the console keymap and a serial console.

## Firmware and boot mode

```bash
[ -d /sys/firmware/efi ] && echo uefi || echo bios
mokutil --sb-state                       # Secure Boot state
efibootmgr -v                            # boot entries (UEFI)
systemctl reboot --firmware-setup        # restart straight into the firmware menu
systemctl reboot --boot-loader-entry=name  # one-shot boot-loader entry (systemd-boot)
```

The key that opens setup (often Esc, Del, F2 or F10) is on the splash screen or in the hypervisor's documentation. Boot
order and Secure Boot live in firmware, not in Linux. With Secure Boot, unsigned kernel modules and some boot options
are restricted.

## Console and keyboard

`/proc/cmdline` shows the arguments of the running kernel. For a serial console add `console=ttyS0,115200n8` (the last
`console=` becomes the main one). The console keymap is `KEYMAP=` in `/etc/vconsole.conf`, set with
`localectl set-keymap us`; `localectl status` shows keymap and layout. For a one-time test edit the entry in the boot
menu with `e` and confirm in `/proc/cmdline`.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Keyboard types wrong characters at the prompt | Console keymap not set | `localectl status` |
| No output on the serial line | Missing `console=` argument | `/proc/cmdline` |
| Cannot boot your own kernel | Secure Boot | `mokutil --sb-state` |
| Boot order resets | Firmware replaced entries | `efibootmgr -v` |
