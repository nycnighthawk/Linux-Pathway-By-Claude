# Users, groups, sudo and password ageing

This lesson follows the topic synthesis `synth/LNX-102/LNX-102-T01.md`, which carries the sources and the history.

## What you will be able to do

- Read the fields of `/etc/passwd`, `/etc/shadow` and `/etc/group` and say which file holds what.
- Create and modify accounts with `useradd`, `usermod`, `groupadd` and `chage`.
- Grant narrow, auditable privilege with a validated file in `/etc/sudoers.d/`.

## The account files

| File | Fields (colon separated) | Mode |
|---|---|---|
| `/etc/passwd` | name, `x`, UID, GID, comment, home, shell | 0644 |
| `/etc/shadow` | name, hash, last change (days since 1970), min, max, warn, inactive, expire, reserved | 0640 or 0000 |
| `/etc/group` | name, `x`, GID, member list | 0644 |
| `/etc/gshadow` | name, hash, admins, members | 0640 or 0000 |

The hash lives in `shadow` because `passwd` must be world-readable for name lookups. A hash starting with `!` means the
password is locked; `*` means no password login at all. `/etc/login.defs` and `/etc/default/useradd` supply defaults such
as `UID_MIN`, `PASS_MAX_DAYS` and the default shell and home base.

## Everyday commands

```bash
groupadd -g 2100 ops
useradd -u 2001 -g ops -G wheel -m -d /srv/deploy -s /bin/bash deploy
usermod -aG docker deploy        # -a matters: without it the supplementary list is replaced
usermod -L deploy                # lock; -U unlocks
userdel -r deploy                # also remove home and mail spool
chage -m 7 -M 90 -W 14 -I 30 deploy   # min, max, warn, inactive days
chage -l deploy                  # show ageing; -d 0 forces a change at next login
```

`--root DIR` (or `-R`) makes these tools work on another tree, which is how the lab avoids touching the host. Use
`id deploy` and `getent passwd deploy` to see the effective result, including accounts that come from other sources.

## sudo done safely

Edit with `visudo`, never with a plain editor, because a syntax error can lock every administrator out. Prefer one file
per purpose under `/etc/sudoers.d/`, mode `0440`:

```
%ops ALL=(root) NOPASSWD: /usr/bin/systemctl restart nginx
```

The fields are who, host, `(run as)`, tag, then the commands. Give full paths to commands, because a bare name can be
resolved through a writable directory. Check without installing: `visudo -cf /etc/sudoers.d/ops`. List what a user may do
with `sudo -l -U deploy`. Allowing a command that can run a shell or edit files (a pager, `vi`, `tar`) hands out root.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| User lost all their groups | `usermod -G` without `-a` | `id user`, then re-add |
| sudo says the file is bad and ignores it | Wrong mode or syntax error | `visudo -cf`, mode `0440` |
| Account locked after a password change | Ageing limits reached | `chage -l user` |
| New files get the wrong group | Primary group differs from intent | `id -gn`, setgid directory |
