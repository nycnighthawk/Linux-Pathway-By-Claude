# cron, at and systemd timers

This lesson follows the topic synthesis `synth/LNX-102/LNX-102-T06.md`, which carries the sources and the history.

## What you will be able to do

- Write user and system crontab entries with the five time fields.
- Run a one-time job with `at`.
- Write a `.timer` and `.service` pair with `OnCalendar=` and test the expression.

## cron

A user crontab (`crontab -e`, `-l`, `-r`) has five fields then the command: minute, hour, day of month, month, day of
week (0 or 7 is Sunday). `*` is any, `,` a list, `-` a range, `/` a step.

```
30 2 * * 1-5  /usr/local/bin/backup.sh
*/15 * * * *  /usr/bin/check
@reboot       /usr/local/bin/warmup
```

System files (`/etc/crontab`, `/etc/cron.d/*`) add a **sixth field, the user**: `30 2 * * 1-5 root /path/backup.sh`.
Scripts dropped into `/etc/cron.daily`, `cron.hourly`, `cron.weekly` and `cron.monthly` run at times set by the system.
Cron uses a minimal environment (`PATH`, `SHELL`, `HOME`), so use full paths. Output is mailed to the owner, so redirect
it or set `MAILTO`. Access is controlled with `/etc/cron.allow` and `/etc/cron.deny`.

## at

`at 17:30` (or `at now + 2 hours`) reads commands from standard input and runs them once. `atq` lists, `atrm N` removes.

## systemd timers

A timer activates a service of the same name. Two files:

```ini
# backup.service
[Service]
Type=oneshot
ExecStart=/usr/local/bin/backup.sh

# backup.timer
[Timer]
OnCalendar=Mon..Fri *-*-* 02:30:00
Persistent=true
[Install]
WantedBy=timers.target
```

Enable the timer, not the service: `systemctl enable --now backup.timer`. `Persistent=true` runs a missed job after
downtime. Other triggers: `OnBootSec=`, `OnUnitActiveSec=`, `RandomizedDelaySec=`. Check an expression with
`systemd-analyze calendar "Mon..Fri 02:30"` and list timers with `systemctl list-timers`. Output goes to the journal.

## Cron or timer?

| Need | Better choice |
|---|---|
| Run every N minutes after the last finish | timer (`OnUnitActiveSec`) |
| Catch up after downtime | timer with `Persistent=true` |
| Resource limits, dependencies, logs per run | timer |
| Tiny portable one-liner | cron |

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Works by hand, not from cron | Minimal `PATH` or environment | Full paths, `env` in the job |
| System crontab line fails | Forgot the user field | Count fields |
| Timer never fires | Enabled the service instead | `systemctl list-timers` |
| Job runs at the wrong hour | Time zone or `OnCalendar` misread | `timedatectl`, `systemd-analyze calendar` |
