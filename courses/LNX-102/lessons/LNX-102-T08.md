## What you will be able to do

- List, inspect, load and unload kernel modules and make module choices persistent.
- Read and set kernel parameters at runtime and persistently.
- Predict which file wins when several define the same parameter.

## Modules

```bash
lsmod                         # loaded modules
modinfo bonding               # description, parameters, dependencies
modprobe br_netfilter         # load with dependencies;  modprobe -r name unloads
```

Persistent configuration:

| Location | Purpose |
|---|---|
| `/etc/modules-load.d/*.conf` | module names to load at boot, one per line |
| `/etc/modprobe.d/*.conf` | options and rules for `modprobe` |

```
options bonding mode=802.3ad miimon=100
blacklist floppy
install usb-storage /bin/false
```

`blacklist` only stops automatic loading by alias; a module can still be loaded by name. An `install` line that runs
`/bin/false` blocks loading in both ways.

## sysctl

Parameters appear as files under `/proc/sys`, with dots for slashes: `net.ipv4.ip_forward` is
`/proc/sys/net/ipv4/ip_forward`.

```bash
sysctl net.ipv4.ip_forward            # read;  sysctl -a lists all
sysctl -w vm.swappiness=10            # runtime only, lost at reboot
sysctl -N vm.swappiness               # does the name exist?
sysctl --system                       # reload all configuration files
```

Persist in `/etc/sysctl.d/99-name.conf` (`key = value`). Files are read from `/etc/sysctl.d`, `/run/sysctl.d` and
`/usr/lib/sysctl.d`; a file with the same name in an earlier directory hides the later one, and across different names
the last one in lexical order wins, hence the `99-` prefix. Some parameters need their module loaded first, otherwise
`sysctl --system` reports an unknown key.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Setting lost at reboot | Used `sysctl -w` only | Add a file, `sysctl --system` |
| Key is "unknown" | Module not loaded yet | `modprobe`, `modules-load.d` |
| Value reverts to the old one | A later file overrides yours | `sysctl --system` output order |
| Blacklisted module still loads | Loaded by name or as dependency | Use an `install` line |
