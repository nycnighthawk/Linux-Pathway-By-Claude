# The boot process, GRUB2, rescue targets and root reset

This lesson follows the topic synthesis `synth/LNX-102/LNX-102-T04.md`, which carries the sources and the history.

## What you will be able to do

- Walk the boot chain from firmware to a login prompt and name what each stage hands over.
- Choose a default target and reach rescue or emergency mode.
- Change kernel arguments persistently and regenerate the GRUB configuration.

## The chain

1. **Firmware** (UEFI or BIOS) initialises hardware and finds a boot loader. UEFI reads the EFI System Partition.
2. **Boot loader** (GRUB2 or systemd-boot) shows a menu, loads the kernel and an initramfs, and passes the kernel command line.
3. **Kernel** starts, mounts the initramfs, which finds the real root file system (drivers, LVM, encryption).
4. **systemd** runs as PID 1 and starts units to reach the default target: `multi-user.target` for text, `graphical.target` for a desktop.

## Targets and rescue modes

```bash
systemctl get-default
systemctl set-default multi-user.target
systemctl isolate rescue.target        # switch now; services stop
systemd-analyze blame                   # slow units;  systemd-analyze critical-chain
```

On the kernel command line (edit the entry in the GRUB menu with `e`, then Ctrl-X to boot once):

| Argument | Effect |
|---|---|
| `systemd.unit=rescue.target` or `1` | single-user style shell, basic file systems mounted |
| `systemd.unit=emergency.target` | minimal shell, root mounted read-only |
| `rd.break` | stop inside the initramfs, before the real root is switched to (RHEL family) |
| `init=/bin/bash` | replace PID 1 with a shell; no services at all |

Rescue and emergency modes ask for the root password unless it is locked, in which case they fail. The classic root
password reset is `rd.break`, then `mount -o remount,rw /sysroot`, `chroot /sysroot`, `passwd`, and `touch /.autorelabel`
on systems with SELinux so file labels are repaired on the next boot. This is why physical or console access means root
access unless the boot loader is protected or the disk is encrypted.

## Persistent boot-loader settings

Do not edit the generated `grub.cfg`. Edit `/etc/default/grub` (`GRUB_TIMEOUT`, `GRUB_CMDLINE_LINUX`) and regenerate:

```bash
grub2-mkconfig -o /boot/grub2/grub.cfg            # BIOS on RHEL family
grub2-mkconfig -o /boot/efi/EFI/redhat/grub.cfg   # UEFI on RHEL family (path varies by vendor)
update-grub                                       # Debian family wrapper
grubby --update-kernel=ALL --args="console=ttyS0,115200n8"   # RHEL family, per-kernel arguments
```

Check the result in `/proc/cmdline` after the next boot.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Change vanishes after the next kernel update | Edited generated file, not the defaults | `/etc/default/grub`, regenerate |
| Boot drops to emergency mode | Bad `fstab` entry | `journalctl -xb`, fix, `mount -a` |
| Shell after `rd.break` cannot write | Root mounted read-only | `mount -o remount,rw /sysroot` |
| SELinux denies everything after reset | Labels not repaired | `touch /.autorelabel` |
