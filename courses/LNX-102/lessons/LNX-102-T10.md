# Proving that changes survive a reboot

This lesson follows the topic synthesis `synth/LNX-102/LNX-102-T10.md`, which carries the sources and the history.

## What you will be able to do

- Say for each common command whether it changes runtime state, persistent state or both.
- Check persistence by reading files, before and without a reboot.
- Plan a safe reboot test.

## Runtime state versus stored state

Linux has two copies of most settings: what the kernel or manager holds now, and what is stored to be applied at boot.
A change that only touches the first disappears; a change that only touches the second does nothing until boot.

| Command | Effect |
|---|---|
| `sysctl -w key=value` | runtime only |
| file in `/etc/sysctl.d/` | persistent only (apply now with `sysctl --system`) |
| `systemctl start unit` | runtime only |
| `systemctl enable unit` | persistent only; `enable --now` does both |
| `modprobe name` | runtime only; `modules-load.d` persists |
| `mount /dev/x /dir` | runtime only; an `fstab` line persists |
| `ip addr add` | runtime only; NetworkManager profile persists |
| `timedatectl set-timezone` | both |

## Verify without rebooting

```bash
systemd-analyze verify /etc/systemd/system/unit.service
findmnt --verify                     # check fstab
systemctl is-enabled labagent.service
grep -r swappiness /etc/sysctl.d /usr/lib/sysctl.d /run/sysctl.d
mount -a                             # test fstab lines now (a bad line shows up here, not at 3 a.m.)
```

A script such as the lab's `verify.sh` reads stored configuration for each change and prints a line per item, exiting
non-zero if any item is not persistent.

## The reboot test

1. Have console or out-of-band access and a rollback plan.
2. Take a snapshot or note the old values.
3. Reboot a test machine (or a clone), not the production one first.
4. After boot check `systemctl --failed`, `findmnt`, `sysctl key`, and `journalctl -b -p warning`.

A bad `fstab` line without `nofail` drops the boot into emergency mode; that is the classic reason to test.

## Common failure patterns

| Symptom | Likely cause | First thing to check |
|---|---|---|
| Works until reboot | Runtime-only command | file under `/etc` for it |
| Boots into emergency mode | Bad `fstab` | `findmnt --verify`, `nofail` |
| Service not running after boot | Started but never enabled | `systemctl is-enabled` |
| Setting overridden at boot | Later file or TuneD wins | order of files, `tuned-adm verify` |
