# Interrupt and timer virtualization

This lesson follows the topic synthesis `synth/LNX-332/LNX-332-T09.md`. Feature names, defaults and bit layouts depend on CPU generation (to verify).

## What you will be able to do

- Explain emulated, APICv/AVIC and posted-interrupt delivery paths.
- Decode an x86 MSI address and data pair and say which vCPU and vector it targets.
- Describe KVM's routing table and the role of irqfd.
- Diagnose an interrupt-driven performance drop from exit counts.

## Three delivery paths

| Path | Who injects | Exit for the target vCPU |
|---|---|---|
| Emulated irqchip | hypervisor on next entry | yes (a kick if running) |
| APICv / AVIC + posted interrupt | hardware | no, when the vCPU is running |
| Passthrough with interrupt remapping | IOMMU posts to the descriptor | no |

## MSI in one picture

```
address: 0xFEE | dest_id[19:12] | ... | RH[3] | DM[2] | 0
data:    trigger[15] | level[14] | delivery_mode[10:8] | vector[7:0]
```

A GSI in KVM's routing table maps to such a pair; an irqfd bound to the GSI makes writing the eventfd inject it.

## Timers

TSC-deadline writes can be emulated with a host timer; time sources must be scaled and offset consistently to survive migration.

## Checks

```
cat /sys/module/kvm_intel/parameters/enable_apicv
perf kvm stat report --event=vmexit    # MSR_WRITE and EXTERNAL_INTERRUPT counts
cat /proc/interrupts                   # affinity and distribution
```
