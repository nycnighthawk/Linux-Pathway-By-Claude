# VirtualBox from source

This lesson follows the topic synthesis `synth/LNX-332/LNX-332-T10.md`. Directory names, configure flags and licence terms change between releases; check the version you build (to verify).

## What you will be able to do

- Name the layers of the VirtualBox source tree and what runs in the kernel and in user space.
- Configure and build a headless OSE on Linux.
- Explain the roles of `VBoxSVC`, the VM process, EMT threads and PDM devices.
- Use the Main API (SDK) to automate a VM.

## Layers

| Directory under `src/VBox` | Role |
|---|---|
| `Runtime` (IPRT) | portable runtime |
| `HostDrivers` | `vboxdrv` kernel module |
| `VMM` | core VMM, PDM, hardware virtualization back ends |
| `Devices`, `Storage` | device models, disk formats |
| `Main` | API implementation, settings |
| `Frontends` | Qt GUI, VBoxManage, VBoxHeadless |
| `Additions` | guest additions |

## Building (Linux, headless)

```
./configure --disable-qt --disable-hardening   # options vary by version
source ./env.sh
kmk
# kernel modules built from out/linux.amd64/release/bin/src, then loaded
```

Needs a compiler, kernel headers for the running kernel, and development packages the configure script reports.

## Run time

`VBoxSVC` keeps machine definitions; a VM process loads the VMM, opens `vboxdrv`, starts EMT threads, and PDM devices handle I/O exits.

## Automation

The API is generated from `VirtualBox.xidl`. The SDK provides COM/XPCOM, web service and language bindings. Flow: get `IVirtualBox`, create or open an `IMachine`, lock a session, launch, handle events.

## Self-check

Try each question before you read the answers below.

1. Which part of VirtualBox runs in the host kernel?
2. What does `VBoxSVC` do?
3. Where does the Main API come from?

### Answers

1. The `vboxdrv` driver from `HostDrivers`; the rest runs in user space.
2. It keeps the registry of machines, disks and settings and serves the Main API to front ends.
3. It is generated from `VirtualBox.xidl`, which also produces the SDK bindings.
