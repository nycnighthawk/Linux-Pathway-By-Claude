# The KVM API and a minimal VMM

This lesson follows the topic synthesis `synth/LNX-332/LNX-332-T02.md`. Structure names and ioctl details vary by architecture and kernel version (to verify).

## What you will be able to do

- Name the three kinds of KVM file descriptor and what each controls.
- Write the sequence of ioctls that creates and runs a one-vCPU guest.
- Handle the common exit reasons in a run loop.
- Diagnose a failed entry or internal error.

## The ioctl ladder

```
kvm  = open("/dev/kvm")
ioctl(kvm, KVM_GET_API_VERSION)          # expect 12
vm   = ioctl(kvm, KVM_CREATE_VM, 0)
mem  = mmap(...);  copy code into it
ioctl(vm, KVM_SET_USER_MEMORY_REGION, &region)
vcpu = ioctl(vm, KVM_CREATE_VCPU, 0)
run  = mmap(vcpu, ioctl(kvm, KVM_GET_VCPU_MMAP_SIZE))
ioctl(vcpu, KVM_SET_SREGS, ...); ioctl(vcpu, KVM_SET_REGS, ...)
for (;;) { ioctl(vcpu, KVM_RUN, 0); switch (run->exit_reason) { ... } }
```

## Exits a VMM must handle

| Exit | Meaning | Typical action |
|---|---|---|
| KVM_EXIT_IO | port in or out | emulate device, fill data for `in` |
| KVM_EXIT_MMIO | access to unbacked address | emulate device |
| KVM_EXIT_HLT | guest halted | stop or wait for an event |
| KVM_EXIT_SHUTDOWN | triple fault or reset | stop |
| KVM_EXIT_FAIL_ENTRY | hardware refused the state | print the code, check segments and control registers |
| KVM_EXIT_INTERNAL_ERROR | emulation failed | check memory slots and the code address |

## Rules of thumb

- Guest RAM is ordinary `mmap` memory in your process; the slot maps it to a guest-physical address.
- Real mode needs sensible segment registers; a wrong flag gives a failed entry.
- Everything the kernel handles itself never reaches your loop.
