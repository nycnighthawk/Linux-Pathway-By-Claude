# QEMU device models and qtest

This lesson follows the topic synthesis `synth/LNX-332/LNX-332-T06.md`. QEMU's internal APIs change often (to verify against your version).

## What you will be able to do

- Describe a QOM type: parent, class init, instance init, realize.
- Explain how a device exposes registers through memory regions and a PCI BAR.
- Explain what a VMStateDescription is for.
- Write a qtest that checks register behaviour without a guest.

## Anatomy of a PCI device

```
static const TypeInfo edu_info = {
    .name = "edu", .parent = TYPE_PCI_DEVICE,
    .instance_size = sizeof(EduState), .class_init = edu_class_init };
type_init(register_types)
/* realize: memory_region_init_io(&s->mmio, ..., &edu_mmio_ops, ...);
            pci_register_bar(pdev, 0, PCI_BASE_ADDRESS_SPACE_MEMORY, &s->mmio); */
```

`-device edu` creates it. Properties appear on the command line and in QMP.

## qtest

```
qemu-system-x86_64 -accel qtest -qtest unix:/tmp/q.sock,server=on -device edu ...
> readl 0xfe000000
< OK 0x10000ed
> writel 0xfe000004 0xdeadbeef
< OK
```

Tests normally use the C helpers (`qtest_readl`, libqos `qpci_*`) and `g_assert_cmphex`.

## Things a test should cover

- Reset values and read-only registers.
- Partial and unaligned accesses.
- Interrupt state after an event.
- Migration (the VMState lists every field).
