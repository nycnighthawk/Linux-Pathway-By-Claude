# Testing KVM: kvm-unit-tests and selftests

This lesson follows the topic synthesis `synth/LNX-332/LNX-332-T08.md`. Runner scripts and status conventions change (to verify).

## What you will be able to do

- Choose between kvm-unit-tests and KVM selftests for a given bug.
- Read a test run: log lines plus exit status.
- Write a skip condition so a test never fails for lack of hardware.
- Add a regression test to a patch.

## Two suites

| | kvm-unit-tests | KVM selftests |
|---|---|---|
| Lives in | separate repository | `tools/testing/selftests/kvm` |
| Style | freestanding guest binary run under QEMU | host program that creates a VM and runs a guest function |
| Result channel | serial and debug-exit device | ucalls (`GUEST_ASSERT`, `GUEST_DONE`), KTAP output |
| Good for | instructions, MSRs, paging, nested | ioctls, state save and restore, dirty logging, capabilities |

## Running

```
./configure --arch=x86_64 && make && ./run_tests.sh msr      # kvm-unit-tests
make -C tools/testing/selftests TARGETS=kvm run_tests         # selftests
```

## Skip is not pass

Check `KVM_CHECK_EXTENSION` (selftests) or CPUID/feature bits (unit tests) first. Report skip with a reason and the skip code. A summary must count skips separately.

## A regression test per fix

Write the smallest guest or ioctl sequence that fails before the patch and passes after, and include it in the same series.

## Lab

`labs/LNX-332/test-verdict` decodes the log and exit status into pass, fail, skip or error.
