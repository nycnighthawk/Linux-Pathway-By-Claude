# A Rust VMM from rust-vmm crates

This lesson follows the topic synthesis `synth/LNX-332/LNX-332-T03.md`. Crate names and versions change quickly (to verify).

## What you will be able to do

- Name the rust-vmm crates and the job of each.
- List the steps from an empty process to a booting Linux guest.
- Build a guest memory map with a device hole and check it for overlaps.
- Explain why a Rust VMM is attractive for security and where `unsafe` remains.

## Crates and jobs

| Crate | Job |
|---|---|
| kvm-ioctls, kvm-bindings | KVM ioctls and structures |
| vm-memory | guest memory regions with checked access |
| linux-loader | place kernel, command line and boot parameters |
| vm-superio | serial and other legacy devices |
| event-manager, vmm-sys-util | epoll loop, eventfd helpers |
| virtio-queue, vhost | virtqueues and back ends |
| vm-fdt, acpi_tables | firmware tables for the guest |

## Boot steps

1. Create VM; allocate RAM; register slots.
2. Load kernel, command line, boot parameters.
3. Create vCPUs and set entry registers (and page tables for a 64-bit entry on x86).
4. Create devices and wire interrupts.
5. Run each vCPU in a thread; route I/O and MMIO exits by address.

## The memory map

```
0x0000_0000 .. 0xC000_0000  RAM (up to 3 GiB)
0xC000_0000 .. 0x1_0000_0000  device windows (hole)
0x1_0000_0000 ..            RAM above 4 GiB
```

An overlap of a device window with RAM gives silent hangs early in boot.

## Debugging a silent boot

Add `console=ttyS0 earlyprintk=serial`, check the command line placement and size, and print the memory map and slots.
