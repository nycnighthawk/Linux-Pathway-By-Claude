# Virtio and virtqueues

This lesson follows the topic synthesis `synth/LNX-332/LNX-332-T04.md`. Specification versions and optional features vary (to verify).

## What you will be able to do

- Describe the layers of a virtio device: transport, status handshake, features, configuration, queues.
- Draw a split virtqueue and trace a block request through it.
- Write the device-side loop and validate guest-controlled values.
- Explain notification suppression and why it cuts exits.

## Split virtqueue

| Area | Written by | Contents |
|---|---|---|
| Descriptor table | driver | address, length, flags (NEXT, WRITE), next |
| Available ring | driver | head index of each chain, free-running index |
| Used ring | device | head index and bytes written, own index |

A block read chain: header (device reads), data (device writes), status (device writes).

## Back-end loop

```
wait for eventfd (guest kick)
while last_avail != avail.idx:
    head = avail.ring[last_avail % size]
    walk chain (stop after `size` descriptors; check next < size and address ranges)
    process; used.ring[used_idx % size] = (head, bytes_written)
    last_avail++, used_idx++
signal irqfd (unless the driver suppressed interrupts)
```

## Validate everything

Loops, out-of-range `next`, lengths that leave RAM, indices that jump, buffers of the wrong direction. On a violation, mark the device broken and stop.
