# vhost and vhost-user

This lesson follows the topic synthesis `synth/LNX-332/LNX-332-T05.md`. Message numbers and extensions change between protocol versions (to verify).

## What you will be able to do

- Explain why a back end is moved out of the VMM's I/O thread.
- Compare vhost (kernel) and vhost-user (separate process).
- List the messages of a vhost-user session setup.
- Validate a message stream defensively.

## Where the back end lives

| Back end | Control plane | Data plane | Typical use |
|---|---|---|---|
| In the VMM | VMM | VMM thread | default, simple |
| vhost (kernel) | VMM via ioctls | kernel worker | virtio-net, vsock, scsi |
| vhost-user | VMM via socket | separate process | DPDK, SPDK, virtio-fs, GPU |

## Session setup (vhost-user)

1. GET_FEATURES, then SET_FEATURES
2. SET_OWNER
3. SET_MEM_TABLE (file descriptors for each memory region)
4. per ring: SET_VRING_NUM, SET_VRING_ADDR, SET_VRING_BASE, SET_VRING_KICK, SET_VRING_CALL

Kick is the guest's doorbell (ioeventfd); call is the interrupt (irqfd).

## Requirements and costs

- Guest memory must be shared (memfd, hugetlbfs, file).
- Migration needs dirty logging and state transfer.
- A separate process can be sandboxed, but it still maps all guest memory.

## Validate

Check version bits, payload size limits, known request numbers and that the payload is complete before use.
