# KVM internals and tracing exits

This lesson follows the topic synthesis `synth/LNX-332/LNX-332-T07.md`. File layout and tool output formats vary by kernel version (to verify).

## What you will be able to do

- Trace an exit from the hardware reason to the handler and back.
- Build and load a modified `kvm` module on a development host.
- Record and read exit statistics with `kvm_stat` and `perf kvm`.
- Choose a first fix for the top non-idle exit reason.

## Where the code is

| Path | Role |
|---|---|
| `virt/kvm/` | generic: VM, vCPU, memslots, eventfds, ioctls |
| `arch/x86/kvm/` | x86 common code, MMU, emulator, LAPIC |
| `arch/x86/kvm/vmx/`, `svm/` | Intel and AMD handlers |

## Observing

```
sudo kvm_stat -1                          # counters
sudo perf kvm stat record -a sleep 30     # record exits
sudo perf kvm stat report --event=vmexit  # summary by reason
sudo trace-cmd record -e kvm sleep 5
```

Exclude `HLT`: it is guest idle time.

## Rebuilding the module

```
make M=arch/x86/kvm modules      # against the matching build tree
sudo rmmod kvm_intel kvm && sudo insmod arch/x86/kvm/kvm.ko && sudo insmod arch/x86/kvm/kvm-intel.ko
```

Use a spare host or a nested guest. A mismatched tree fails with a version-magic error.

## From reason to action

| Dominant exit | First thing to try |
|---|---|
| EPT_VIOLATION | huge pages, pre-faulting |
| IO_INSTRUCTION / MMIO | virtio, ioeventfd, vhost |
| MSR_WRITE (APIC) / EXTERNAL_INTERRUPT | interrupt virtualisation, pin host IRQs |
| HLT | halt polling (if latency matters) |
