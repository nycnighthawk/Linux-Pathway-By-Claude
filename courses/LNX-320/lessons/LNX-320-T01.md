# Syscalls, errno, glibc versus raw calls, and strace

This lesson follows the topic synthesis `synth/LNX-320/LNX-320-T01.md`. Option names and versions of `strace` vary; check the manual page of the tool you have.

## What you will be able to do

- Explain what happens between a C call such as `open()` and the kernel handler, and what comes back.
- Handle `errno` without losing it, including `EINTR` and `EAGAIN`.
- Decide when the glibc wrapper is right and when `syscall()` is justified.
- Use `strace` to find the first failing call, count calls, and inject a failure.

## The path of a call

A wrapper puts the call number and up to six arguments in the registers the ABI names, then runs the entry instruction (`syscall` on x86-64, `svc #0` on arm64). The kernel validates the arguments, copies data to or from user memory with safe helpers, and returns a result. A negative value in the range of error codes means failure. The library turns that into the familiar pair: the function returns -1 and the thread-local `errno` holds the positive code.

Reads of the clock are the exception. `clock_gettime` normally runs in the vDSO, a page of kernel-supplied code mapped into your process, so it makes no syscall and `strace` will not show it.

## errno rules

1. Look at `errno` only after a call reported failure. Success does not clear it.
2. Copy it to a local variable before anything else runs: logging, `free` and `printf` can all change it.
3. `EINTR` means a signal arrived; retry the call, or install the handler with restart behaviour.
4. `EAGAIN` and `EWOULDBLOCK` are the same value on Linux: the operation would block.
5. pthread functions return the error code and leave `errno` alone. `strtol` needs `errno = 0` before the call.

## Wrapper or raw call

| Situation | Choice |
|---|---|
| Ordinary use | The wrapper: typed, documented, handles cancellation |
| A kernel call without a wrapper yet | `syscall(SYS_xxx, ...)`, with every argument cast to the right width |
| A tool that must avoid the library | Inline assembly or a helper library, and accept the maintenance cost |

Raw calls lose type checking, and `fork` through a raw `clone` skips the library's fork handlers.

## strace in practice

```bash
strace -f -o t.log -e trace=file ./prog      # file calls, follow children
strace -c -f ./prog                          # counts and time per call
strace -T -yy -e trace=network ./prog        # per-call time, decorated descriptors
strace -f -e trace=write -e inject=write:error=ENOSPC:when=3+ ./prog   # fail the third write onward
```

Read a trace from the top: find the first call that returned an error, then ask whether the program handled it. Many `ENOENT` results in a row usually mean a search path. `-p PID` needs permission to trace the process, which Yama's `ptrace_scope` may refuse.

## Worked example

A tool prints "No such file or directory" when the real cause is "Is a directory". The function that opens the file calls a logging helper before it prints the message, and the helper tries to read a timezone file that does not exist. Its failed `open` replaces `errno`. Saving `int e = errno;` right after the failing call, and printing `strerror(e)`, repairs it. The lab asks you to do this.

## What goes wrong

Checking `errno` after a success. Printing before saving. Treating `EINTR` as fatal. Passing an `int` where a 64-bit `off_t` is expected to `syscall()`. Tracing a latency-sensitive program with plain `strace -f` and trusting the timings.
