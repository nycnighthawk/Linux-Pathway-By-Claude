# Capabilities, seccomp-bpf, namespaces and Landlock

This lesson follows the topic synthesis `synth/LNX-320/LNX-320-T09.md`. Which Landlock rights exist depends on the kernel ABI version (to verify with `landlock_create_ruleset` version query), and some distributions restrict unprivileged user namespaces.

## What you will be able to do

- Say which of the four mechanisms answers which question.
- Install a seccomp-bpf filter that checks the architecture and denies chosen calls.
- Read capability sets and grant one capability instead of running as root.
- Explain how namespaces and Landlock confine a process, and how they combine.

## Four questions, four tools

| Question | Tool |
|---|---|
| Which privileged acts may it do? | Capabilities |
| Which system calls may it make? | seccomp-bpf |
| Which instance of a resource does it see? | Namespaces |
| Which files and ports may it reach? | Landlock (and LSMs) |

## Capabilities

Root's power is split into about forty capabilities, held in sets: permitted, effective, inheritable, bounding and ambient. Look at `/proc/PID/status` (`CapEff`, `CapBnd`) or `capsh --print`. Grant `CAP_NET_BIND_SERVICE` to bind port 80 without root (`setcap`, or `AmbientCapabilities=` in a unit). `CAP_SYS_ADMIN`, `CAP_SYS_PTRACE` and `CAP_DAC_OVERRIDE` are close to root; do not hand them out.

## seccomp-bpf

1. `prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0)`.
2. Build a filter: check the architecture field first, then the call number, then return an action (`SECCOMP_RET_ALLOW`, `SECCOMP_RET_ERRNO | errno`, `SECCOMP_RET_KILL_PROCESS`).
3. Install it with `prctl(PR_SET_SECCOMP, SECCOMP_MODE_FILTER, &prog)` or `seccomp(2)`.

A filter sees the number and the register values, not the data behind pointers, so it cannot decide on a path. Filters are inherited and can only be tightened. Return `ENOSYS` for unknown calls when libraries should fall back; `clone3` is the classic example.

## Namespaces and Landlock

Namespaces give a process its own view: mounts, PIDs, network, hostname, IPC, users, cgroups and time. A user namespace maps an ordinary user to root inside, with capabilities valid only over that namespace's resources. After `unshare(CLONE_NEWNS)` make mounts private first. Landlock lets a process restrict itself to chosen directory trees and, in newer ABIs, ports: create a ruleset, add rules, set `no_new_privs`, call `landlock_restrict_self`. Anything not granted for a handled right returns `EACCES`.

## Order of setup

Open what you need, enter namespaces, set up mounts, drop capabilities, apply Landlock, then install seccomp last, because earlier steps need calls the filter will forbid. Test each denial.

## Worked example

A document converter needs no `mkdir`, `mount` or `ptrace`. Its filter denies `mkdir` and `mkdirat` with `EPERM`, kills the process on `ptrace`, and allows the rest. A compromised converter that tries to create a persistence directory fails. The lab builds such a filter.

## What goes wrong

No architecture check, so a 32-bit entry slips through. A profile that breaks when libc starts using a new call. A namespace sandbox that leaks a mount or a descriptor. A sandbox that silently does not apply on an old kernel.
