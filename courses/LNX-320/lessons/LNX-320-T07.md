# IPC: pipes, Unix sockets with descriptor passing, shared memory and eventfd

This lesson follows the topic synthesis `synth/LNX-320/LNX-320-T07.md`. Newer peer-identity options (such as a pidfd for the peer) depend on the kernel version (to verify).

## What you will be able to do

- Choose the right local IPC mechanism for a task.
- Close pipe ends correctly so end of file arrives.
- Pass an open descriptor between processes with `SCM_RIGHTS` and check the peer's credentials.
- Share memory safely and wake a sleeper with `eventfd`.

## Pipes

`pipe2(fds, O_CLOEXEC)` gives a one-way byte stream. Writes up to `PIPE_BUF` (4096 bytes) are atomic. When every write end is closed, `read` returns 0. When every read end is closed, `write` raises `SIGPIPE` and fails with `EPIPE`. So close the ends you do not use, in every process that holds a copy.

## Unix domain sockets

| Type | Boundaries | Use |
|---|---|---|
| `SOCK_STREAM` | none | byte stream with your own framing |
| `SOCK_DGRAM` | kept | simple messages |
| `SOCK_SEQPACKET` | kept, connection-oriented | structured protocols |

`socketpair` makes two connected ends without a name. A path address is protected by file permissions and must be unlinked; an abstract address (leading null byte) has no file. `SO_PEERCRED` tells you the PID, UID and GID the peer had at connect time, supplied by the kernel.

## Passing descriptors

`sendmsg` carries control data of level `SOL_SOCKET` and type `SCM_RIGHTS` holding an array of descriptors, plus at least one byte of normal data. The receiver calls `recvmsg` with a control buffer sized by `CMSG_SPACE`, and `MSG_CMSG_CLOEXEC` to mark the new descriptors close-on-exec. They refer to the same open file descriptions. A broker can open a file the worker is not allowed to open, then hand it over.

## Shared memory and eventfd

`shm_open` plus `mmap`, or `memfd_create` plus a descriptor passed over a socket. Sealing (`F_SEAL_WRITE`, `F_SEAL_SHRINK`) stops the sender changing a buffer after handing it over. Shared memory has no built-in synchronisation: use process-shared mutexes, futexes, or atomics with an `eventfd`. `eventfd` is a 64-bit counter descriptor: `write` adds, `read` returns and clears it, and it is pollable. Read each shared field once into a local variable before you check it, because the other side may change it.

## Worked example

A sandboxed worker asks a broker for a report file. The broker checks policy, opens the file read-only and replies with a status byte and the descriptor. The worker reads the file without ever having permission to open it. The lab builds the two helper functions.

## What goes wrong

A forgotten write end keeps a pipeline open. A server ignores ancillary data and leaks descriptors. A stale socket file blocks restart. A length field is checked and then re-read from shared memory.
