# Sockets and non-blocking servers

This lesson follows the topic synthesis `synth/LNX-320/LNX-320-T08.md`. Sysctl names and defaults (`somaxconn`, buffer autotuning) differ between kernels; check them on the target.

## What you will be able to do

- Write the lifecycle of a TCP server and client with `accept4`, `connect` and `getaddrinfo`.
- Handle partial reads and writes, `EAGAIN` and `EPIPE` in non-blocking code.
- Bound buffers, connections and time so slow peers cannot hurt you.
- Shut a connection down cleanly and read `ss` output.

## Server lifecycle

1. `getaddrinfo(NULL, port, AI_PASSIVE)` or an IPv6 socket with `IPV6_V6ONLY` off.
2. `socket(..., SOCK_STREAM | SOCK_NONBLOCK | SOCK_CLOEXEC, 0)`.
3. `SO_REUSEADDR`, `bind`, `listen(fd, backlog)`.
4. When the listener is readable, `accept4` until `EAGAIN`.
5. On `EMFILE`, keep a spare descriptor to accept and drop, or the loop spins on a listener that stays readable.

## Client lifecycle

A non-blocking `connect` returns `EINPROGRESS`. Wait for writability with `poll`, then read `SO_ERROR` with `getsockopt` for the result. `getaddrinfo` returns several addresses; try them in turn within a total deadline (Happy Eyeballs races IPv6 and IPv4 with a short delay). Name resolution blocks, so keep it off an event loop.

## Reading and writing

A read returns any amount up to the request, 0 on orderly close, or `EAGAIN`. A write may take part of the data: keep the rest in an output buffer and ask for `EPOLLOUT` only while that buffer is non-empty. Use `MSG_NOSIGNAL` so a closed peer gives `EPIPE`, not a signal. Frame your messages: a stream has no boundaries.

## Limits, backpressure and shutdown

Set a high-water mark on every output buffer and stop reading from the source above it. Bound header size, request size, connections per client and idle time. For a clean close use `shutdown(fd, SHUT_WR)`, drain input briefly, then `close`; closing with unread input sends a reset that can destroy the client's response.

| Option | Why |
|---|---|
| `TCP_NODELAY` | small request and response messages without Nagle delay |
| `SO_REUSEPORT` | one listener per core with kernel balancing |
| `TCP_USER_TIMEOUT`, keepalive | detect dead peers |

## Worked example

A client writes a header and then a body in two small writes and sees 40 ms of delay each time: Nagle waits for an acknowledgement that the server delays. Setting `TCP_NODELAY` or sending one buffer fixes it. In the lab you write a client connect function with a deadline and a fallback across addresses.

## What goes wrong

Unbounded buffers. A blocking DNS call in the loop. No timeouts. Ignoring `SO_ERROR` after `connect`. Closing before draining.
