# inotify, fanotify and netlink

This lesson follows the topic synthesis `synth/LNX-320/LNX-320-T10.md`. Which fanotify events and privilege rules apply depends on the kernel version (to verify in `man fanotify_init`).

## What you will be able to do

- Watch a directory with inotify and parse the event stream correctly.
- Explain why watchers must resynchronise after an overflow.
- Say what fanotify adds (mount-wide marks, permission events) and what it costs.
- Read a netlink message and dump or monitor links and addresses.

## inotify in four steps

1. `inotify_init1(IN_NONBLOCK | IN_CLOEXEC)`.
2. `inotify_add_watch(fd, dir, IN_CREATE | IN_DELETE | IN_CLOSE_WRITE | IN_MOVED_FROM | IN_MOVED_TO)`.
3. `read` into a buffer: it holds several `struct inotify_event` records, each followed by `len` bytes of name. Advance by `sizeof(struct inotify_event) + len`.
4. Act: `IN_CLOSE_WRITE` means a file finished being written, `IN_MODIFY` fires on every write, `IN_MOVED_FROM` and `IN_MOVED_TO` share a `cookie` to pair a rename, `IN_Q_OVERFLOW` means events were lost.

Watch directories, not files: an editor that saves by writing a temporary file and renaming it replaces the inode. Watches are not recursive; add one per subdirectory and scan after adding, because files can appear before the watch exists.

## The limits

Changes made on another host over NFS or SMB produce no event. Identical queued events can be merged. The queue overflows during bursts. So treat events as hints, and reconcile by scanning at start and after `IN_Q_OVERFLOW`.

## fanotify

It marks a whole mount or filesystem, passes an open descriptor and the PID of the actor, and can send permission events that block the operation until the listener answers `FAN_ALLOW` or `FAN_DENY`. That needs privilege, and a slow or crashed listener freezes access to the mount. Keep the scanner off the watched path.

## netlink

A socket of family `AF_NETLINK` carries typed messages. `NETLINK_ROUTE` manages links, addresses and routes. A message is a header (`nlmsghdr`: type, flags, sequence, port) followed by a family header and attributes in type-length-value form. A dump request sets `NLM_F_REQUEST | NLM_F_DUMP` and ends with `NLMSG_DONE`. Multicast groups deliver notifications. `ENOBUFS` on receive means you lost some: dump again. Subscribe first, then dump, then apply newer updates. Use a library for parsing.

## Worked example

A daemon watches its configuration directory with `IN_CLOSE_WRITE | IN_MOVED_TO | IN_DELETE`, collects the burst for 100 ms and reloads once. The lab builds a watcher that prints a line per event and survives a burst of 500 files.

## What goes wrong

Reading one event per `read`. Watching a file that is replaced by rename. A scanner that scans its own files and loops. Dumping before subscribing.
