# Milestone 6: a multi-day syzkaller campaign

This milestone follows the topic synthesis `synth/LNX-404/LNX-404-T06.md`. Versions and defaults change; confirm them in current project documents (to verify).

## Goal

Run kernel fuzzing for at least two days and triage the result.

## Lessons this milestone relies on

- LNX-330-T09 (KASAN, lockdep and friends)
- LNX-331-T05 (locking, so races make sense)
- LNX-320-T09 (seccomp, namespaces, Landlock, as system-call interface knowledge)
- LNX-307-T06 (kdump and crash)

## Steps

1. Build a kernel with KASAN and KCOV and boot it in QEMU.
2. Write the manager configuration; enable the system calls of one subsystem.
3. Run for at least 48 hours and check the coverage curve each day.
4. Triage crashes against the public dashboard; minimise one reproducer.
5. Report real new findings by the right channel (private first for security bugs).

## Acceptance

- The evidence file passes the check.
- Coverage grew over the run.
- You can explain each crash title as known, new or noise.

## Lab

[Grader lab](lab:syzkaller-evidence) checks the mechanical parts of this milestone. Passing it is necessary but not enough: the evidence in your repository is what is marked. See [the capstone brief](../brief.md) for the rubric, the resource budget and what to do if you cannot run this milestone.
