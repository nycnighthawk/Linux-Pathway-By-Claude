# Milestone 1: a driver for a QEMU device with KUnit tests

This milestone follows the topic synthesis `synth/LNX-404/LNX-404-T01.md`. Versions and defaults change; confirm them in current project documents (to verify).

## Goal

Write a PCI driver for QEMU's edu device and test its logic in the kernel's unit test framework.

## Lessons this milestone relies on

- LNX-331-T01 to T03 (character devices, device model, a PCI driver for the QEMU edu device)
- LNX-331-T04 and T05 (interrupts, locking)
- LNX-330-T07 (KUnit)
- LNX-330-T03 (boot testing with QEMU)
- LNX-330-T04 (in-tree and out-of-tree modules)

## Steps

1. Write the driver so that all register access goes through small functions that tests can replace.
2. Write KUnit cases for a valid case, an out-of-range input, a stuck device and a wrong identity value.
3. Run the tests in a user-mode or QEMU kernel build.
4. Load the module in a QEMU guest with the real edu device and exercise it from user space.
5. Record the differences between the fake and the real device model.

## Acceptance

- The grader passes on the logic model.
- Your KUnit tests pass and fail when you break the driver on purpose.
- The module loads and works in the guest.
