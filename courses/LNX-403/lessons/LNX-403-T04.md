# Milestone 4: a hardened systemd unit

This milestone follows the topic synthesis `synth/LNX-403/LNX-403-T04.md`. Versions and defaults change; confirm them in current project documents (to verify).

## Goal

Run the service with the least privilege that still works and prove it.

## Lessons this milestone relies on

- LNX-220-T08 (systemd integration)
- LNX-320-T09 (capabilities, seccomp-bpf, namespaces, Landlock)
- LNX-204-T04 and T05 (SELinux and AppArmor)
- LNX-307-T05 (strace to find the calls the service needs)

## Steps

1. Record the exposure score of the plain unit with `systemd-analyze security`.
2. Add sandbox directives step by step, restarting and testing the normal path after each.
3. Use strace or the journal to find any call a filter blocks; allow only what is needed.
4. Declare the state directory and drop capabilities; use socket activation to avoid binding privileges.
5. Record the final exposure score and explain each remaining exposure.

## Acceptance

- The grader passes on the unit files.
- The service still passes your end-to-end test under the unit.
- Each directive has a one-line reason in your notes.
