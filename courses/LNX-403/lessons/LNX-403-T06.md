# Milestone 6: releases and user issues over time

This milestone follows the topic synthesis `synth/LNX-403/LNX-403-T06.md`. Versions and defaults change; confirm them in current project documents (to verify).

## Goal

Keep the service in public for weeks and handle what comes in.

## Lessons this milestone relies on

- LNX-330-T06 (format-patch, list etiquette, as a model of review manners)
- LNX-304-T03 (signing and key rotation)
- LNX-307-T10 (production on-call)
- LNX-220-T10 (packaging)

## Steps

1. Publish a security policy and issue templates.
2. Tag and sign a release; publish packages, checksums and release notes.
3. Invite at least three people to use it and report problems.
4. Triage, reply and fix; ship at least one patch release with a changelog entry.
5. Test an upgrade from the previous release before each release.

## Acceptance

- The evidence file passes the check.
- Every report has a reply.
- At least one report led to a fix, a release and a note.
