# Milestone 2: fuzzing and sanitizers in CI

This milestone follows the topic synthesis `synth/LNX-403/LNX-403-T02.md`. Versions and defaults change; confirm them in current project documents (to verify).

## Goal

Make memory errors and crashes fail the build and be kept as regression tests.

## Lessons this milestone relies on

- LNX-220-T05 (sanitizers and static analysis)
- LNX-220-T06 (unit tests, coverage, fuzzing)
- LNX-220-T04 (gdb, core dumps, valgrind)
- LNX-330-T09 (KASAN and friends as a parallel from the kernel side)

## Steps

1. Write a fuzz target for your protocol parser and seed a corpus.
2. Build tests with address and undefined-behaviour sanitizers and run them on every push.
3. Add a time-boxed fuzz job that fails on a crash and uploads the crash files.
4. Minimise one found crash and commit it as a regression test.
5. Record the code coverage reached by the corpus.

## Acceptance

- The grader passes on the fuzzer model and the CI file.
- A planted bug in a branch is found by your CI.
- Crash files are stored and replayed.
