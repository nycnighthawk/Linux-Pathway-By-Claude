# AD DNS and time

This lesson follows the topic synthesis `synth/LNX-302/LNX-302-T05.md`, which carries the sources and the history.

## What you will be able to do

- Name the SRV records a domain controller must publish and check them with `host` or `dig`.
- Configure a Linux member's resolver correctly, including with `systemd-resolved`.
- Configure `chrony` against domain controllers, and on a Samba DC with the signing socket.
- Diagnose the symptoms that look like Kerberos or LDAP faults but are DNS or time faults.

## Why these two come first

A client does not know where a DC is; it asks DNS for SRV records. Kerberos rejects any request whose timestamp differs by more than five minutes by default. Nearly every "domain is broken" report on a Linux member is one of these two.

## The records

- `_ldap._tcp.<domain>`, `_kerberos._tcp.<domain>`, `_kerberos._udp.<domain>`, `_kpasswd._tcp.<domain>`, `_gc._tcp.<domain>`.
- The same with `dc._msdcs` inserted (`_ldap._tcp.dc._msdcs.<domain>`), used to find a DC specifically.
- Site-specific variants under `_sites`, so clients prefer a nearby DC.
- A records for every DC and member; CNAMEs named by DC GUID under `_msdcs`, which replication partners use.

Check: `host -t SRV _ldap._tcp.dc._msdcs.acme.example`, `host dc1.acme.example`, a reverse lookup. On a Samba DC `samba_dnsupdate --verbose --all-names` shows and repairs missing records; `samba-tool dns query|add|delete|zonecreate` manage the zones. Samba's internal DNS accepts secure updates only and does not scavenge stale records.

## How members register

A secure dynamic update (GSS-TSIG) with the machine ticket: `net ads dns register`, SSSD's `dyndns_update = true`, or `adcli`. The record then belongs to that machine. If a DHCP server created it first, the machine is later denied the update, so choose one owner for registration.

## The member's resolver

Only DCs should answer for the domain. A router as second nameserver is a classic fault: during a DC reboot it answers NXDOMAIN for the SRV query and SSSD goes offline. With `systemd-resolved`:

```bash
resolvectl dns eth0 10.0.0.10 10.0.0.11
resolvectl domain eth0 acme.example ~acme.example
resolvectl query -t SRV _ldap._tcp.acme.example
```

Set a fully qualified hostname with `hostnamectl`; the join and the DNS registration derive from it.

## Time

Windows members follow the domain hierarchy (NT5DS) and the PDC emulator of the forest root takes an external source (`w32tm /query /status`, `w32tm /monitor`). On Linux, `chrony`:

```text
# member
server dc1.acme.example iburst
server dc2.acme.example iburst
makestep 1 3
# Samba DC additionally
bindcmdaddress 10.0.0.10
allow 10.0.0.0/16
ntpsigndsocket /var/lib/samba/ntp_signd
```

Windows clients expect signed time replies, so the DC's chrony must read Samba's `ntp_signd` socket directory (group `chrony`, mode 0750). Check with `chronyc tracking` and `chronyc sources -v`. A VM restored from a snapshot needs `chronyc makestep`.

## Worked example: the second resolver

A server lists the DC first and the office router second "for resilience". During a DC reboot, `_ldap._tcp.dc._msdcs` goes to the router, which says NXDOMAIN; SSSD marks the domain offline and caches that. The fix is two DCs as the two nameservers, with the router reached only through the DCs' forwarder.

## Common mistakes

- Choosing a domain name such as `.local` (collides with mDNS) or one the company may lose: neither the DNS domain nor the realm can be renamed in place.
- A hardware clock in local time on a host that assumes UTC (a skew of whole hours).
- Two time sources fighting (hypervisor sync and guest NTP).
