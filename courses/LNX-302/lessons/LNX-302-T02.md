# winbind vs SSSD members

This lesson follows the topic synthesis `synth/LNX-302/LNX-302-T02.md`, which carries the sources and the history.

## What you will be able to do

- List what a join creates and what must be right before it (DNS, time, hostname).
- Compare the winbind and SSSD stacks and pick one for a given server role.
- Choose an id-mapping strategy (`rid`, `autorid`, `ad`, SSSD algorithmic) and explain why it is a one-way door.
- Verify a member with `wbinfo`, `getent`, `id`, `sssctl` and `net ads testjoin`.

## Three questions every member must answer

For `alice@ACME.EXAMPLE` the host must decide: is she who she says (authentication, Kerberos), which uid and groups does she get (identity), and may she do this (authorisation). AD names a principal by SID; Unix names it by a small integer. A join gives the host a machine account and keys, and a caching daemon translates between SIDs and uids for NSS and PAM.

## Before the join

1. DNS: the host resolves the domain's SRV records (`_ldap._tcp.dc._msdcs.<domain>`) through a DC.
2. Time: within five minutes of the DC (`chronyc tracking`).
3. A fully qualified hostname inside the domain.
4. A join account with rights on one OU, not a domain admin.

## Winbind

`net ads join` creates the computer account and stores secrets in `/var/lib/samba/private/secrets.tdb`. `winbindd` talks to a DC and generates ids through an `idmap` back-end.

| Back-end | Id comes from | Same on every host? | Use |
|---|---|---|---|
| `tdb` | first come, first served, local database | no | the default domain `*` only |
| `rid` | range base plus the RID | yes, if the range matches | one domain, no POSIX attributes |
| `autorid` | per-domain slices of one pool | yes, if the pool matches | many domains, no POSIX attributes |
| `ad` | `uidNumber`/`gidNumber` in the directory | yes | stable ids, needs attributes on every account |

Tools: `wbinfo -t` (trust secret), `wbinfo -u`/`-g` (list), `wbinfo -n alice` (name to SID), `wbinfo -S <sid>` (SID to uid), `net ads testjoin`, `getent passwd ACME\\alice`. Wire up NSS and PAM with `authselect` (RHEL family) rather than editing the files.

## SSSD

`realm join acme.example` discovers the domain, installs packages, joins with `adcli` and writes `/etc/sssd/sssd.conf` (mode 0600). With `ldap_id_mapping = True` (default) ids are computed from the SID inside a configured range, so hosts with the same settings agree. With `False`, POSIX attributes are read from AD. Useful settings: `use_fully_qualified_names`, `fallback_homedir`, `access_provider`, `ad_gpo_access_control`, `cache_credentials`. Tools: `realm list`, `realm permit -g group@domain`, `sssctl domain-status`, `sssctl user-checks alice`, `sss_cache -E`, `journalctl -u sssd`.

## Choosing

- Logins only: SSSD (offline cache, GPO access control, default on most distributions).
- A Samba file server that serves domain users: winbind, or SSSD with Samba's `sss` idmap back-end so that both agree.
- Existing NFS data or ids that must survive a domain rebuild: POSIX attributes (`idmap_ad`, `ldap_id_mapping = False`).

The mapping choice is written down before the first user logs in. Changing it later changes uids and orphans file ownership.

## Worked example: a join that fails

`realm join` reports `Clock skew too great`. The VM was restored from a snapshot and chrony had not stepped the clock. `chronyc makestep`, then retry. Other messages point elsewhere: `Preauthentication failed` is a wrong or locked account, `Cannot find KDC for realm` is DNS, and `KDC has no support for encryption type` is an RC4 versus AES mismatch.

A quieter failure: a host powered off for months returns and no AD user can log in. The machine password rotated while it was away; `net ads testjoin` or `sssctl domain-status` shows the broken secure channel. Rejoin, and monitor it.

## Common mistakes

- Joining a template image and cloning it; clones fight over one machine account.
- Giving two hosts different `idmap` ranges for the same domain and then sharing files between them.
- Hand-editing PAM and NSS instead of using `authselect`.
