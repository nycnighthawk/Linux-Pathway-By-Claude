# Samba AD DC replication

This lesson follows the topic synthesis `synth/LNX-302/LNX-302-T03.md`, which carries the sources and the history.

## What you will be able to do

- Join an additional Samba domain controller and verify that every partition replicates.
- Read `samba-tool drs showrepl` output and map Windows error numbers to causes.
- Explain why SYSVOL needs a separate mechanism and set up the one-way copy.
- Show, transfer and seize the FSMO roles, and retire a DC cleanly.

## Multi-master in one paragraph

Every DC accepts writes. Each change gets a local update sequence number, and each DC remembers the highest number it accepted from each peer. Attribute-level metadata (version, time, originating DC) lets every DC choose the same winner for a conflict. The KCC computes the connections between DCs. Five naming contexts replicate: domain, configuration, schema, `DomainDnsZones` and `ForestDnsZones`.

## Join and verify

```bash
samba-tool domain join acme.example DC -U 'ACME\administrator' --dns-backend=SAMBA_INTERNAL
```

Before the join: the resolver points at an existing DC, `kinit administrator` works, the clock agrees, and the DNS forwarder is given when using the internal DNS. After the join, run the `samba-ad-dc` service (not the member-server units).

| Command | Purpose |
|---|---|
| `samba-tool drs showrepl` | inbound and outbound neighbours, last success, failure count |
| `samba-tool drs replicate <dest> <src> <NC>` | force one partition |
| `samba-tool dbcheck --cross-ncs` | database consistency (add `--fix` to repair) |
| `samba-tool fsmo show` | role holders |
| `samba-tool visualize reps` | text picture of the live topology |

The KCC can need up to fifteen minutes to create connections after a join.

## Reading errors

| Error | Usual cause |
|---|---|
| 8524 | DNS lookup of the partner failed: the `_msdcs` GUID CNAME is missing or the resolver is wrong |
| 1722 | RPC server unavailable: firewall or daemon down |
| 8453 | replication access denied: machine account or rights |
| 8606 / 8240 | inconsistencies or lingering objects |

Check in this order: DNS, Kerberos and time, firewall, database. `samba_dnsupdate --verbose --all-names` recreates missing records.

## SYSVOL

SYSVOL holds group policy and logon scripts as files. Windows DCs replicate it with DFS-R; Samba has no equivalent. The standard answer is a one-way copy from the DC that holds the PDC emulator role, run on a timer on the others with `rsync -XAavz --delete-after` (the `-XA` flags keep ACLs), followed by `samba-tool ntacl sysvolreset` on first use. Edit policy only on the source DC, or the next copy overwrites the edit.

## FSMO roles

Five roles cannot be multi-master: schema master and domain naming master (one per forest); PDC emulator, RID master and infrastructure master (one per domain). `samba-tool fsmo transfer --role=all` moves them gracefully. `fsmo seize` takes them from a dead holder, which must then never return without a wipe.

## Worked example: a stalled DC

`showrepl` on `dc2` shows result 8524 for `DomainDnsZones`. `host -t CNAME <guid>._msdcs.acme.example` returns nothing: the DC's resolver pointed at an external server during the join, so the record was never registered. Fix: set the resolver to the DCs, run `samba_dnsupdate --verbose --all-names`, then `samba-tool drs replicate dc1 dc2 DC=DomainDnsZones,DC=acme,DC=example`.

## Retiring a DC

Transfer roles, run `samba-tool domain demote` while the host is alive, then check DNS for SRV and A records that still name it. For a dead host use `samba-tool domain demote --remove-other-dead-server=<name>`, delete the stale DNS records and seize roles only if needed.

## Common mistakes

- Powering on a DC that was off for longer than the tombstone lifetime (it can resurrect deleted objects).
- Editing GPOs on a DC that is not the SYSVOL source.
- Raising the functional level in a mixed forest before the Samba release supports it.
