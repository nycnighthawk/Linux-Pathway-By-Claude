## Why a translation layer is needed

A Windows client sends SMB requests: open with share-mode flags, byte-range locks, security descriptors, named streams. A Linux filesystem knows owners, groups, nine mode bits and optionally POSIX ACLs. Samba is a user-space server that implements SMB on top of the filesystem and translates where the two models differ. `smbd` forks one process per client connection, so a bad request harms one session. `nmbd` answers NetBIOS name queries and is optional when DNS is used. `winbindd` maps domain accounts to Unix ids and is only needed when the server is a domain member.

## The configuration file

Everything lives in `/etc/samba/smb.conf`: a `[global]` section, optional `[homes]` and `[printers]`, and one section per share.

```ini
[global]
    workgroup = LAB
    server role = standalone server
    server min protocol = SMB2_10
    server signing = mandatory
    log level = 1
    log file = /var/log/samba/%m.log

[projects]
    path = /srv/samba/projects
    read only = no
    valid users = @staff
    force group = staff
    create mask = 0660
    directory mask = 2770
```

`testparm -s` parses the file and prints the effective configuration, and it exits non-zero on errors. `smbcontrol all reload-config` applies most changes to running daemons. Parameters such as `server role` need a restart. Macros such as `%m` (client name), `%U` (user) and `%S` (share name) are expanded per connection.

## Accounts

Samba cannot use the hashes in `/etc/shadow`, because SMB needs NT hashes or Kerberos keys. Create the Unix user first, then give it an SMB password with `smbpasswd -a alice` or `pdbedit -a -u alice`. `pdbedit -L` lists SMB users. Guest access needs both `map to guest = Bad User` and `guest ok = yes`, and it should stay off for anything that is not meant to be public.

## Two permission models

- **POSIX model.** Samba maps the Windows security tab onto owner, group and other, and masks (`create mask`, `directory mask`, `force group`) shape new files. Linux tools tell the whole story, but the Windows dialog is an approximation: deny entries and fine-grained inheritance cannot be stored.
- **Windows ACL model.** With `vfs objects = acl_xattr`, `map acl inherit = yes` and `store dos attributes = yes`, Samba keeps the full security descriptor in an extended attribute and enforces it. The filesystem must support xattrs, and the underlying directory modes should be permissive enough that the NT ACL decides. Edit ACLs from Windows, with `smbcacls`, or with `samba-tool ntacl`.

Do not mix the models on one tree: a `chmod` from Linux and an ACL edit from Windows then fight over the same file.

## Security parameters

| Parameter | Effect |
|---|---|
| `server min protocol = SMB2_10` | refuses SMB1; a scanner that needs SMB1 should not decide the policy for everyone |
| `server signing = mandatory` | refuses unsigned traffic, defeating tampering and relay at some CPU cost |
| `smb encrypt = required` | forces SMB3 encryption (global or per share) |
| `hosts allow` / firewall | expose TCP 445 only; 139 only if NetBIOS is needed |
| SELinux `samba_share_t` | the shared directory needs the label (or the `samba_export_all_rw` boolean as a blunt tool) |

## Worked example: "Access denied"

Alice can authenticate but cannot write to `[projects]`. Check in this order:

1. `testparm -s`: is the share what you think it is?
2. `smbstatus`: is she connected, and as whom?
3. The per-client log at `log level = 3`: the NT_STATUS code. `NT_STATUS_LOGON_FAILURE` means no SMB password; `NT_STATUS_ACCESS_DENIED` after a good login means permissions.
4. `ls -ldZ /srv/samba/projects` and `getfacl`: owner `root:root 0755` stops her whatever the share says, because `create mask` affects only new files.
5. The audit log for an SELinux denial.

## Common mistakes

- Editing the share but not the directory mode or SELinux label.
- Changing an `idmap config` range on a live domain member (it orphans file ownership; see [winbind and SSSD](lesson:LNX-302-T02)).
- Serving the same tree over NFS and SMB with different models.
- Lowering `server min protocol` to satisfy one old device.
