# Containerfile craft: multi-stage, non-root, distroless

This lesson follows `synth/LNX-310/LNX-310-T05.md`, which carries the sources and history.

## What you will be able to do

- Use multi-stage builds so compilers and caches never reach the runtime image.
- Order instructions by volatility and use `.dockerignore` so the cache works.
- Run as a numeric non-root user, with exec-form entrypoints and correct signal handling.
- Choose between a full, slim, UBI/Alpine, distroless and `scratch` base and state the trade.

## Instructions that matter

`RUN` commits a layer; deleting a file later does not remove it from the earlier layer. `COPY` is preferred to `ADD` (use `ADD --checksum` for remote files). `ENV` persists, `ARG` is build-time but visible in `docker history`; neither holds secrets. `ENTRYPOINT` is the executable and `CMD` supplies default arguments; write both as JSON arrays. The shell form wraps the process in `sh -c`, which becomes PID 1, often swallows `SIGTERM`, and turns a graceful stop into a `SIGKILL` after the grace period. Wrapper scripts end with `exec "$@"`. Use `--init` or `catatonit` when children need reaping. `HEALTHCHECK` helps Docker and Compose; Kubernetes uses probes.

## Cache order and context

Least volatile first: base image, OS packages (`apt-get update` and `install` in one `RUN`, `--no-install-recommends`, clean `/var/lib/apt/lists`), dependency manifests and install, then source, then build. A `.dockerignore` excludes `.git`, `node_modules`, build output and secrets; it protects the cache and prevents leaks. Pin base images by digest (`FROM image:1.2@sha256:...`) and let a bot update them.

## Multi-stage

```dockerfile
# syntax=docker/dockerfile:1
FROM golang:1.24-bookworm AS build
WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o /out/app ./cmd/app

FROM gcr.io/distroless/static-debian13:nonroot
COPY --from=build /out/app /app
USER 65532:65532
ENTRYPOINT ["/app"]
```

The build stage is large; the final image holds only the binary. `--target build` stops at a stage for tests. For interpreted languages build a virtualenv or `node_modules` in a builder and copy it into a slim runtime with the *same* libc.

## Non-root by design

Use a numeric UID (`USER 10001:10001`) so Kubernetes can verify `runAsNonRoot`. The application owns only data and temp directories; binaries stay root-owned and read-only. For platforms that assign a random UID, give writable paths group 0 with `chmod g=u`. Ports under 1024 need `CAP_NET_BIND_SERVICE` or a high port inside. Test the image under the restrictions you will run with:

```bash
docker run --rm --read-only --tmpfs /tmp --cap-drop ALL --security-opt no-new-privileges --user 10001 app:1
```

## Choosing a base

| Base | Shell and package manager | libc | Notes |
|---|---|---|---|
| debian, ubuntu | yes | glibc | wide compatibility, large |
| slim variants | yes | glibc | docs and locales removed |
| UBI micro, Alpine | partial | glibc / musl | musl differs in DNS, locale, wheels |
| distroless | no | glibc | `:nonroot`, `:debug` tags; signed |
| `scratch` | no | none | copy CA certificates and `/tmp` yourself |

Minimal images shrink the scanner report and an attacker's toolbox, but they remove `exec sh`. Debug with `kubectl debug`, `nsenter` ([T09](lesson:LNX-310-T09)) or a `:debug` tag outside production.

## Worked example: signals and certificates

A Node image uses `CMD npm start`. Rolling updates take 30 seconds a pod because `npm` does not forward `SIGTERM`. Switching to `CMD ["node","server.js"]` fixes it. A Go service on `scratch` fails with a certificate-authority error until `/etc/ssl/certs/ca-certificates.crt` is copied from the build stage or `distroless/static` is used.

## Failure patterns

- `COPY . .` copies `.env`, SSH keys and the `.git` history into a layer.
- `latest` tags change under a green pipeline.
- A setuid shell or writable `/etc/passwd` returns root to a "non-root" image: check `find / -perm -4000`.
- `--squash` destroys layer sharing and history that scanners use.
