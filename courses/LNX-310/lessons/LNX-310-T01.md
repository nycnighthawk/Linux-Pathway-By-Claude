## The three layers

A container is an ordinary process. **Namespaces** give it private views: mount table, hostname (UTS), IPC objects, process IDs, network stack, user and group IDs, the cgroup tree root and the clocks. Each process belongs to exactly one namespace of every type, and the links in `/proc/<pid>/ns/` carry an inode number: equal numbers mean a shared namespace. **Control groups** (version 2) give it a budget in a single tree under `/sys/fs/cgroup`. **Capabilities, seccomp and an LSM** (SELinux, AppArmor) restrict what it may do even as UID 0.

Three system calls matter: `clone` creates a child in new namespaces, `unshare` moves the caller into new ones, `setns` joins an existing one. Their shell faces are `unshare`, `nsenter` and `lsns`. A PID namespace takes effect for children, so `unshare --pid` needs `--fork`, and the first child becomes PID 1 of the new namespace with init's special signal rules.

User namespaces are the key to rootless operation. A process can create one without privilege, becomes root inside it, and owns the other namespaces it creates there. The mapping in `/proc/<pid>/uid_map` reads "inside-ID, outside-ID, length". Root inside is an unprivileged UID outside, so a breakout lands in a weak account.

## cgroup v2 in practice

There is one hierarchy. A controller must be listed in the parent's `cgroup.subtree_control` before children can use it, and a group that holds processes cannot delegate controllers below it (the "no internal process" rule), so processes live in leaves. The files you will use:

| File | Meaning |
|---|---|
| `memory.max` | hard limit: reclaim, then the OOM killer for this group |
| `memory.high` | throttle: allocations above it are slowed, nothing is killed |
| `memory.events` | counters `max`, `oom`, `oom_kill` |
| `cpu.max` | `quota period` in microseconds, e.g. `20000 100000` is one fifth of a core |
| `cpu.weight` | proportional share when CPUs are contended (default 100) |
| `cpu.stat` | `nr_throttled`, `throttled_usec` |
| `pids.max` | task count cap, the fork bomb guard |
| `cgroup.kill` | write `1` to kill every task in the group |

systemd should own the tree on a systemd host: ask for a scope or use `Delegate=yes`, and make the runtime's cgroup driver match the manager, or two writers will fight.

## Capabilities

Root's power is split into about forty capabilities (`CAP_NET_BIND_SERVICE`, `CAP_NET_ADMIN`, `CAP_SYS_ADMIN`, `CAP_CHOWN` and so on). Each thread has permitted, effective, inheritable, bounding and ambient sets, shown as hex masks in `/proc/<pid>/status` (`CapEff:`, `CapBnd:`). Decode them with `capsh --decode=<hex>`. Runtimes drop the bounding set to a short list, set `no_new_privs`, and install a seccomp filter. `CAP_SYS_ADMIN` is nearly root, so granting it is almost the same as `--privileged`.

## Worked example: a container with only util-linux

```bash
sudo mkdir /sys/fs/cgroup/demo
echo 100M | sudo tee /sys/fs/cgroup/demo/memory.max
echo 64   | sudo tee /sys/fs/cgroup/demo/pids.max
echo "20000 100000" | sudo tee /sys/fs/cgroup/demo/cpu.max
sudo sh -c 'echo $$ > /sys/fs/cgroup/demo/cgroup.procs; exec unshare --pid --fork --mount --uts --ipc --net --mount-proc=/srv/rootfs/proc chroot /srv/rootfs /bin/sh'
```

Inside, `hostname demo` does not change the host, `ps` shows PID 1, `ip link` shows only a down loopback. From the host, `readlink /proc/<pid>/ns/net` differs from `readlink /proc/self/ns/net`. Allocating 200 MiB makes `memory.events` show `oom_kill 1`. A real runtime replaces `chroot` with `pivot_root`, mounts a read-only `/sys` and a tmpfs `/dev`, masks paths like `/proc/kcore`, drops capabilities, sets `no_new_privs`, applies seccomp and finally `execve`s the command.

## Failure patterns

- A `--cpus` quota causing latency while the host is idle: read `cpu.stat` for `nr_throttled`.
- A limit that silently does not apply because the controller was never enabled or delegated: always read the file, not the configuration.
- Page cache counted against `memory.max` so a file-heavy container looks full without a leak.
- Container root treated as safe: without a user namespace it is UID 0 for file ownership on the host.
