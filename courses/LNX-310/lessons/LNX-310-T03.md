- Fix bind-mount ownership problems with `--userns=keep-id`, `:U` and `podman unshare`.
- Group containers in a pod and move it to Kubernetes YAML with `generate kube` and `kube play`.
- Write Quadlet `.container`, `.volume` and `.pod` files and run them as systemd services.

## Rootless in one picture

Podman has no daemon. Each run forks a monitor (`conmon`) and calls `crun` or `runc`. A rootless container starts in a user namespace that maps your UID to container root and a range from `/etc/subuid` and `/etc/subgid` (`user:start:count`) to the other IDs. Check it with `podman unshare cat /proc/self/uid_map`. After changing the ranges run `podman system migrate`.

Consequences: files the container writes to a bind mount appear on the host owned by a subordinate UID; ports below `net.ipv4.ip_unprivileged_port_start` cannot be bound; cgroup limits need delegation to the user's systemd slice; `ping` needs `net.ipv4.ping_group_range`. Networking uses `pasta` (default since Podman 5) with Netavark and Aardvark DNS for user networks. Storage is under `~/.local/share/containers/storage`.

Ownership fixes: `--userns=keep-id` maps your UID to the same number inside (good for development); `-v dir:/data:U` chowns the source to the container's mapped user; `podman unshare chown 999:999 dir` does it by hand; idmapped mounts (`:idmap`) do it in the kernel.

## Pods and kube play

A pod has an infra container that holds shared namespaces. By default the members share network, IPC and UTS, so they talk over `localhost` and ports are published on the pod:

```bash
podman pod create --name app -p 8080:80
podman run -d --pod app docker.io/library/nginx:1.27
podman run -d --pod app docker.io/library/redis:7
podman generate kube app > app.yaml
podman kube play app.yaml     # podman kube down app.yaml removes it
```

`kube play` implements a subset of Kubernetes (Pods, Deployments, PVCs, ConfigMaps, Secrets); Services and scheduling are absent.

## Quadlet

Quadlet is a systemd generator. Put files in `~/.config/containers/systemd/` (rootless) or `/etc/containers/systemd/` (root); `web.container` becomes `web.service`, `data.volume` becomes `data-volume.service`.

```ini
[Unit]
Description=Static site
[Container]
Image=docker.io/library/nginx:1.27
PublishPort=127.0.0.1:8080:80
Volume=site.volume:/usr/share/nginx/html:ro,Z
ReadOnly=true
NoNewPrivileges=true
DropCapability=ALL
AddCapability=NET_BIND_SERVICE
HealthCmd=curl -fs http://localhost/ || exit 1
Notify=healthy
[Service]
Restart=always
[Install]
WantedBy=default.target
```

Then `systemctl --user daemon-reload && systemctl --user start web.service`. Debug generation with `/usr/lib/systemd/system-generators/podman-system-generator --user --dryrun`. Enable lingering (`loginctl enable-linger $USER`) or the service dies at logout. Set `Pod=app.pod` in a container file to join a pod, `Yaml=` in a `.kube` file to run `kube play`, and `AutoUpdate=registry` with `podman-auto-update.timer` for updates with rollback.

## SELinux and mounts

On Fedora and RHEL a bind mount keeps the host label and the container is denied. `:Z` relabels for this container alone, `:z` for sharing. Never use `:Z` on a shared tree such as your home directory.

## Failure patterns

- A container that works over SSH and vanishes after logout: lingering is off.
- "permission denied" writing to a bind mount: a UID mapping or SELinux problem, in that order of checking.
- `systemctl --user` reports no bus: `XDG_RUNTIME_DIR` is unset after `su` or `sudo -u`.
- A typo in a Quadlet key is ignored: always run the dry run.
