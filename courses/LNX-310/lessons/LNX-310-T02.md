## The image side

An image is content-addressed JSON plus tar layers. A **layer** is a tar changeset; deletion is a whiteout entry `.wh.<name>` and an opaque directory is `.wh..wh..opq`. The **config** holds the platform, `rootfs.diff_ids` (digests of the *uncompressed* layers), default `Entrypoint`, `Cmd`, `Env`, `User`, and the build `history`. The **manifest** lists the config and the ordered layers as descriptors (`mediaType`, `digest`, `size`). An **index** maps platforms to manifests, so one tag serves several architectures. A tag is a mutable pointer, a digest is an identity: the layer digest in a manifest covers the *compressed* bytes, the `diff_id` the uncompressed ones, and recompressing changes the first but not the second.

On disk an OCI layout is `oci-layout`, `index.json` and `blobs/sha256/<hex>`. `sha256sum` of a blob equals its file name, which is how any holder verifies it. The distribution specification gives the registry HTTP API (`/v2/<name>/manifests/<ref>`, `/blobs/<digest>`, uploads, tags, referrers).

## The runtime side

A **bundle** is a directory with `rootfs/` and `config.json`. The file has `process` (args, env, cwd, user, capabilities, `noNewPrivileges`), `root` (path, `readonly`), `mounts`, `hooks`, and a `linux` section: namespaces, UID/GID mappings, `cgroupsPath`, `resources`, `seccomp`, `maskedPaths`, `readonlyPaths`, `rootfsPropagation`. The lifecycle is `create` (namespaces and mounts built, process waiting), `start`, `kill`, `delete`; `state` prints `creating`, `created`, `running` or `stopped`. This is the same list of actions you did by hand in [T01](lesson:LNX-310-T01).

## The stack

```
kubelet / docker / podman / nerdctl
   CRI gRPC or Engine API
containerd or CRI-O        images, snapshots, sandboxes
   shim v2 (ttrpc) or conmon
shim                       parent of the container, keeps stdio, reports exit
   OCI command line
runc / crun / runsc / kata
   kernel
```

**runc** (Go) is the reference low-level runtime; **crun** (C) is smaller and faster to start, default on Fedora and RHEL. **containerd** manages content, snapshots (overlayfs, native, lazy-pulling ones) and tasks; its CRI plugin serves Kubernetes. **CRI-O** is a CRI-only runtime whose version tracks Kubernetes. The **shim** is why the daemon can restart without killing containers, and why one pod costs one shim. A `RuntimeClass` names a handler so sandboxed runtimes (T10) sit beside runc. Docker Engine delegates to containerd; Kubernetes dropped `dockershim` in 1.24 but Docker-built images still run because they are OCI images.

## Worked example: run a bundle by hand

```bash
mkdir -p b/rootfs && cd b
podman export $(podman create alpine) | tar -C rootfs -x
runc spec                                 # writes config.json
# edit: process.terminal=false, process.args=["/bin/sh","-c","echo hi; sleep 5"]
sudo runc create demo && sudo runc state demo   # status: created
sudo runc start demo  && sudo runc state demo   # status: running
sudo runc delete -f demo
```

To inspect an image without a runtime: `skopeo copy docker://docker.io/library/alpine:3.21 oci:/tmp/a:3.21`, then `jq . /tmp/a/index.json` and `sha256sum /tmp/a/blobs/sha256/*`.

## Failure patterns

- "Digest mismatch": a compressed digest compared with a `diff_id`, or a mirror that rewrote the manifest.
- A pod failing at sandbox creation: the CRI runtime configuration lacks the handler named by the RuntimeClass.
- Limits flapping: the kubelet cgroup driver and the runtime's `SystemdCgroup` setting disagree.
- A multi-arch pull from a mirror that flattened the index returns the wrong platform.
