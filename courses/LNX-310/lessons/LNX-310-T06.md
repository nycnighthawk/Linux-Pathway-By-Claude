## The protocol

`GET /v2/` returns `401` with a `WWW-Authenticate: Bearer realm=...,service=...,scope=...` header; the client obtains a short-lived token from the realm and retries. Then `GET /v2/<name>/manifests/<tag-or-digest>` (with an `Accept` header of media types), and `GET /v2/<name>/blobs/<digest>` for the config and layers, often redirected to object storage. Push is `POST /blobs/uploads/`, data, digest check, then `PUT` of the manifest. Tags move, digests do not. Rate limits (Docker Hub for anonymous pulls) and outages make a private mirror a reliability control.

## Client configuration

Podman, Buildah, Skopeo and CRI-O read `/etc/containers/registries.conf` (and `registries.conf.d/`, `~/.config/containers/registries.conf`):

```toml
unqualified-search-registries = ["registry.example.com"]
short-name-mode = "enforcing"

[[registry]]
prefix = "docker.io"
location = "docker.io"
[[registry.mirror]]
location = "mirror.internal:5000/dockerhub"

[[registry]]
location = "registry.badvendor.example"
blocked = true
```

`prefix` selects names, `location` is the real source (so it can rewrite), mirrors are tried first, `pull-from-mirror = "digest-only"` trusts a mirror only for pinned references, `insecure = true` allows HTTP or an untrusted certificate. Private CAs go in `/etc/containers/certs.d/<host:port>/ca.crt`. `/etc/containers/policy.json` decides whether pulled content is acceptable (signature requirements); `registries.conf` decides where it comes from. Credentials: `podman login` writes `${XDG_RUNTIME_DIR}/containers/auth.json` (cleared at logout); `docker login` uses `~/.docker/config.json`; credential helpers avoid base64 passwords on disk. Docker's own `registry-mirrors` covers Docker Hub only; containerd uses `/etc/containerd/certs.d/<host>/hosts.toml`; Kubernetes adds `imagePullSecrets` and `imagePullPolicy`.

## Skopeo

Transports: `docker://`, `oci:`, `dir:`, `docker-archive:`, `containers-storage:`. No daemon and no root needed.

```bash
skopeo inspect --raw docker://docker.io/library/alpine:3.21 | jq '.manifests[].platform'
skopeo inspect docker://docker.io/library/alpine:3.21 | jq -r .Digest
skopeo copy --all --preserve-digests docker://docker.io/library/alpine:3.21 docker://registry.internal/base/alpine:3.21
skopeo sync --src yaml images.yaml --dest docker registry.internal/mirror
```

Without `--all`, `copy` takes only the host platform and produces a single-platform manifest. `--preserve-digests` keeps manifest bytes (and the digest) identical and fails if conversion would be needed.

## Mirrors

A **pull-through cache** (a registry in proxy mode) fetches on a miss. A **full mirror** is filled with `skopeo sync` or `oc-mirror`, which suits air-gapped sites. **Replication** (Harbor, Quay, cloud registries) copies projects. Digest pinning makes all three safe, since the client verifies bytes whoever served them. Garbage collection removes unreferenced blobs; deleting a manifest only removes the reference.

## Worked example: ARM nodes fail after mirroring

A team mirrors `app:2.0` with plain `skopeo copy`; ARM nodes report `exec format error`. `skopeo inspect --raw docker://registry.internal/app:2.0` shows a single manifest, not an index. Re-run with `--all --preserve-digests`; the destination now lists both platforms and the same digest as the source.

## Failure patterns

- Fifty parallel CI jobs hit anonymous rate limits from one egress IP.
- `insecure = true` and `--tls-verify=false` left in place after a test.
- A search list of several registries lets a squatted short name win.
- Tag-based mirrors drift from upstream.
