## The Engine

`dockerd` listens on `/var/run/docker.sock` (root and group `docker`). Everything uses its REST API. Below it, containerd and runc execute containers. `/etc/docker/daemon.json` holds `data-root`, `log-driver` and `log-opts` (the default `json-file` driver never rotates unless `max-size` and `max-file` are set), `live-restore`, `userns-remap`, `registry-mirrors` (Docker Hub only), `default-runtime` and `runtimes`. Docker Engine 29 makes the containerd image store default on fresh installs, deprecates cgroup v1, and offers experimental nftables.

Group `docker` is root: `docker run -v /:/host --privileged alpine chroot /host` gives a root shell. Mitigations: rootless mode, `userns-remap`, a socket proxy that filters API calls, and never mounting the socket into application containers. Published ports are NAT-ed ahead of host firewalls such as `ufw`, so publish on `127.0.0.1` and use the `DOCKER-USER` chain for policy.

## BuildKit

A frontend compiles the Dockerfile into a build graph; independent branches run in parallel, unused stages are skipped, and each step is cached by its inputs. Use `# syntax=docker/dockerfile:1` first. Key features:

- `RUN --mount=type=cache,target=...` keeps a package cache outside layers.
- `RUN --mount=type=secret,id=npm,target=/root/.npmrc` exposes a secret for one step only; pass it with `--secret id=npm,src=file`. Never use `ARG` or `ENV` for secrets: they remain in image metadata.
- `COPY --link`, heredocs, `ADD --checksum`.
- `--platform linux/amd64,linux/arm64 --push` builds an index; other-architecture steps use QEMU (slow) or native builders.
- External caches: `--cache-to/--cache-from type=registry,ref=...,mode=max`, `type=local`, `type=gha`, `type=s3`.
- Builders and drivers: `docker` (built in), `docker-container` (needed for cache export and multi-platform), `kubernetes`, `remote`. `docker buildx bake` builds several targets from one file.
- Attestations: `--provenance=mode=max` and `--sbom=true` (used in [T08](lesson:LNX-310-T08)).

Order for caching: base, OS packages, dependency manifests and install, then source. Prune with `docker builder prune --filter until=168h`.

## Compose

```yaml
services:
  web:
    build: .
    ports: ["127.0.0.1:8000:8000"]
    environment:
      DATABASE_URL: postgres://app@db:5432/app
    depends_on:
      db: {condition: service_healthy}
  db:
    image: postgres:17
    secrets: [db_password]
    environment: {POSTGRES_PASSWORD_FILE: /run/secrets/db_password}
    healthcheck: {test: ["CMD-SHELL", "pg_isready -U app"], interval: 5s, retries: 10}
secrets:
  db_password: {file: ./db_password.txt}
```

Compose creates one network per project and services reach each other by name. Daily commands: `up -d`, `ps`, `logs -f`, `exec`, `run --rm`, `down` (`-v` deletes named volumes) and `config`, which prints the resolved model and is the first step when interpolation misbehaves. Shell variables beat `.env`. `depends_on` with a health condition orders start only; the application must still retry connections.

## Worked example: removing a leaked token

A Dockerfile has `ARG NPM_TOKEN` and writes `.npmrc`, then deletes it. The token stays in the layer and in `docker history`. Replace it with `RUN --mount=type=secret,id=npm,target=/root/.npmrc npm ci`, build with `--secret id=npm,src=$HOME/.npmrc`, and revoke the old token.

## Failure patterns

- `-p 5432:5432` on a cloud VM behind `ufw`: still reachable.
- Logs without rotation fill the disk; `docker system df -v` shows it.
- `docker system prune -a --volumes` on the wrong host deletes data.
- `COPY . .` before dependency install invalidates the cache on every edit.
