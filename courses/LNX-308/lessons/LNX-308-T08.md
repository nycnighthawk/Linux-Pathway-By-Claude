# Proxmox/oVirt clusters

## What you will be able to do

- Explain why a virtualisation cluster needs quorum, fencing, shared storage and separated networks.
- Do the quorum arithmetic for a given design.
- Name the architectural difference between Proxmox VE and oVirt.

## What a cluster manager adds

`virsh` knows one host. A cluster manager keeps one authoritative record of hosts, guests, networks, storage and users; places guests; migrates them (T05); restarts them after a failure; and schedules backups. The four concepts that decide whether it is safe:

- **Quorum.** Decisions need a strict majority of votes, so at most one partition can proceed. Three nodes tolerate one failure; two nodes tolerate none unless a third vote is added (a QDevice or witness). With V votes the quorum is floor(V/2)+1. A cluster that loses quorum goes read-only so that no one can make conflicting changes.
- **Fencing.** Before restarting a guest elsewhere, the cluster must be sure the failed host is not still running it: power control (IPMI), a watchdog that resets a node which cannot prove it is healthy, or storage leases. Detection is not fencing; without fencing two hosts write one disk.
- **Shared or replicated storage.** The survivors must be able to open the disk: NFS, iSCSI, Ceph RBD, or replication with a known data-loss window.
- **Separate networks.** Heartbeat traffic must not compete with storage and migration traffic.

## Proxmox VE

A Debian-based distribution (AGPLv3, optional paid subscription) with KVM, LXC, ZFS and integrated Ceph. There is no central server: every node runs the same services and a cluster file system, `pmxcfs`, mounted at `/etc/pve`, replicates configuration through Corosync. Tools: `pvecm create NAME`, `pvecm add IP`, `pvecm status`, `qm` (VMs), `pct` (containers), `pvesm` (storage), `ha-manager`. Corosync wants a dedicated low-latency link (under about 5 ms, UDP 5405-5412), and a second link for redundancy. HA uses `pve-ha-crm` and `pve-ha-lrm` with watchdog fencing: a node that loses quorum while running HA guests is reset after about 60 seconds and the guests restart elsewhere, so plan for about two minutes of failover. Newer releases add affinity rules, maintenance mode and dynamic load balancing. Check the current release before adopting.

## oVirt

A central **engine** (Java, PostgreSQL) controls hosts that run `vdsmd`, which drives libvirt. Hosts belong to clusters (a CPU baseline) inside data centres; storage domains hold images; the SPM host manages storage metadata; fencing agents power-cycle failed hosts; the engine can run as a self-hosted VM. It is a rigorous enterprise model with a heavier installation. Red Hat retired its commercial product in favour of OpenShift Virtualization (KubeVirt), and the community project continues with slower releases (oVirt 4.5.7 was announced as generally available on 13 January 2026, the first release in about two years).

## Others

OpenStack and CloudStack for clouds; KubeVirt and Harvester for Kubernetes-centred shops; Incus clustering for small mixed container and VM clusters; Pacemaker for hand-built clusters.

## Worked example: maintenance that stops the cluster

A three-node cluster (3 votes, quorum 2). An administrator reboots two nodes at once for firmware updates. One vote remains, below the quorum: the survivor goes read-only and cannot start guests. Update one node at a time and run `pvecm status` before the next. Overriding with `pvecm expected 1` is an emergency measure that voids the guarantees.
