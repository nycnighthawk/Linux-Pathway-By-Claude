# Live migration between hypervisors

This lesson follows the topic synthesis `synth/LNX-308/LNX-308-T05.md`, which carries the sources, the history and the failure cases.

## What you will be able to do

- Describe pre-copy and post-copy migration and when each fits.
- State the prerequisites: CPU, machine type, storage, network and firewall.
- Run, monitor, tune and abort a migration with `virsh`.

## What moves

Memory (copied while the guest keeps dirtying it), device and CPU state, storage (shared, or copied alongside) and network identity (the guest keeps its MAC and IP; switches must relearn the port). **Pre-copy** copies all memory, then repeatedly the pages dirtied meanwhile, then pauses the guest briefly to send the rest. Until the last step the source holds the authoritative state, so a failure leaves the guest running where it was. **Post-copy** resumes the guest on the destination early and fetches missing pages on demand: it always finishes, but if the link breaks mid-way the memory is split between hosts and the guest can be lost.

## Prerequisites

- KVM on both hosts, reachable to each other; libvirt daemons authenticated by SSH, TLS or Kerberos.
- A destination QEMU at least as new as the source's, the same versioned machine type.
- CPU: `host-model` lets libvirt check compatibility before the move; `host-passthrough` cannot be checked and the destination must be at least as capable. In mixed fleets use a **named baseline** from `virsh hypervisor-cpu-baseline`; compare with `virsh cpu-compare`.
- Storage: shared (NFS, iSCSI, Ceph) or copied with `--copy-storage-all`/`--copy-storage-inc`; for the `all` form, create matching empty images on the destination first.
- Network: same bridge or network names and VLANs; destination firewall open for QEMU's range 49152-49215/tcp; no passthrough devices.

## The command

```bash
virsh migrate --live --persistent --undefinesource --verbose \
      --parallel --compressed --tls web1 qemu+ssh://hv2/system
```

Useful options: `--copy-storage-all`, `--auto-converge`, `--postcopy`, `--bandwidth MiB/s`, `--timeout N`, `--p2p`, `--tunnelled`, `--xml new.xml` (adjust paths for the destination). Never use `--unsafe`: it skips the cache-safety checks and is how corruption is made.

Monitor from a second terminal: `virsh domjobinfo web1` (data remaining, dirty rate, iterations, downtime), `virsh migrate-setmaxdowntime web1 300`, `virsh migrate-setspeed`, `virsh migrate-postcopy web1`, and `virsh domjobabort web1` to cancel (the guest keeps running on the source).

## Worked example: it never finishes

A guest with an in-memory cache dirties 800 MB/s on a 1 GB/s link with a 50 ms downtime budget. `domjobinfo` shows the remaining data hovering above the threshold. In order of safety: raise the downtime budget to a few hundred ms; add `--auto-converge` to throttle the guest; add `--parallel` for throughput; if the network is dependable, switch to post-copy with `virsh migrate-postcopy`. If none is acceptable, abort and migrate in a quiet period.

Also remember the quiet failure: a guest using `host-passthrough` with AVX-512 migrates to a host without it, and crashes with an illegal instruction after resuming. libvirt could not check this beforehand.
