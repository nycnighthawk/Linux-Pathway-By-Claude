## What a system container is

An operating-system tree started in its own kernel namespaces (mount, PID, UTS, IPC, network, user, cgroup, time), limited by cgroups, restricted by capabilities, seccomp and an LSM profile, and running a full init so it behaves like a small server. It shares the host's kernel, so it starts in a fraction of a second and costs only its own processes, but the isolation is only as strong as the kernel and the policy. A **privileged** container's root is the host's root; an **unprivileged** one maps its UIDs through a user namespace to an ordinary range (`lxc.idmap`, `PrivateUsers=pick`). Use unprivileged by default.

## systemd-nspawn

```bash
debootstrap bookworm /var/lib/machines/bld                    # or dnf --installroot, pacstrap, mkosi
systemd-nspawn -D /var/lib/machines/bld --private-users=pick  # shell in the tree
systemd-nspawn -b -D /var/lib/machines/bld -M bld             # boot its init
machinectl start bld ; machinectl login bld ; machinectl shell bld
machinectl list ; machinectl poweroff bld ; machinectl enable bld
```

Persistent settings live in `/etc/systemd/nspawn/bld.nspawn` (`[Exec] Boot=yes PrivateUsers=pick`, `[Network] VirtualEthernet=yes`, `[Files] BindReadOnly=/srv/src:/src`); resource limits go in a drop-in for `systemd-nspawn@bld.service` (`MemoryMax=`, `TasksMax=`, `Delegate=yes`). nspawn makes `/sys` and `/proc/sys` read-only, forbids module loading, clock changes and device creation, and `systemd-detect-virt` inside reports `systemd-nspawn`.

## LXC and Incus

LXC is a library and tools (`lxc-create`, `lxc-start`, `lxc-attach`) with a `config` file per container: `lxc.rootfs.path`, `lxc.net.0.type = veth`, `lxc.idmap = u 0 100000 65536`, `lxc.cgroup2.memory.max`. Unprivileged use needs `/etc/subuid` and `/etc/subgid` ranges.

Incus is a daemon with a REST API over LXC for containers and QEMU for virtual machines, forked from LXD in 2023 after Canonical moved LXD in-house and relicensed it.

```bash
incus admin init --auto
incus launch images:debian/12 web1                 # container; add --vm for a virtual machine
incus config set web1 limits.memory=1GiB limits.cpu=2
incus config device add web1 src disk source=/srv/src path=/src readonly=true
incus snapshot create web1 before-upgrade ; incus snapshot restore web1 before-upgrade
```

## Containers or VMs

Use a container for trusted, same-kernel workloads: builds, test trees, many small services. Use a VM when you need your own kernel, a non-Linux guest or a boundary against hostile tenants. Containers cannot load modules, set most sysctls or run a different kernel, and `/proc/meminfo` may show host values unless `lxcfs` corrects them.

## Worked example: a build container

`debootstrap --include=systemd-container bookworm /var/lib/machines/bld ...`, then write `bld.nspawn` with `Boot=yes`, `PrivateUsers=pick`, `VirtualEthernet=yes` and `BindReadOnly=/srv/src:/src`, add the drop-in `MemoryMax=1G`, and `machinectl start bld`. Writes outside the bind mount stay in the tree, the source is read-only, and the container cannot take more than 1 GiB. Compare the privileged mistake: binding the host's `/etc` read-write into a container whose root is host root lets a script in the container edit the host's `/etc/passwd`.
