# Storage: PV/PVC, StorageClass, CSI

This lesson follows the topic synthesis `synth/LNX-311/LNX-311-T06.md`, which carries the sources, the history and the failure cases.

## What you will be able to do

- Explain the claim, volume and class objects and how binding works.
- Choose access modes, binding mode and reclaim policy for a workload.
- Describe the CSI controller and node split, and use expansion and snapshots.

## Objects

- **PersistentVolume (PV)**: a cluster-level disk. **PersistentVolumeClaim (PVC)**: a namespaced request for size, access mode and class. They bind one-to-one.
- **StorageClass**: names a CSI provisioner, back-end parameters, `reclaimPolicy`, `volumeBindingMode`, `allowVolumeExpansion`. A claim that names a class gets a volume created on demand (dynamic provisioning); one default class may exist.
- Pods use claims through `volumes[].persistentVolumeClaim`. `emptyDir` is scratch tied to the pod; `hostPath` is a node directory and a portability and security hazard.

## Access modes

`ReadWriteOnce` (one node), `ReadWriteOncePod` (one pod), `ReadOnlyMany`, `ReadWriteMany` (needs a shared filesystem or distributed back end). After a node crash a RWO disk may still be attached to the dead node, giving a multi-attach error until the control plane detaches it.

## Binding, reclaim, expansion

- `WaitForFirstConsumer` creates the disk after scheduling, in the right zone; `Immediate` creates it at once and can strand the pod in another zone.
- `reclaimPolicy: Delete` removes the disk when the claim goes; `Retain` keeps it (the PV becomes Released and needs manual cleanup).
- With `allowVolumeExpansion: true` raise the claim's request; shrinking is impossible. The filesystem resize can lag behind the disk resize.

## CSI

A driver is a controller Deployment (sidecars for provisioning, attach, snapshot, resize) plus a node DaemonSet (stage and publish). Provisioning problems are in the controller sidecar logs; mount problems in the node plugin and kubelet. Snapshots use `VolumeSnapshotClass`, `VolumeSnapshot` and `VolumeSnapshotContent`; a new PVC can take a snapshot as its data source.

## Stateful workloads

A StatefulSet's `volumeClaimTemplates` gives each replica a stable claim. Claims are not deleted when it scales down unless the retention policy says so. Replication is not backup.

## Worked example: the namespace that took a disk with it

A test namespace was deleted. Its claim used a class with `Delete`, so the cloud disk was removed. For irreplaceable data use `Retain`, snapshots and an application backup, decided before the first write.
