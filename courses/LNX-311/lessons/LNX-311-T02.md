# kubeadm install on 3 VMs; HA control-plane design

This lesson follows the topic synthesis `synth/LNX-311/LNX-311-T02.md`, which carries the sources, the history and the failure cases.

## What you will be able to do

- Prepare nodes and bootstrap a cluster with a reviewable kubeadm configuration file.
- Join control-plane and worker nodes and explain what the token, the CA hash and the certificate key protect.
- Choose between stacked and external etcd and size a control plane by quorum arithmetic.

## Prepare every node the same way

Unique hostname and machine id, synchronised clock, swap off, kernel modules `overlay` and `br_netfilter`, sysctls for bridged traffic and IP forwarding, containerd with the **systemd cgroup driver**, and `kubeadm`, `kubelet`, `kubectl` at pinned, matching versions. Open 6443 (API), 2379 and 2380 (etcd), 10250 (kubelet) between nodes.

## Bootstrap from a file, not from flags

```yaml
apiVersion: kubeadm.k8s.io/v1beta4
kind: ClusterConfiguration
kubernetesVersion: v1.35.0
controlPlaneEndpoint: "k8s-api.example.internal:6443"
networking:
  podSubnet: 10.244.0.0/16
  serviceSubnet: 10.96.0.0/12
---
apiVersion: kubelet.config.k8s.io/v1beta1
kind: KubeletConfiguration
cgroupDriver: systemd
```

```bash
sudo kubeadm init --config kubeadm.yaml --upload-certs
```

`kubeadm init` runs phases: preflight, certificates, kubeconfigs, etcd and control-plane static pods, upload of configuration, bootstrap token, CoreDNS and kube-proxy. Afterwards nodes stay NotReady until a **pod network plugin** is installed, and its CIDR must match `podSubnet`.

## Joining

- The **bootstrap token** (24 h by default) lets a node ask for a kubelet certificate.
- The **CA public-key hash** lets the joiner verify the cluster before trusting it.
- The **certificate key** (2 h) decrypts the shared PKI for another control-plane node.

Join control-plane nodes one at a time: each adds a stacked etcd member. Create fresh values with `kubeadm token create --print-join-command` and `kubeadm init phase upload-certs --upload-certs`.

## Designing for failure

| Members | Quorum | Failures tolerated |
|---|---|---|
| 1 | 1 | 0 |
| 2 | 2 | 0 |
| 3 | 2 | 1 |
| 4 | 3 | 1 |
| 5 | 3 | 2 |

Stacked etcd (one member per control-plane node) is simple, but a lost node costs an API server and a member together. External etcd separates failure domains at the price of more machines. Put a health-checked load balancer or virtual IP (kube-vip, keepalived plus HAProxy, a cloud LB) behind `controlPlaneEndpoint`, and spread nodes over independent failure domains.

## Worked example: the endpoint chosen too late

cp1 was initialised with its own address. cp2 can join as a worker, but joining as a control-plane node fails on certificate names because the API server certificate lacks a shared address. The fix means reissuing the certificate and every kubeconfig. Decide the endpoint, pod subnet and service subnet before `kubeadm init`.
