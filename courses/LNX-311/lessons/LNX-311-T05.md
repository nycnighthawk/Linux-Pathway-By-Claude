## Requests, limits and QoS

The scheduler places by **requests**, never by live usage or limits. At run time a CPU request is a weight, a CPU limit a throttling quota, a memory limit a hard ceiling that triggers the OOM killer.

| QoS class | Condition | Eviction order |
|---|---|---|
| Guaranteed | every container: requests equal limits for CPU and memory | last |
| Burstable | some request or limit set | middle |
| BestEffort | nothing set | first |

`LimitRange` gives per-namespace defaults; `ResourceQuota` caps totals.

## The placement vocabulary

- `nodeSelector`: exact label match.
- **Node affinity**: expressions, required (`requiredDuringSchedulingIgnoredDuringExecution`) or preferred.
- **Pod affinity and anti-affinity**: relative to other pods within a topology domain (`kubernetes.io/hostname`, zone).
- **Topology spread constraints**: bound the skew between domains; usually better than hard anti-affinity.
- **Taints** repel (`NoSchedule`, `PreferNoSchedule`, `NoExecute`); **tolerations** permit. A taint keeps the wrong pods out but does not attract the right ones: add a selector or affinity as well.
- **PriorityClass** ranks pods; higher priority may preempt lower. Low-priority placeholder pods give cheap headroom.

When a pod is Pending read the events: they list which filter rejected how many nodes.

## Autoscaling

HPA formula: `desired = ceil(current * currentMetric / targetMetric)`. It measures utilisation against the *request*, so pods without requests cannot be scaled on CPU percentage. Use `behavior` (stabilisation window, rate policies) against flapping. VPA adjusts requests; do not drive the same metric with both. A **node autoscaler** adds nodes shaped by the constraints of Pending pods and removes idle nodes after draining them; it cannot fix a pod whose rules no node shape can satisfy.

## Worked example: the GPU pool

GPU nodes carry the taint `gpu=true:NoSchedule` and the label `pool=gpu`. A training Job needs a toleration for the taint **and** `nodeSelector: pool: gpu`. With only the toleration, ordinary tolerant pods may also spread onto the expensive nodes.
