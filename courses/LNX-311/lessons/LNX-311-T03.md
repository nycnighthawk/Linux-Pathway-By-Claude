# Cluster upgrades, drain and cordon

This lesson follows the topic synthesis `synth/LNX-311/LNX-311-T03.md`, which carries the sources, the history and the failure cases.

## What you will be able to do

- Apply the version-skew policy and plan a one-minor-version upgrade.
- Run the kubeadm upgrade sequence for the first control-plane node, the others and the workers.
- Drain a node safely and write PodDisruptionBudgets that allow progress without breaking quorum.

## Skew rules

The API server sets the reference. Controller manager and scheduler: same minor or one older. Kubelet and kube-proxy: same or up to three minors older in current releases, never newer. `kubectl`: one minor either side. The control plane moves **one minor version at a time**, control plane first, nodes afterwards. Highly available API servers may differ by one minor only during the rolling upgrade (check the release page for the exact numbers for your version).

## The sequence

1. Read release notes and scan for removed APIs (apiserver metric `apiserver_requested_deprecated_apis`, tools such as pluto).
2. Snapshot etcd. A control plane cannot be downgraded; restore from the snapshot is the rollback.
3. First control-plane node: upgrade the `kubeadm` package, `kubeadm upgrade plan`, `kubeadm upgrade apply vX.Y.Z`.
4. On that node: `kubectl drain`, upgrade `kubelet` and `kubectl`, restart the kubelet, `kubectl uncordon`.
5. Other control-plane nodes and workers: `kubeadm upgrade node`, then the same drain, package, restart, uncordon.
6. Upgrade the network plugin and other add-ons against their own compatibility tables.

```bash
kubectl drain NODE --ignore-daemonsets --delete-emptydir-data --timeout=300s
kubectl uncordon NODE
kubectl get pdb -A         # ALLOWED DISRUPTIONS must be above zero for a drain to progress
```

## Cordon, drain and the eviction API

`cordon` stops new pods arriving (the node is tainted unschedulable); running pods stay. `drain` cordons, then evicts pods through the eviction API, which consults PodDisruptionBudgets. Pods without an owner are not recreated elsewhere, so drain refuses them. DaemonSet pods are skipped with `--ignore-daemonsets`. `--disable-eviction` bypasses budgets: avoid it.

## PodDisruptionBudgets

A budget states `minAvailable` or `maxUnavailable` for pods selected by labels. It limits *voluntary* disruption only (drains, evictions), not crashes. Two traps: `minAvailable` equal to the replica count blocks every drain; a single replica protected by a budget can never be moved. For a three-member quorum database use `maxUnavailable: 1` and spread members over nodes with anti-affinity or topology spread constraints.

## Worked example: the hanging drain

`kubectl drain` waits forever. `kubectl get pdb -A` shows `web` with `minAvailable: 3` for three replicas and zero allowed disruptions. Change the budget to `maxUnavailable: 1` (or scale up), then drain again. Forcing the eviction would break the owner's availability promise.
