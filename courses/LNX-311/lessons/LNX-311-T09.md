## The CRD

A CRD declares a group, kind (singular, plural, list), scope and versions. Each version carries an OpenAPI v3 **structural schema**: every field has a type, so the API server can validate, prune unknown fields and default values. Exactly one version is the **storage version**; a conversion webhook translates between versions if their structure differs (and a broken webhook breaks every read).

```yaml
apiVersion: apiextensions.k8s.io/v1
kind: CustomResourceDefinition
metadata: {name: widgets.example.com}
spec:
  group: example.com
  scope: Namespaced
  names: {kind: Widget, plural: widgets, singular: widget, shortNames: [wg]}
  versions:
  - name: v1
    served: true
    storage: true
    subresources: {status: {}}
    additionalPrinterColumns:
    - {name: Size, type: integer, jsonPath: .spec.size}
    schema:
      openAPIV3Schema:
        type: object
        properties:
          spec:
            type: object
            required: [size]
            properties:
              size: {type: integer, minimum: 1, maximum: 10}
```

Prefer schema validation and CEL `x-kubernetes-validations` rules to admission webhooks for custom resources.

## Status, finalizers, owners

The `status` subresource separates what the user wants (spec) from what the controller observed (status, with `conditions`). A **finalizer** blocks deletion until the controller has cleaned up external resources and removed it. **Owner references** make deleting an owner garbage-collect its dependents.

## The controller loop

Watch the custom kind and the kinds it owns, reconcile idempotently (read, compare, create or update dependents, write status), requeue on error. It needs RBAC for exactly what it touches; an operator asking for cluster-admin is an escalation path.

## Operating operators

```bash
kubectl get crd | grep example.com
kubectl explain widget.spec
kubectl get widget w1 -o yaml          # read status.conditions and events
kubectl -n widgets-system logs deploy/widgets-operator
```

Helm does not upgrade CRDs, so apply them first. Deleting a CRD deletes all its objects. Remove custom resources **before** the operator, or finalizers will leave objects stuck in Terminating.

## Worked example: the stuck namespace

An operator was deleted first; its Widgets kept finalizers and the namespace hung in Terminating. Reinstall the operator, delete the Widgets so it can clean up, then remove the operator. Stripping finalizers by hand leaves the external resources behind.
