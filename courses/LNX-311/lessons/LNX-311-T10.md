# Troubleshooting nodes, control plane and apps

This lesson follows the topic synthesis `synth/LNX-311/LNX-311-T10.md`, which carries the sources, the history and the failure cases.

## What you will be able to do

- Follow a fixed ladder from symptom to layer, and read status, events, logs and exit codes.
- Debug pods without a shell, and nodes when the API is down.
- Capture evidence before you restart anything.

## The ladder

1. **Scope**: one pod, one workload, one node, one namespace, or everything? Compare healthy and unhealthy instances.
2. `kubectl get pods -A -o wide`, then `kubectl describe pod` (events at the bottom, last state, exit code).
3. `kubectl logs POD -c C` and `--previous` for crashed containers.
4. `kubectl get events -A --sort-by=.lastTimestamp` (events expire after about an hour).
5. `kubectl describe node`: conditions Ready, MemoryPressure, DiskPressure, PIDPressure, NetworkUnavailable; allocated resources.
6. `kubectl get --raw='/readyz?verbose'` for the API server's own checks.

## Pod states

| State | Meaning and next step |
|---|---|
| Pending, no node | scheduling failed: read the FailedScheduling event (resources, taints, affinity, unbound claim) |
| ContainerCreating (long) | image pull, volume mount or CNI sandbox: events say which |
| ImagePullBackOff | wrong name or tag, no credentials, registry unreachable |
| CrashLoopBackOff | read `--previous` logs; exit 137 is signal 9 (often OOM), 143 is SIGTERM |
| Running, not Ready | readiness probe failing: check path, port, app logs |
| Terminating forever | stuck finalizer or unreachable node |

## No shell in the image

```bash
kubectl debug -it POD --image=busybox:1.36 --target=app          # ephemeral container
kubectl debug POD --copy-to=pod-debug --container=app -- sh       # a modified copy
kubectl debug node/NODE -it --image=busybox:1.36                  # node shell
kubectl run t --rm -it --image=curlimages/curl -- sh              # test the network from inside
```

## Services, DNS, nodes, control plane

- No traffic: `kubectl get endpointslices -l kubernetes.io/service-name=NAME`; compare selector and pod labels; readiness.
- DNS: CoreDNS pods and endpoints; `ndots` search expansion makes things slow rather than broken.
- Node NotReady: `systemctl status kubelet`, `journalctl -u kubelet -e`, then the runtime (`crictl info`), cgroup driver mismatch, clock skew, swap, disk pressure, expired kubelet certificate, missing CNI configuration.
- API down: `crictl ps -a` and `crictl logs` on a control-plane node; static pod manifests; certificate expiry; `etcdctl endpoint health` and `endpoint status`; alarms.

## Worked example: capture first

A NotReady node shows kubelet errors about its runtime socket. Before restarting anything: save `kubectl describe node`, the kubelet journal and `crictl info`. Then fix the runtime's cgroup driver, restart containerd and the kubelet, and verify. Restarting first would have destroyed the evidence.
