# Series passes checkpatch; boots on x86_64 and arm64

## Define the problem

A kernel change is reviewed as a series of small patches. Reviewers expect each patch to build, each commit to leave the tree in a working state so that bisection stays possible, and the result to boot on more than one architecture. The problem is to prepare a series that meets the project's style rules mechanically and works on at least x86_64 and arm64, with evidence rather than hope.

## History and approaches

Patches moved from tarball diffs to mailed series with conventions on subject, sign-off and size. Tools followed: checkpatch checks style and common mistakes, sparse and Coccinelle find deeper problems, and b4 manages series. Cross compilation and QEMU made multi-architecture builds practical on one machine, and bots now build submitted series across many configurations.

## Current state

The author writes the series with each commit self-contained and bisectable. For every commit, a script builds the kernel for each target architecture and configuration and runs the style checker. The final tree is booted in QEMU for each architecture to a known point (the init process starting), and tests run. The cover letter explains the series and the test coverage. Version numbers and a changelog track revisions.

## Assessment: the good, the bad and the ugly

The routine catches most trivial review comments before sending and prevents embarrassment from a series that breaks the build. Limits: building every commit on every architecture takes time, configuration coverage is never complete, and boot tests only show that the kernel starts. The ugly parts are architecture-specific breakage that only shows on a configuration nobody tried and fixes pushed to the wrong patch of a series.

## Applications beyond this domain

Series discipline and per-commit builds appear in other large projects that use mailing lists or stacked pull requests, and in monorepo CI that tests each commit.

## Examples

A worked example: a series of three patches renames a function, adds a driver and enables it in the build. A per-commit build shows that the second patch fails on arm64 because a header is missing on that architecture. The fix goes into that patch and the series is rebuilt. A failing example: all patches passed on x86_64 but the final tree panicked early on arm64 due to a different memory layout; the boot test caught it.
