# 100+ node scale test

## Define the problem

Behaviour at ten nodes says little about behaviour at a hundred: the API server, etcd, the scheduler, the network plugin and the monitoring stack all have limits. The problem is to find the limits of the platform with a large number of nodes, which most learners cannot host, so the exercise uses simulated nodes or rented capacity and records measurements honestly.

## History and approaches

Kubernetes scalability work defined service level objectives for the API server and published thresholds for supported cluster sizes. Tools such as kubemark and KWOK simulate nodes cheaply; load generators such as ClusterLoader2 create objects at a controlled rate.

## Current state

The test grows the cluster in steps, creating pods, services and policies, and measures API latency, scheduling throughput, etcd size and latency, control plane memory and the cost of network policy at scale. Monitoring itself is measured, because Prometheus is often the first thing to fall over. Results are recorded with the version and configuration used.

## Assessment: the good, the bad and the ugly

Simulation is cheap but does not exercise real kubelets or real network paths. Real scale is costly. Results are specific to a configuration and must be repeated after upgrades. The ugly part is that the first bottleneck is often not the one you expected, such as a controller list operation or a webhook.

## Applications beyond this domain

Scale testing is used for databases, message systems, search clusters and network control planes.

## Examples

A worked example: at one thousand pods per node group the scheduler keeps up but Prometheus memory doubles; the fix is to reduce label cardinality. A failing example: simulated nodes passed a test that real nodes failed because of image pull load.

## Related problems and ideas

Related topics: capacity planning, autoscaling, cost modelling and federation as an alternative to one very large cluster.

## Active research

Work includes better node simulation and scalability limits for new APIs (to verify).

## Future direction

Expect scale tests to be part of release qualification for platform changes.
