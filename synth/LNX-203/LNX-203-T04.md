# Turning command output into answers: awk for columns, jq and yq for structure

## Define the problem

Operations work is largely reading and reshaping output: which processes use the most memory, which log lines mention a user, which volumes in a JSON inventory have no snapshot, which hosts in a YAML file lack a key. Output arrives in two shapes. Much of the classic Unix toolset prints **columns of text** meant for people (`ps`, `df`, `ss`, `ls -l`, log files), where the fields are separated by white space or a delimiter and the structure is implicit. Modern tools and APIs print **structured data** (JSON from `ip -j`, `lsblk -J`, `journalctl -o json`, cloud and Kubernetes clients; YAML in configuration files), where nesting and types are explicit and a line-oriented tool gets them wrong. A sysadmin needs a language for each shape, small enough to type at a prompt and robust enough to put in a script.

For columns, the answer is `awk`: a language whose main loop reads input record by record, splits each record into fields and runs actions on those that match a pattern. For JSON, it is `jq`, a filter language over a stream of JSON values. For YAML, `yq` brings the jq model to YAML files. This slice teaches the three tools together, because the real skill is choosing the right one: do not parse JSON with awk, and do not run a JSON processor for a three-column report. It also covers what to do instead of parsing human-oriented output at all, when a tool offers a machine-readable mode.

## History and approaches

Awk was created in 1977 at Bell Laboratories; its authors, Aho, Weinberger and Kernighan, gave it a name made of their initials for the kind of quick data manipulation that was clumsy in the shell and heavy in C. It reached wide use through the 1985 revision (sometimes called "new awk", `nawk`), which added user-defined functions and other features, and through the 1988 book by the three authors. Several implementations exist today: the original one-true-awk (still maintained and used on BSD systems), GNU awk (`gawk`), which adds many extensions such as `asort`, `strftime`, `gensub`, in-place editing and, in recent releases, native CSV handling, and `mawk`, a fast implementation that Debian-family distributions have often used as the default `awk`. The POSIX standard describes the common core: patterns, actions, fields, the built-in variables, associative arrays and the standard functions [src: man-pages 26cfc1f1e66c7b1c] [src: man-pages c2e3cd5bc07ca9b3]. Because the default `awk` differs by distribution, portable scripts stay within POSIX and anything that needs `gawk` says so in its first lines and installs it.

For structured data, the 2010s brought JSON as the default format of web APIs and then of command-line tools. `jq`, created by Stephen Dolan and first released in 2012, supplied the missing "sed for JSON": a small functional language with paths, filters and pipes. It has remained compact enough to learn in an afternoon, and its manual and its tutorial define the language [web: jqlang.github.io]. Reimplementations (`gojq`, `jaq`) trade features and speed. YAML, a superset-like format popular for configuration (Kubernetes, Ansible, CI systems), followed with `yq`, and here the history is a trap: there are two unrelated projects with the same name. The one written in Go by Mike Farah uses a jq-like syntax and edits YAML files directly, and the other, a Python program by Andrey Kislyuk, is a thin wrapper that converts YAML to JSON, runs the real `jq` and converts back. Their command lines are similar but not identical, and distributions package different ones [web: mikefarah.gitbook.io]. The way to know which you have is `yq --version`.

Alternatives exist for each job. For columns, `cut`, `sort`, `uniq -c`, `column -t`, `paste`, `join` and `sed` cover simple cases, and Python covers anything with state (see the Python slice). For JSON and YAML, Python's `json` and `yaml` modules, `jc` (which converts the output of dozens of classic tools into JSON), and `miller` (a data processor for CSV and JSON) are common. The strongest alternative is to avoid parsing: ask the tool for structured output (`ip -j addr`, `lsblk -J`, `findmnt -J`, `systemctl show -p ActiveState --value unit`, `df --output=source,pcent`, `stat --printf`, `ps -o pid=,rss= -p PID`).

## Current state

### awk

An awk program is a list of `pattern { action }` pairs. For each input record (by default a line), awk splits it into fields `$1`, `$2` ... `$NF` on the field separator (by default runs of white space), and runs the action of every pattern that matches. A missing pattern matches every record; a missing action prints the record. `BEGIN { }` runs before input and `END { }` after it. Core variables are `NR` (record number), `NF` (number of fields), `FS` and `OFS` (input and output field separators), `RS` and `ORS` (record separators), `FILENAME` and `$0` (the whole record). Awk is a loop around your code, with associative arrays and `printf`.

```bash
awk '{ print $1, $NF }' file                       # first and last field
awk -F: '$3 >= 1000 { print $1 }' /etc/passwd      # users with UID of 1000 or more
awk 'NR > 1 { sum += $2 } END { print sum / (NR - 1) }' data.txt
awk '/error/ && !/timeout/' app.log                # regex patterns combined
awk -v min=80 '$5+0 > min { print $6, $5 }' <(df -P | tail -n +2)
awk '{ count[$1]++ } END { for (k in count) print count[k], k }' access.log | sort -rn | head
```

Points worth knowing: fields are strings that become numbers in numeric context, and `$5+0` forces conversion (so `95%` becomes 95); assigning to a field or to `$0` makes awk rebuild the record with `OFS`; `-F` accepts a regular expression (`-F'[,;]'`) and, for a single space, a literal space (`-F' '` is the default behaviour, not a literal single-space split); `printf` follows C formats and needs explicit newlines; regex matching uses `~` and `!~`; `getline` reads additional input; `system()` runs a command (a source of quoting trouble). The POSIX specification states the rules for field splitting, uninitialised variables (empty string and zero) and comparison (numeric if both sides look numeric, string otherwise), which are the sources of most surprises [src: man-pages c2e3cd5bc07ca9b3]. The Rocky Linux sed/awk/grep book gives a practical tour, with the common one-liners [src: rocky-docs 7951972943f2f8a8], and GNU awk's manual documents the extensions, including the `--csv` mode of recent versions, `-i inplace` and `asorti` [src: man-pages 364b1fe7a0f893bb].

Awk handles delimited text that does not contain the delimiter in a quoted field. For real CSV with quoted commas, use `gawk --csv`, `miller` or Python's `csv` module; a field-splitting `-F,` breaks on `"Smith, John"`.

### jq

A jq program is a filter applied to each JSON value on input. The simplest filter is `.`, which prints the input pretty-printed, and filters compose with the pipe `|`.

```bash
ip -j addr show | jq -r '.[] | select(.operstate == "UP") | .ifname'
lsblk -J -o NAME,SIZE,TYPE,MOUNTPOINT | jq -r '.blockdevices[] | select(.type == "disk") | "\(.name)\t\(.size)"'
journalctl -o json -u sshd --since today | jq -r 'select(.PRIORITY | tonumber <= 4) | .MESSAGE'
jq -r '.items[] | [.metadata.name, .status.phase] | @tsv' pods.json
jq '[.[] | {host: .name, ram: .memory}] | sort_by(.ram) | reverse | .[0:3]' inventory.json
jq -e '.status == "ok"' health.json > /dev/null    # exit status reflects the result
```

The vocabulary to know: `.field`, `.[]` (iterate), `.[n]`, `.a.b.c`, `select(cond)`, `map(f)`, `.[] | f`, object construction `{a: .x, b: .y}`, array construction `[ ... ]`, string interpolation `"\(.name): \(.size)"`, the alternative operator `//` (default when null), the optional `?` that suppresses errors, `keys`, `has("k")`, `length`, `sort_by`, `group_by`, `unique_by`, `add`, `to_entries` and `from_entries`, `paths`, `limit`, `reduce`, `if ... then ... else ... end`, and formatters `@csv`, `@tsv`, `@sh` (shell-safe quoting), `@uri`, `@base64`. Options: `-r` prints raw strings without quotes, `-c` prints one compact line per result, `-e` sets the exit status from the last output (false and null give 1), `-n` runs with no input (`jq -n --arg x "$v" '{name: $x}'`), `-s` slurps all inputs into an array, `-R` reads raw text lines, `--arg name value` passes a string and `--argjson name json` passes a typed value, and `--slurpfile` and `--rawfile` load files. Passing values with `--arg` is the safe way to use shell variables inside a filter; pasting a shell variable into the filter text is the same injection mistake as in SQL.

Typical sysadmin uses are reading the machine-readable output of Linux tools, API responses, and building JSON for requests. `jq` writes numbers in a way that can lose precision for very large integers (older versions convert to double), so IDs that are large integers should be handled as strings. Version differences exist (1.5, 1.6, 1.7 and later add functions such as `ltrimstr`, `splits`, `abs` and others), so a script that needs a recent feature checks `jq --version`.

### yq

Mike Farah's `yq` (version 4 and later) reads YAML, JSON, XML, CSV, TOML and properties and applies expressions similar to jq's:

```bash
yq '.services.web.image' compose.yaml
yq -r '.spec.template.spec.containers[].name' deploy.yaml
yq '.version = "2.1"' -i config.yaml                  # edit in place
yq eval-all 'select(fileIndex == 0) * select(fileIndex == 1)' base.yaml override.yaml   # deep merge
yq -o=json '.' config.yaml                             # convert to JSON
yq '.items[] | select(.enabled == true) | .name' list.yaml
```

Python's `yq` instead takes jq programs directly and prints JSON by default (`yq -r '.a.b' file.yaml`, with `-y` to print YAML), which means that comments and formatting are lost in any rewrite, and multi-line strings and anchors come back transformed. Mike Farah's version preserves comments and layout in most edits, which makes it the better tool for editing files that humans also edit. YAML itself brings hazards: bare `no`, `yes`, `on` and `off` are booleans in YAML 1.1 parsers (the "Norway problem": the country code `NO` becomes false), unquoted numbers such as `1.10` become floats, indentation is meaning, and anchors and merge keys (`<<:`) are not universally supported. When correctness matters, validate against a schema, and quote ambiguous strings.

### Choosing and combining

A short decision rule: if the data has nesting or types (JSON, YAML, TOML), use `jq` or `yq`; if it is columns, delimited text or log lines, use `awk`; if a tool offers `-j`, `-J` or `--output json`, prefer that to scraping columns. Combine them through pipes and keep each stage simple. When a one-liner needs state across several steps or more than a screen of code, move to a script (awk file with `-f`, or Python). Always test on awkward input: empty lines, missing fields, quoted delimiters, large files and Unicode.

## Assessment: the good, the bad and the ugly

**The good.** Awk, jq and yq turn minutes of ad hoc scripting into a line, they stream (so they handle gigabyte files with small memory), and they compose with the rest of Unix. jq gives sysadmins a safe way to handle structured output without writing a program, and its `@sh`, `--arg` and exit-status features make it script-friendly. awk's pattern-action model is concise: reports, joins on a key, aggregation and counting need very little code. All three are scriptable, available in every distribution, and documented in manual pages and tutorials.

**The bad.** Terse syntax becomes unreadable fast: a five-line jq filter or an awk program with several nested conditions is a maintenance problem, and a comment next to it helps. Implementation differences bite: mawk, gawk and BSD awk differ on extensions, `jq` versions differ on functions, and the two `yq` programs differ on syntax. Awk's field model is wrong for quoted CSV and for data with embedded spaces, and its uninitialised-variable and string-versus-number rules cause silent mistakes. jq's type errors (for example `Cannot iterate over null`) are cryptic at first, and YAML parsing hides pitfalls.

**The ugly.** Parsing human-formatted output is fragile: column positions change with locale, terminal width and tool version; header lines move; units change from `K` to `Ki`. A script that scrapes `ps` or `df` works until the day it does not. Shell injection through unquoted variables placed in awk or jq programs is common (`awk "/$pattern/"` with untrusted `$pattern`; use `-v` and `--arg`). Large or deeply nested JSON can use a great deal of memory with `jq -s`, and a filter that works on one record can be wrong on a list. In-place YAML edits that silently drop comments or reorder keys have caused configuration incidents.

## Applications beyond this domain

The same patterns appear in log analytics (counting by key with awk is the ancestor of `GROUP BY`), in data engineering (jq-like path languages such as JSONPath, JMESPath, used by the AWS and Azure command-line tools, and Kubernetes' `-o jsonpath`), and in configuration management (Ansible's `json_query` filter and Jinja expressions). Kubernetes operators use `kubectl get -o json | jq` daily, and Helm charts and CI pipelines use `yq` to patch YAML. awk's model (records, fields, rules and associative arrays) influenced Perl and Python scripting habits and the design of stream processors. Security tooling uses jq to filter structured audit logs and SBOM files; compliance scanners emit JSON that jq turns into reports.

## Examples

**1. Top five memory users, robustly.**

```bash
ps -eo pid=,rss=,comm= --sort=-rss | awk 'NR <= 5 { printf "%s %.1f MiB %s\n", $1, $2/1024, $3 }'
```

Asking `ps` for specific columns without headers (`=`) removes the guesswork.

**2. Sum a column with a header, skipping blank lines.**

```bash
awk 'NR == 1 || NF == 0 { next } { total += $3 } END { printf "%d rows, total %.2f\n", NR - 1, total }' report.txt
```

**3. Find interfaces that are up and have an IPv4 address.**

```bash
ip -j addr | jq -r --arg s UP --arg f inet '.[] | select(.operstate == $s) | .ifname as $n | .addr_info[] | select(.family == $f) | [$n, .local, .prefixlen] | @tsv'
```

**4. Safely pass a shell variable into jq.**

```bash
unit=sshd.service
systemctl show "$unit" -p ActiveState --value
journalctl -o json -n 200 | jq -r --arg u "$unit" 'select(._SYSTEMD_UNIT == $u) | .MESSAGE'
```

**5. Update one key in a YAML file, keeping comments (Go yq).**

```bash
yq -i '.replicas = 3' deploy.yaml
git diff --stat deploy.yaml
```

The diff shows exactly one line changed, which is the check that the edit did not reformat the file.

**6. Convert a YAML inventory to a host list.**

```bash
yq -r '.hosts | keys | .[]' inventory.yaml | while IFS= read -r h; do printf '%s\n' "$h"; done
```

## Related problems and ideas

- **Machine-readable output first.** Tools increasingly offer `-J`, `-j` or `--output json`; prefer them to scraping.
- **Encoding and locale.** Set `LC_ALL=C` for byte-oriented, predictable sorting and matching in awk and `sort`; use UTF-8 aware tools when text is multilingual.
- **Streaming and memory.** `jq -c` with line-delimited JSON, and `--stream` for huge documents, avoid loading everything.
- **Schema validation.** JSON Schema and tools such as `check-jsonschema` verify the data you transform.
- **Other path languages.** JMESPath (`--query` in cloud CLIs), JSONPath, XPath for XML, and `xmlstarlet`.
- **Replacing with Python.** Once logic needs functions, error handling or tests, the next slice's scripts are the better home.

## Active research

Work on these tools is incremental. jq's maintainers have brought out releases that added features and fixes after a long pause; gawk's recent versions added CSV support and improved Unicode handling; and projects such as `miller`, `gron` and `jc` explore alternative models for structured shell pipelines. Structured shells (Nushell, PowerShell, Elvish) make typed tables the pipeline's basic unit and so reduce the need for text parsing, and there is research on type-checking pipelines and on query languages that unify JSON, YAML and tabular data. On the operations side, more Linux utilities are gaining JSON output, which removes the need to scrape their text.

## Future direction

Expect structured output to become the default interface between tools, and text scraping to shrink to legacy cases. awk will stay a durable tool for columns and logs, jq for JSON, and a YAML tool for configuration edits, with a clear convention in each team about which `yq` is installed. The course target is a student who can choose the right tool for a task, write a clear one-line filter with each, pass shell values in safely, and know when to stop and write a script.
